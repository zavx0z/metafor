# `@internal/*`

`@internal/*` (далее — internal-пакеты) — пространство сменяемых служебных
пакетов самого Hamiltonian. Каждый пакет предоставляет одну внутреннюю
возможность, которая может иметь платформенные части для нескольких сред.

В [распределённой оркестрации Hamiltonian](../README.md#распределение-ответственности)
эти пакеты обеспечивают знакомство, управление, наблюдение и другие служебные
возможности. Их точные версии входят в
[состав сменяемого выпуска](../release/README.md#что-называется-выпуском),
который готовит `@hamiltonian/release` (далее — `release`), поэтому начальная
часть остаётся минимальной.

## Внутренний пакет и его возможность

Имя каждого пакета выражает предоставляемую им возможность. Сам пакет объявляет
поддерживаемые среды своими точками входа: одна возможность может иметь
платформенные части для браузера, Service Worker, серверного процесса или
другой среды и при этом остаётся одним пакетом.

Все объявленные платформенные части принадлежат одной версии пакета. При
изменении одной платформенной части пакет получает новую версию, а выпуск
подготавливает все объявленные части этой версии.

Когда выпуску нужен внутренний пакет:

1. состав выпуска включает точную версию пакета;
1. `release` получает и проверяет все объявленные платформенные части этой
   версии;
1. оркестрация Hamiltonian выбирает размещение воплощений только среди сред,
   объявленных пакетом;
1. запущенные воплощения предоставляют внутреннюю возможность пакета.

Наблюдаемый результат — Hamiltonian получает одну служебную возможность во всех
назначенных местах исполнения. Все платформенные части принадлежат одной точной
версии пакета, а каждое запущенное воплощение сохраняет его назначение.

## Владельцы внутренних пакетов

Этот закон закрепляет общий смысл пространства internal-пакетов. Каждый
входящий в него пакет отдельно определяет предоставляемую возможность и
наблюдаемый результат.

Пакет `@internal/visual` (далее — Visual) предоставляет
[визуальное наблюдение Hamiltonian](visual/README.md#как-появляется-сцена):
воплощения Visual отображают фактически наблюдаемую работу.
Точные программные интерфейсы внутренних пакетов принадлежат их открытым типам
и документации исходного кода.
