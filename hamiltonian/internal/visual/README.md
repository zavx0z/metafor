# `@internal/visual`

`@internal/visual` (далее — Visual) — сменяемый внутренний пакет Hamiltonian.
Visual предоставляет возможность визуального наблюдения: превращает фактически
наблюдаемую работу сети и контуров в единую понятную сцену, чтобы пользователь
видел, какие воплощения существуют, где они работают, как связаны и что с ними
происходит.

Visual объявляет свои платформенные части по
[закону внутренних пакетов](../README.md#внутренний-пакет-и-его-возможность), а
его точная версия входит в
[состав сменяемого выпуска](../../release/README.md#что-называется-выпуском).
Сцена отображает [наблюдаемую работу сети Hamiltonian](../../README.md#как-устроена-сеть),
не подменяя её владельцев.

<a id="принятый-закон-причинной-проекции"></a>

## Как появляется сцена

Когда Hamiltonian получает новое описание работающего контура:

1. визуальное воплощение определяет, к какому контуру и действующему состоянию
   относится описание;
1. принимает только целое, внутренне согласованное и замкнутое по владению
   описание;
1. строит из него ноды и связи;
1. передаёт общей нодовой системе задачу расположить и показать их;
1. отражает состояния показанных сущностей.

Наблюдаемый результат — сцена совпадает с последней принятой картиной каждого
контура и содержит только фактически наблюдённую работу.

<a id="декларации-контуров"></a>

## Несколько контуров

Каждый независимо наблюдаемый контур предоставляет одно целое описание своей
текущей структуры. Новое действующее описание того же контура целиком заменяет
предыдущее, а остальные контуры сохраняются независимо.

Описание принимается, когда все показанные сущности принадлежат известному корню,
а связи указывают на существующие стороны. Устаревшее, неполное или внутренне
противоречивое описание не вытесняет последнюю пригодную картину.

Связь между разными контурами отображается как отдельное наблюдаемое отношение
с сохранением их внутренних границ. Завершение сущности убирает принадлежащие ей
дочерние сущности и связи из следующей принятой картины.

## Сообщения и изменения

Каждое фактически наблюдённое сообщение создаёт одно временное движение по
существующей связи и в наблюдённом направлении. Состояние жизненного цикла
воплощения показывается отдельно от типа связи.

Изменение структуры перестраивает расположение нод. Изменение состояния или
новое сообщение обновляет уже построенную сцену, сохраняя её расположение,
пока состав остаётся тем же.

<a id="визуальная-среда-main"></a>

## Браузер и сервер

В браузере визуальное воплощение создаёт интерактивное пространство, в котором
пользователь наблюдает сцену, перемещается по ней и выбирает наблюдаемые
сущности Hamiltonian.

Браузерная и серверная платформенные части принадлежат одной версии пакета
Visual и входят в один выпуск. Их запущенные воплощения включают доступные
наблюдения в общую картину.

## Соседние владельцы

Visual владеет правилами, по которым принятые наблюдения становятся сценой и
одно из полученных описаний показывается как действующее. Общие механизмы
нодовой системы принадлежат точным соседям:

* [общая модель нод и связей](../../../pkg/nodes/README.md) принадлежит пакету
  `nodes`;
* [раскладка сцены](../../../pkg/nodes/layout/requirements/COMMON.md)
  принадлежит `@nodes/layout`;
* [отображение нод, связей и области просмотра](../../../pkg/nodes/ui/REQUIREMENTS.md)
  принадлежит `@nodes/ui`.

Точные формы описаний, программные интерфейсы и правила проверки принадлежат
открытым типам и документации исходного кода.
