# Hamiltonian

Hamiltonian — распределённый оркестратор воплощений MetaFor. Он доставляет
проверенный код, выбирает место исполнения, запускает, знакомит, обновляет и
заново воплощает части Вселенной. Процессы Bun, Service Worker, Window и другие
платформенные исполнения выполняют части этого общего закона в своей среде.

Имя `Hamiltonian` является проектным термином для целого закона рождения и
изменения воплощений.

## Общий закон

Когда участник появляется, возвращается или должен сменить код:

1. Hamiltonian устанавливает идентичность участника, его среду и установленный
   выпуск;
1. Hamiltonian определяет допустимое размещение и требуемый проверенный выпуск;
1. механизм доставки передаёт код, `startup` проверяет выпуск, а действующий
   `release` запускает подходящее воплощение;
1. механизм управления знакомит готовые воплощения для непосредственной
   рабочей связи;
1. наблюдаемый результат фиксирует одно допущенное воплощение с точной
   идентичностью, версией кода и восстановленными обязательными связями.

Идентичность участника, воплощение исполнения, версия кода и сетевой адрес —
разные свойства. Право продолжать работу подтверждается совпадением
идентичности, требуемого выпуска и причинной связью с предыдущим состоянием.

Все управляемые среды следуют одной последовательности:

```text
тонкая точка входа → startup → release → internal / metafor
```

Точка входа передаёт управление устойчивому `startup`. Он находит, проверяет и
запускает `release`. Выпуск определяет согласованный состав сменяемой среды.
Браузер и сервер реализуют этот закон своими способами хранения, загрузки и
перезапуска.

Браузерный путь уже выполняет эту последовательность. Для сервера требуемый
результат имеет вид `server.ts → startup/server → release/server →
internal/metafor`: `server.ts` запускает устойчивый `startup`, а вся среда
после него получает новое воплощение как один согласованный выпуск. Текущее
состояние и переход описаны у
[`@hamiltonian/startup`](startup/README.md) и
[`@hamiltonian/release`](release/README.md).

## Сетевой закон

Байты кода передаются через `fetch` от разрешённого источника и проверяются до
исполнения. Управляющий WSS переносит идентичность, сигнальный обмен и команды.
После знакомства готовые воплощения переходят к непосредственной рабочей
связи; её канал и смысл задаёт договор загруженной функции из
[карты MetaFor](../docs/README.md#карта-документов).

В первой целевой реализации воплощение Bun публикует один фиксированный внешний
сетевой вход для HTTP(S)-доставки начального кода и WSS-управления. Доменные
воплощения открывают исходящие и временные равноправные каналы по своим
договорам.

Долговечная идентичность Hamiltonian, право выпуска, подписи, обнаружение и
размещение нескольких идентичностей образуют отдельный сетевой договор. Его
принимаемый результат должен назвать владельца решения и способ проверки,
который не зависит от конкретного сетевого входа или источника байтов.

## Распределение ответственности

| Владелец | Ответственность |
| --- | --- |
| Hamiltonian | Доставка, размещение, знакомство, запуск, обновление и повторное воплощение |
| [`@hamiltonian/startup`](startup/README.md) | Начальная загрузка, проверка артефакта выпуска, действующее исполнение и передача управления |
| [`@hamiltonian/release`](release/README.md) | Состав выпуска, правила кеша и обновления, управляющий RPC и жизненный цикл сменяемой части |
| [`@internal/*`](internal/README.md) | Сменяемые служебные функции Hamiltonian после запуска выпуска |
| `@metafor/*` | Загружаемые функции самой MetaFor |
| [Документы MetaFor](../docs/README.md#карта-документов) | Предметные договоры и критерии готовности загружаемых функций |

Hamiltonian использует принятый договор при размещении и проверке готовности;
предметный закон сохраняется у владельца загруженной функции.

## Терминологический словарь

В обычном тексте используется русское название. Написание в обратных кавычках
фиксирует точное имя поля, среды, пакета или протокольного понятия.
Имена пакетов и их роли закреплены таблицей ответственности выше.

| Термин | Название | Описание |
| --- | --- | --- |
| `participant` | участник | Логическая часть системы, которой Hamiltonian назначает код и место исполнения |
| `identity` | идентичность | Устойчивое имя участника, сохраняемое между перезапусками |
| `incarnation` | воплощение | Одно конкретное исполнение участника от рождения до завершения |
| `env` | среда | Место и способ исполнения: `main`, `worker`, `service`, `server` или `server-worker` |
| `package` | пакет | Версионируемая единица исходного кода с одним именем |
| `artifact` | артефакт | Проверенные байты одной версии пакета для одной среды |
| `release` | выпуск | Согласованный набор версий пакетов, заменяемый как одно целое |
| `startup` | начальная оболочка | Устойчивая часть, которая проверяет и запускает выпуск |
| `runtime` | исполнение | Работающий экземпляр загруженного кода |
| `current` | действующий | Принятый сейчас состав или воплощение |
| `candidate` | кандидат | Полностью подготовленный преемник до передачи ему управления |
| `predecessor` | предшественник | Действовавшее воплощение, которое заменяет кандидат |
| `handover` | передача управления | Переключение новых событий на кандидата и завершение предшественника |
| `placement` | размещение | Решение, в какой среде и на каком устройстве действует участник |
| `listener` | сетевой вход | Фиксированная внешняя точка приёма HTTP или WSS |
| `signaling` | сигнальный обмен | Обмен данными, необходимыми участникам для знакомства и установления связи |
| `control` | управление | Команды Hamiltonian, идентификация и согласование состояния |
| `transport` | канал связи | Конкретный путь передачи сообщений между готовыми участниками |
| `contract` | договор | Проверяемые входы, решения, результаты и границы владельца |
| `contour` | контур | Независимо наблюдаемая группа исполнений с общим корнем и владельцем |
| `declaration` | декларация | Цельное описание текущей структуры одного контура |
| `revision` | редакция | Монотонный номер изменения декларации |
| `frontier` | причинная граница | Последняя причинная точка, полностью учтённая в снимке |

## Стандартная среда Window чистой реализации

Жизненный цикл стандартной среды принадлежит
[`@internal/visual`](internal/visual/README.md). Разделение устойчивого `startup`
и сменяемого состава описывают [`@hamiltonian/startup`](startup/README.md) и
[`@hamiltonian/release`](release/README.md).

## Текущее состояние

Чистая браузерная реализация содержит устойчивые точки входа `startup`,
сменяемый `release` и отдельный `@internal/visual`. Браузерный выпуск
подготавливается, проверяется и заменяется как согласованный состав.

Серверная среда сейчас публикует и доставляет браузерные выпуски. Следующий
результат добавляет `startup/server` и новое воплощение всей рабочей среды после
него. Владельцы производственных доменов продолжают действовать в своих
контурах; подключение к чистой реализации Hamiltonian требует отдельной
приёмки по [канонической документации](../docs/README.md#карта-документов).
