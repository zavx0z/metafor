# `@internal/visual`

`@internal/visual` (далее — visual) — сменяемый internal-пакет, который
предоставляет готовую визуальную среду Cosmos.

Visual объявляет свои платформенные части по
[закону внутренних пакетов](../README.md#внутренний-пакет-и-его-возможность), а
его точная версия входит в
[полный состав release](../../release/README.md#что-называется-выпуском).

<a id="визуальная-среда-main"></a>

## Визуальная среда main

Когда release запускает browser-часть visual, visual получает предоставленный
Canvas и монтирует готовый DOM-конструктор своего приложения через browser API
`@zavx0z/immersive` (далее — Browser). App объявляет stylesheet link рядом со Space во Fragment. Приложение содержит единственные Space
и ViewPoint, пространственное дерево Atom выбранной Verse и навигацию в HUD.
Служебный адрес отдельно открывает наблюдаемую сеть в том же Document.

Browser монтирует приложение в один semantic Document, подготавливает общие
шрифты, стили и производное представление сцены. Готовность наступает после
первого представленного кадра. Ошибка запуска освобождает созданные ресурсы.
При unmount Browser освобождает приложение и свой lifecycle,
включая созданную Browser ссылку на theme.

Пространственные узлы и HUD принадлежат одному пространству. События проходят
общий выбор получателя с учётом перекрытия. Browser владеет вводом, изменением
размера Canvas и циклом кадров. Общий свет освещает стеклянные тела дерева.
Каждая сущность получает тонкую пространственную поверхность; общий корень
содержит области, а область содержит наблюдаемых участников. Группировка
показывает принадлежность. Наблюдаемые соединения образуют плавные пространственные
кривые между материализованными окончаниями. Контрольные точки сохраняют глубину
общего пространства при движении камеры. Связи используют полную числовую геометрию наблюдаемых участников. LOD
тяжёлого содержимого сохраняет эти связи; лёгкие пространственные подписи
обслуживаются отдельным ограниченным рабочим набором.

Источник наблюдения передаёт полный следующий read-only снимок. Visual сохраняет
пространственную композицию при обновлении значений и показывает подробности
только выбранной сущности. Состояние соединения берётся из сообщения источника;
цвет канала и текст подробностей не устанавливают причинный факт.

Предметное дерево показывает фактические Atom полученного Graph в порядке Matter.
Структурные контроллеры сохраняют вложенность через ближайший родительский Atom;
шаблоны дают подписи, а не дополнительные сущности. В позе, вписывающей выбранный
Display в viewport, его фон размывается. Полёт, масштаб или изменение размера
снимают размытие и открывают вид на офис внутри того же Atom. Это локальное
изменение представления сохраняет адрес и экземпляр беседы.
Размер поверхности следует фактической области просмотра клиента. После resize
вписанный Display получает новую позу fit; свободная камера сохраняет свою позу.
До первого жеста навигации появление участников вписывает полную композицию
в доступный обзор. Обновление значений сохраняет камеру. Ручная навигация
закрепляет выбранный обзор; действие «Вписать сеть» возвращает общий вид.
Оболочка использует общую тему UI, чёрный фон пространства и пристыкованное
управление камерой. Подписи материализуются
по видимому размеру их поверхности.

До первого снимка дерево содержит общий корень и две области: «Сервер» и
«Браузер». Они не обозначают обнаруженные исполнения или действующие соединения.
При завершении приложения visual освобождает подписки и производную модель.
Источник наблюдения владеет сбором данных и доставкой снимков; visual владеет
только представлением. Демонстрационная анимация по умолчанию остановлена.

## Совместная работа с клиентом

Человек и агент работают с одним представлением подключённого клиента.
Oracle направляет разрешённое действие выбранному подключению; Visual читает
и изменяет существующие элементы своего Document через их обычные публичные
операции. Перенос элемента между проекциями сохраняет его identity, а удаление
прекращает возможность действия по прежнему указателю. Управление не создаёт
отдельного дерева интерфейса или собственного браузерного протокола.

В режиме аннотации человек выбирает существующий semantic node. Visual связывает
его Inspector identity с фактическим spatial hit, явно указанным owning Atom и
доступной проекцией текущего кадра. Отсутствующая связь остаётся неизвестной;
удаление узла прекращает выбор. Отметки HUD показывают выбранный и активный узлы
того же Document. Подтверждённый выбор автоматически передаёт выбранному Agent
отдельное служебное наблюдение с неизменной identity. Chat сохраняет его в Mass и
предоставляет модели при следующем ходе. Повтор доставки не создаёт новое событие;
служебные данные не являются пользовательским prompt или разрешением действия.
Пользовательский draft сохраняется, а HUD показывает подтверждение либо ошибку.

## Граница ответственности

Visual владеет композицией и переключением обзора. Смысл наблюдаемых сущностей,
причинные переходы и canonical состояние принадлежат соответствующим
Quantum-доменам и загруженным metafor-пакетам.

Binary default font принадлежит `@zavx0z/immersive/engine` (далее — Engine).
Visual использует объявление общего шрифта в HTML composition root; release
включает выбранный asset в проверенную поставку и сохраняет его в runtime
offline cache. Установленное представление получает шрифт из своего выпуска.

Theme source и production controls принадлежат `@zavx0z/immersive/ui` (далее — UI).
Visual объявляет `theme.css` в своих exports ссылкой на публичный CSS UI. Сборка
публикует его в той же версии без локальной CSS-обёртки; Browser получает
его точный адрес и подключает один stylesheet. UI и Engine не становятся отдельными
участниками Cosmos release.

Точные side effects, public exports и ошибки запуска принадлежат внутрикодовой
TSDoc visual entrypoints.
