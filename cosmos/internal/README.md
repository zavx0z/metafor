# `@internal/*`

`@internal/*` — пространство сменяемых инфраструктурных packages Cosmos (далее
— internal-пакеты). Каждый package предоставляет одну внутреннюю возможность,
которая может иметь платформенные части для нескольких environments.

В [общей системе Cosmos](../README.md#распределение-ответственности)
internal-пакеты обеспечивают служебные возможности выпуска. Их точные версии
входят в [полный состав release](../release/README.md#что-называется-выпуском),
поэтому startup остаётся минимальной устойчивой частью.

## Внутренний пакет и его возможность

Имя package выражает предоставляемую возможность. Package сам объявляет
поддерживаемые environments своими платформенными частями: одна возможность
может воплощаться в browser, Service Worker, Bun process или другой
поддерживаемой среде и при этом остаётся одним package.

Все объявленные платформенные части принадлежат одной package version. При
изменении одной части package получает новую версию, а release подготавливает
полный набор частей этой версии.

Когда выпуску нужен internal-пакет:

1. состав release включает точную package version;
1. release получает и проверяет все объявленные платформенные части;
1. Cosmos выбирает допустимые environments только среди объявленных package;
1. запущенные воплощения предоставляют внутреннюю возможность.

Наблюдаемый результат — Cosmos получает одну инфраструктурную возможность во
всех назначенных environments, а все её воплощения принадлежат одной точной
package version.

## Владельцы внутренних пакетов

Этот документ закрепляет общий закон namespace. Каждый internal-пакет отдельно
определяет собственную возможность и наблюдаемый результат. Например,
`@internal/visual` (далее — visual) предоставляет
[готовую визуальную среду Cosmos](visual/README.md#визуальная-среда-main).

Internal-пакеты реализуют инфраструктуру выпуска. Загруженные metafor-пакеты и
Quantum-домены сохраняют предметный смысл и состояние у своих владельцев.
