# Участник сети

`@internal/peer` (далее — peer) объявляет предметное участие в сети
[инфраструктуры Cosmos](../README.md). Корневой экспорт и публичная декларация
представляют одну Meta. Её States и Process управляют запуском, принятыми
передачами и остановкой участника; физическую сеть и резервный путь создаёт
[серверная композиция release](../../release/README.md#знакомство-участников).

Декларация Meta предоставляет ordinary Fields запроса и подтверждения: `request`,
`requestId`, `ack`, `ackId`, `status` и `error`. Root назначает новый requestId и
сбрасывает ack; Process читает выданный requestId и возвращает его как ackId.
Подтверждение остаётся результатом канонического Process commit, а не ответом
сетевого transport. Политика запуска и остановки принадлежит состояниям Meta.

Конфигурация участника и credential находятся в объявленной directory Mass.
Запрос `prepare` наполняет её из явно переданного private native inbox, не
открывая сеть. Подготовка проверяет конфигурацию, устойчиво записывает пару
приватных файлов и освобождает lease до подтверждения. Точный повтор сохраняет
bytes; конфликт или неполный прежний результат отклоняется. Credentials и
физические пути не входят в Fields или канонический результат Process.

Относительный `tokenFile` читается от каталога приватной конфигурации, поэтому
перенос Mass сохраняет её bytes и не требует записи нового host path в Meta.
Запускающий Process удерживает её lease и создаёт одну композицию участника с
источником точного установленного выпуска. Живой объект сохраняется только в
Energy. Повторный согласованный запрос использует этот объект; несовпадающий
контекст требует явной остановки. Холодная Energy создаёт своё воплощение заново.

Останавливающий Process сначала запрещает новые обращения к источнику,
дожидается принятых передач, затем закрывает участника и освобождает lease.
Неудачное закрытие сохраняет ресурс для повторной попытки. Structural destroy
использует ту же явно объявленную очистку. Пассивный broker Cosmos сам не
запускает этого участника и не принимает его предметных решений.

Завершающий `destroy` привязан к `stopped`: он идемпотентно очищает Energy после
обычной остановки и служит объявленной очисткой при structural removal. В
`running` такой Process не объявляется, поскольку вход в это State должен
сохранять живого участника.

```sh
bun run --filter @internal/peer typecheck
bun run --filter @internal/peer test
```
