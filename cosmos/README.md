# Cosmos

Cosmos — внешний контур исполнения MetaFor. Он связывает программный выпуск с
физической средой: запускает серверное воплощение, восстанавливает опубликованный
выпуск, доставляет пакеты и предоставляет каналы, через которые загруженная
система продолжает работу.

Cosmos не определяет предметные законы MetaFor и не владеет причинным состоянием
Quantum-доменов. Его ответственность заканчивается на подготовке среды,
публикации выпуска, доставке кода и предоставлении внешних возможностей.

## Текущий контур запуска

```text
server.ts
   └── @cosmos/startup:server
         └── exact @cosmos/release:server process
               └── Bun.serve()
                     ├── статическая оболочка и assets
                     ├── доставка пакетов выпуска
                     ├── чтение и публикация /code
                     └── RPC-канал Service Worker через /sw
```

Корневой `server.ts` запускает только устойчивый startup. Startup читает
последнюю завершённую version release, проверяет exact server artifact и
запускает его отдельным Bun-процессом. Release process восстанавливает принятую
публикацию и создаёт единственный Bun-сервер для оболочки приложения, файлов
выпуска, операций публикации и WebSocket RPC. При падении startup показывает
ошибку без автоматического restart или rollback. Доменный runtime в этот server
startup пока не входит.

## Состав

```text
cosmos/
├── server.ts                 серверный composition root
├── build.ts                  сборка пакетов, входящих в выпуск
├── startup/                  минимальный устойчивый вход выпуска
├── release/                  публикация, доставка и восстановление выпуска
├── internal/                 сменяемые инфраструктурные пакеты
├── shared/                   общие контракты Cosmos
├── static/                   статическая оболочка
├── assets/                   доставляемые статические ресурсы
└── tests/                    архитектурные и интеграционные проверки
```

### `startup`

`startup` — минимальный код, способный начать работу, получить согласованный
выпуск и передать управление его составу. Он должен оставаться меньше и
стабильнее остальной системы.

### `release`

`release` владеет техническим жизненным циклом выпуска:

- построением включённых пакетов;
- формированием точного состава;
- публикацией и чтением текущего выпуска;
- доставкой пакетов браузеру и Service Worker;
- RPC, необходимым для обновления;
- восстановлением последней принятой публикации после перезапуска.

### `internal`

`internal` содержит инфраструктурную функциональность, которая входит в выпуск,
но не является предметным законом Quantum. Конкретный internal-пакет поставляет
реализацию возможности; загруженный доменный код получает эту возможность как
часть собранной среды.

## Сборка

`build.ts` читает зависимости пакета Cosmos и передаёт принадлежащие выпуску
пакеты механизму сборки `release`. Состав выпуска определяется manifest-ом, а не
жёстким списком исходных директорий внутри сервера.

Это сохраняет одну точку композиции:

```text
package.json
     │
     ▼
build.ts
     │
     ▼
release package builders
     │
     ▼
published release
```

## Граница с Quantum

Cosmos и Quantum разделены по ответственности, а не по способу вызова.

```text
Cosmos
  └── собирает и материализует среду исполнения
          │
          ▼
Quantum
  └── исполняет предметные домены и их причинные законы
```

Cosmos может включить реализацию общей возможности в выпуск. Для Quantum такая
возможность присутствует в среде исполнения как данность; домен не обязан знать,
каким устройством, процессом или сетевым механизмом она реализована.

Обратная зависимость запрещена: инфраструктурный код не должен становиться
владельцем состояния, переходов или семантики Quantum-доменов.

## Что не входит в Cosmos

В текущую архитектуру Cosmos не входят удалённые части автономного прототипа:

- отдельная peer-to-peer модель устройств;
- старый `server_proto` и связанный с ним `server-runtime`;
- prototype browser orchestration и lifecycle projection;
- prototype host, peer, soak и update runtimes;
- отдельный prototype visual-пакет.

История этих экспериментов остаётся доступной в Git. Новый код не должен
восстанавливать их неявно и не должен использовать их как архитектурное
основание.

## Правило развития

Новая общая функциональность сначала может быть выражена и проверена на уровне
Quantum. Когда её контракт становится универсальным и реализация должна
присутствовать во всех выпусках, она переносится в Cosmos как предоставляемая
возможность.

При таком переносе должны сохраняться три условия:

1. Quantum зависит от контракта возможности, а не от физической реализации.
2. Cosmos поставляет реализацию при сборке или запуске выпуска.
3. Владелец предметного состояния остаётся в Quantum.
