# Cosmos

Cosmos — внешний уровень MetaFor, который создаёт и поддерживает условия для
работы Вселенных. Он готовит и запускает согласованный выпуск, предоставляет
инфраструктурные возможности и связывает платформенные воплощения. Предметные
законы сохраняются у владельцев Quantum.

## Текущий контур запуска

На каждой платформе действует один общий жизненный цикл:

```text
тонкая точка входа → startup → release → internal / metafor
```

Платформа запускает `@cosmos/startup` (далее — startup). При
[устойчивом запуске выпуска](startup/README.md#как-начинается-работа) startup
получает проверенный кандидат, делает его действующим и завершает
предшественника без потери уже принятой работы.

Действующий `@cosmos/release` (далее — release) подключает
[подготовку полного выпуска](../tech/release/README.md) через технический API,
запускает входящие internal- и metafor-пакеты и восстанавливает принадлежащие
runtime связи. Сборка, версии, публикация и восстановление сохранённых
артефактов принадлежат `tech/build` и `tech/release`. После передачи управления startup остаётся только устойчивой
границей следующего запуска или замены.

Обычное обновление сохраняет фиксированный startup и выполняет
[полную замену release](release/README.md#ленивая-загрузка-и-handover).
Для internal-пакетов принят [будущий контракт бесшовной замены](internal/README.md#будущий-контракт-замены);
он не является действующей возможностью частичного обновления доменов.

Browser и Bun используют разные средства платформы, но дают один наблюдаемый
результат: в environment действует один полный проверенный выпуск.

При запуске Bun CLI экземпляр получает свой сетевой вход и директорию данных.
Несколько экземпляров могут пользоваться одной поставкой кода, сохраняя
независимые базы данных, Mass и выбор действующего выпуска. Корневая Meta
передаётся Quantum для первого наполнения мира; сохранённый мир восстанавливает
Quantum. Запуск предметных ресурсов внутри этого мира принадлежит его Meta.

При управляемой остановке CLI даёт действующему выпуску до 60 секунд на
объявленный Meta lifecycle и освобождение Quantum. Это ограниченный срок:
неподчиняющийся выпуск завершается startup с явным отказом. Остальные callers
сохраняют существующий срок startup, если явно не назначают свой.

## Среды выполнения packages

Environment задаёт место исполнения одной платформенной части package. Роль и
предоставляемая возможность принадлежат самому package. Точный
[закон сред выполнения](shared/package/environment.ts) различает browser и Bun
environments и закрепляет их внутрикодовой TSDoc.

Одна версия package охватывает все объявленные им платформенные части. Выбор
доступного environment определяет место воплощения и не меняет состав выпуска.

## Публичный граф artifacts

Одна версия package владеет одним публичным графом artifacts. Корневые
platform parts, отдельно загружаемые code units, styles, WebAssembly и другие
публичные файлы объявляются только в `package.json#exports` этого package.
Источник может принадлежать самому package или публичному экспорту его прямой
зависимости. Результаты совместной сборки и общие chunks выводятся из этого графа и
не образуют параллельный реестр выпуска.

Обычные зависимости package входят в его готовые artifacts и не обязаны
принимать Cosmos-specific contract. Поэтому UI, Engine и другие владельцы
остаются обычными packages: Cosmos не добавляет в них собственные declarations
или adapters ради доставки.

Полный жизненный цикл этого графа — совместная подготовка, ленивая загрузка и
сохранение artifacts предшественника до handover — принадлежит
[публичному графу artifacts выпуска](release/README.md#публичный-граф-artifacts).

## Распределение ответственности

| Владелец | Назначение |
| --- | --- |
| startup | Устойчивый запуск кандидата, handover событий и завершение предшественника |
| tech/build и tech/release | Подготовка артефактов, версии, совместимость, публикация и восстановление |
| release | HTTP/RPC, доставка и подключение опубликованного состава к runtime Cosmos |
| `@internal/*` (далее — internal-пакеты) | [Сменяемые инфраструктурные возможности Cosmos](internal/README.md#внутренний-пакет-и-его-возможность) |
| `@internal/visual` (далее — visual) | [Готовая визуальная среда Cosmos](internal/visual/README.md#визуальная-среда-main) |
| `@metafor/*` (далее — metafor-пакеты) | Загружаемая предметная функциональность MetaFor |

## Граница с Quantum

Cosmos владеет выпуском, размещением и инфраструктурой исполнения. Dark,
Boundary, Matrix, Energy и Bulk сохраняют собственные предметные состояния,
переходы и причинные законы.

Предметные инфраструктурные возможности предоставляют internal-пакеты.
Физические сетевые транспорты и связанная с ними native policy принадлежат
сменяемому release. Quantum зависит от публичных контрактов, а не от
физического устройства воплощающих их adapters.
