# Actions в Quantum Atom

## Введение

Actions (действия) — это операции, которые выполняются при входе в определённое состояние. Они являются центральной частью бизнес-логики, определяя поведение системы в зависимости от текущего состояния и глобального
контекста. Actions взаимодействуют с контекстом (`context`) и внутренними данными атома (`internal`), чтобы выполнять бизнес-операции и обеспечивать передачу данных между состояниями.

---

## Концепция действий

### Где задаются действия?

1. **Вход в состояние:**
    - Действие связано с состоянием, в которое атом входит.
    - Для запуска действия используется указание имени действия в ключе `action` для состояния `from`.

2. **Метод `actions`:**
    - Функции действий задаются внутри метода `actions()` при создании атома.
    - Каждое действие описывает логику выполнения и модификации глобального контекста.

---

## Принципы работы

### 1. Работа при входе в состояние

- Действие выполняется при входе в состояние, указанное в `from`.
- Это позволяет изолировать бизнес-логику от триггеров и контекста.

### 2. Работа с `context`

- `context` — это глобальное пространство данных, доступное для всех действий.
- Действие может изменять контекст через метод `update`, передавая обновления в систему.

### 3. Использование `internal`

- `internal` — это внутренние данные атома, которые используются исключительно действиями.
- Примеры:
    - API-сервисы.
    - Вспомогательные утилиты.
    - Данные, передаваемые из одного действия в другое.

### 4. Асинхронность

- Actions поддерживают асинхронные операции.
- Пока действие выполняется, триггеры блокируются, чтобы исключить конкуренцию состояний.

### 5. Обработка ошибок

- Обработка ошибок встроена в логику действий.
- При сбое результат ошибки записывается в контекст через `update`. Это позволяет системе учитывать ошибочное выполнение и инициировать переход в другое состояние.

---

## Особенности реализации

### Ключевые аспекты:

1. **Выполнение при входе в состояние:**
    - Actions привязаны к состояниям, и их выполнение начинается при входе в указанное состояние.

2. **Контекст и внутренние данные:**
    - `context` остаётся глобальным для всех атомов и состояний.
    - `internal` принадлежит атомам и используется только для выполнения действий.

3. **Асинхронные операции:**
    - Actions могут быть асинхронными, при этом система остаётся последовательной благодаря блокировке триггеров.

4. **Обновление контекста:**
    - Даже при ошибках действия контекст обновляется с результатами выполнения или информации об ошибке.

---

## Рекомендации

1. **Единичность действий:**
    - В рамках одного состояния выполняется только одно действие. Это упрощает архитектуру и исключает пересечения логики.

2. **Использование `internal`:**
    - Используйте `internal` для передачи данных между действиями или взаимодействия с внешними сервисами, чтобы минимизировать зависимость от глобального контекста.

3. **Обработка ошибок:**
    - Обновляйте контекст как при успешном, так и при ошибочном выполнении, чтобы обеспечить предсказуемость системы.

---

## Итог

Actions в Quantum Atom выполняются при входе в состояния и обеспечивают гибкость управления бизнес-логикой. Разделение глобального контекста (`context`) и внутренних данных атома (`internal`) делает систему прозрачной и
масштабируемой. При этом система остаётся предсказуемой благодаря последовательной обработке и обновлению контекста.
