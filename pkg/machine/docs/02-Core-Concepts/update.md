# Обновление контекста

1. Гарантировать последовательность изменений

   Изменения обрабатываются строго в порядке поступления за счёт синхронного выполнения функции update.
   • Вся логика обновлений контекста происходит линейно, поэтому коллизии и параллельные конфликты исключены.
   • Это упрощает работу системы и делает её поведение предсказуемым.

2. Защищать контекст от параллельных обновлений

   За счёт синхронного выполнения JavaScript (event loop) параллельные обновления невозможны.
    - Единственный поток выполнения гарантирует, что изменения будут происходить строго последовательно.
    - Нет необходимости в сложных механизмах блокировок или управления конкурентным доступом.

3. Обрабатывать ошибки

   Если данные из update не могут быть применены к контексту (например, не соответствуют ожидаемой структуре), они просто игнорируются.
    - Такой подход защищает систему от сбоев при неправильных данных.
    - Ошибка не прерывает выполнение программы и позволяет системе работать стабильно.

4. Журналировать изменения

   Запись изменений в виде патчей позволяет:
   • Хранить историю изменений для отладки.
   • Реализовать функцию “перемещения во времени”, чтобы откатить контекст на предыдущие состояния.
   • Патчи могут включать только изменённые поля, что минимизирует объём данных для хранения.

### Преимущества подхода

1. Простота и предсказуемость: за счёт синхронности и последовательности.
2. Стабильность: данные не применяются, если они некорректны.
3. Отладка и анализ: история изменений позволяет легко восстановить контекст или проанализировать его состояние.
4. Масштабируемость: реализация патчей минимизирует объём данных и сохраняет производительность.
