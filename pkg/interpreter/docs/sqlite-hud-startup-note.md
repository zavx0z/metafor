# Пометка для агента: SQLite HUD застревает на старой базе

## Текущее состояние

При запуске интерпретатора с SQLite-базой через аргументы CLI HUD может показывать пустое состояние:

- `ready: false`;
- `loading: true`;
- `tables: []`;
- `selectedTable: null`.

При этом сама база на диске не пустая. Прямая проверка через `/sqlite?path=...` возвращает таблицы и строки. Ручной вызов `/sqlite/open` для того же файла сразу оживляет HUD.

## Причина

Проблема не в доменном сервере и не в удалении файла базы.

В `pkg/interpreter/web/main.ts` при обработке сообщения `hello` стартовые SQLite-базы открываются с параметром `notBefore`, который вычисляется по времени запуска модулей:

```ts
const notBefore = earliestModuleTargetStartedAt(msg.modules ?? [])
```

Дальше `pkg/interpreter/src/sqlite-db.ts` проверяет `mtime` файла базы:

```ts
if (stat.mtimeMs < notBefore) throw new Error(`sqlite database not ready: ${path}`)
```

Это было полезно, когда база каждый раз удалялась и создавалась заново: HUD ждал именно файл текущего запуска. Сейчас база `boundary.sqlite` может сохраняться между перезапусками. Если файл уже существовал до старта интерпретатора, его `mtime` старше `notBefore`, поэтому HUD считает базу "не готовой" и бесконечно остается в ожидании.

## Как воспроизвести

1. Оставить существующую заполненную SQLite-базу на диске.
2. Запустить интерпретатор с этой базой в списке SQLite-аргументов.
3. Открыть `/hud/sqlite`: HUD будет в `loading`.
4. Проверить `/sqlite?path=<path>`: данные есть.
5. Вызвать `/sqlite/open` без `notBefore`: HUD сразу начинает показывать таблицы.

## Что нужно исправить

Нужно пересмотреть применение `notBefore` для стартовых SQLite-баз.

Рабочий вариант: не передавать `notBefore` из `hello` для баз, которые интерпретатор получает как стартовые SQLite-аргументы. Тогда HUD будет открывать уже существующую базу сразу, а если файла еще нет, текущий механизм ожидания все равно продолжит ждать появления файла.

Если сценарий ожидания именно новой базы еще нужен, его лучше сделать явным отдельным режимом, а не применять ко всем стартовым SQLite-базам автоматически.
