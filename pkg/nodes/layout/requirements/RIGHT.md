# Алгоритмические требования RIGHT

Этот документ дополняет [общие алгоритмические требования](COMMON.md) для
горизонтальной раскладки.

1. `RIGHT` выбирается только когда фактический viewport landscape или square:
   `width >= height`.
2. Основной причинный flow идёт слева направо. Layers располагаются по X, а
   ordering и compaction по Y уменьшают crossings, bends и пустоты.
3. Политика стремится сохранить socket alignment связанных карточек. Ноды не
   центрируются механически, если сдвиг вверх или вниз даёт более прямой и
   компактный допустимый маршрут.
4. Несвязанные компоненты и независимые branches заполняют доступную высоту и
   могут переходить в следующий столбец вместо создания одного чрезмерно
   широкого graph.
5. Различная ширина карточек не заставляет все карточки становиться широкими.
   Положение следующего слоя учитывает фактическую наиболее широкую ноду и
   необходимый corridor, не добавляя второй пустой интервал.
6. Для landscape сохраняется socket-aligned placement, после чего применяется
   общий лексикографический порядок routing-целей.
7. Все общие port, gateway, containment и clearance laws сохраняются без
   специальных исключений для горизонтального режима.
8. Для нескольких вертикально расположенных targets одного exact source-port
   router предпочитает общий вертикальный trunk и прямые горизонтальные terminal
   stubs. Отдельная U-петля вокруг уже существующего совместимого trunk является
   дефектом, если bundle проходит полный validator. Рёбра из разных портов одной
   source-node не сливаются и сохраняют полный обязательный шаг.
