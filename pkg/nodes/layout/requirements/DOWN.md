# Алгоритмические требования DOWN

Этот документ дополняет [общие алгоритмические требования](COMMON.md) для
вертикальной раскладки.

1. `DOWN` выбирается только когда фактический viewport portrait:
   `height > width`.
2. Компоненты и строки размещаются сверху вниз, а внутри доступной строки —
   слева направо. Когда ширины недостаточно, ноды переносятся ниже, а не
   продолжают расширять graph за пределы телефона.
3. Portrait policy сначала минимизирует пустые области display и compound.
   Одна широкая нода не делает обязательными широкими остальные; размеры строк
   выводятся из фактических карточек и доступной ширины.
4. Карточки одного fan-out ряда выравниваются по верхнему краю. Различные
   offsets target sockets не поднимают отдельную карточку и не увеличивают
   высоту всего ряда; bends получают только фактически занятый межрядный
   corridor.
5. Вертикальный flow не меняет стороны parameter ports: source остаётся
   `EAST`, target — `WEST`, а все compound transitions проходят через
   `WEST`/`EAST`, никогда через верх или низ.
6. Внутри каждого уровня hierarchy применяется та же `DOWN` policy, а не только
   к root. Compound не оставляет широкую или высокую пустую область ради
   сохранения landscape-позиции children.
7. Для portrait сначала исключаются заведомо пустые варианты placement; среди
   одинаково плотных допустимых вариантов действует общий лексикографический
   порядок routing-целей.
8. Все общие hard laws и единый socket-pitch rhythm действуют без ослабления для
   узкого viewport.
9. Связанные edges могут использовать общий generated trunk и в portrait.
   Направление responsive placement не отменяет exact EAST/WEST terminal stubs,
   устойчивый порядок junctions и запрет overlap для несвязанных edges.
