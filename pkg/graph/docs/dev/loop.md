# Оптимизация циклов в иерархических графах

## Анализ производительности множественных проходов

При работе с иерархическими структурами данных (например, в `quantum/graph/layout/hierarchy.js`) часто возникает вопрос об оптимизации множественных проходов по данным.

### Текущая реализация
Типичный паттерн включает несколько проходов:

```javascript
// 1. Инициализация структур данных O(n)
states.forEach(state => nodes.set(state, {ports: []}))

// 2. Основная обработка данных O(c * t) 
collapses.forEach(collapse => {
  collapse.to.forEach(target => {
    Object.keys(target.trigger).forEach(trigger => {
      // Обработка портов и ребер
    })
  })
})

// 3. Финальное преобразование O(n)
nodes.forEach((node, state) => {
  // Форматирование выходных данных
})
```

### Преимущества разделения на циклы

1. **Возможности параллельного выполнения**:
   - Независимые циклы можно выполнять параллельно
   - Каждый проход может быть распределен на отдельные потоки/воркеры
   - Упрощается масштабирование на многоядерных системах

2. **Масштабируемость**:
   - Легче распределить нагрузку между несколькими процессорами
   - Проще реализовать batch-обработку для больших наборов данных
   - Возможность применения map-reduce паттернов

3. **Управление ресурсами**:
   - Лучший контроль над памятью для каждого этапа
   - Возможность освобождения ресурсов между проходами
   - Более предсказуемое потребление CPU

4. **Отказоустойчивость**:
   - Проще реализовать checkpoint'ы между проходами
   - Легче обрабатывать ошибки на каждом этапе
   - Возможность перезапуска с определенного этапа

### Когда объединение циклов НЕ даст существенного профита

1. При работе с "легкими" операциями внутри циклов
2. Когда циклы выполняют логически различные задачи
3. Когда промежуточные структуры данных все равно необходимо хранить
4. Когда читаемость кода важнее микрооптимизаций

### Когда стоит рассмотреть объединение циклов

1. При наличии дорогостоящих операций инициализации на каждой итерации
2. При работе с большими наборами данных, где важна локальность кэша
3. При наличии повторяющихся вычислений между циклами
4. Когда промежуточные структуры данных можно исключить

### Сложность алгоритмов

- Инициализация: O(n), где n - количество состояний
- Основная обработка: O(c * t), где:
  - c - количество collapses
  - t - среднее количество триггеров
- Финальное преобразование: O(n)

### Пример параллельной обработки

```javascript
// Параллельная инициализация
Promise.all(states.map(async state => {
    return nodes.set(state, await initializeNode(state));
}));

// Параллельная обработка collapses
await Promise.all(collapses.map(async collapse => {
    // Обработка каждого collapse независимо
    return processCollapse(collapse);
}));

// Параллельное финальное преобразование
const results = await Promise.all(Array.from(nodes).map(async ([state, node]) => {
    return transformNode(node);
}));
```

## Рекомендации

1. Начинайте с читаемой реализации с разделением логики
2. Проводите профилирование перед оптимизацией
3. Объединяйте циклы только при доказанном профите производительности
4. Документируйте причины оптимизации в комментариях к коду
