# MF-205 — Опубликовать и восстановить source принятого patch

## Зачем

Сбой после live commit не должен провоцировать второй runtime patch или
оставлять неизвестной публикацию `meta.ts`.

## Границы

* Единственная durable причина операции — authoring cause той же Force history
  entry; второй operation journal запрещён.
* Повтор находит acceptance по `(rpcSource, operationId)` и тому же request
  digest.
* Source projector восстанавливает deterministic candidate/rollback artifacts,
  проверяет before/after revisions и публикует один или два `meta.ts`.
* Уже опубликованный source распознаётся как завершённый; чужая revision
  отклоняется без перезаписи.
* Повтор source projection не перечитывает живой мир и не выполняет новую
  runtime mutation.
* Ошибка публикации возвращает наблюдаемую phase `source_pending`, успех —
  `complete`.

## Критерии готовности

Изолированные тесты доказывают normal publish, повтор после success, повтор
после сбоя до первой замены и восстановление частично опубликованного move без
второго Force history entry.
