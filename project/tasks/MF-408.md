# MF-408 — Завершить декларационные entity Meta

## Зачем

После доказательства Field один агент должен уметь редактировать остальные
канонические декларации без новых специальных RPC.

## Действующая основа

Field уже доказывает общий `meta.declaration.apply` и его live-first/source
projection path.

## Границы

* Добавить в закрытый union entity для template metadata, State вместе с
  transitions и conditions, Mass declaration, Reaction и Bulk declaration.
* Использовать semantic key или name и точную source revision, не SQLite ID и
  не filesystem path.
* Поддержать `add`, `replace`, `remove` и значимый `move` одной entity.
* Enum variants остаются внутри Field; Transition и Condition — внутри State.
* Process реализуется отдельно в `MF-404`, но через тот же метод и provider.
* Новая access policy, capability scope и конкурентные writes не входят.

## Критерии готовности

Один доверенный агент через `meta.declaration.apply` меняет каждую
не-Process декларационную секцию, а один accepted patch наблюдаем в source,
Boundary и нужных runtime projections.

## Результат

* Закрытый RPC union включает metadata, optional Field, State composition,
  Mass, Reaction и Bulk с semantic key или name и точной source revision.
* State переносит Transition и Condition одним Inflaton; Boundary сохраняет их
  в одной транзакции и передаёт причинно упорядоченные дочерние проекции.
* Mass живёт отдельной declaration entity, Reaction использует authored key, а
  Bulk остаётся singleton декларацией Meta.
* Реальный RPC add/remove terminal State на `zavx0z/lada` принят Force как
  `visual-cloud-20260731:683` и `visual-cloud-20260731:690`, наблюдался в
  Boundary, `readGraph` и Bulk, после чего source побайтово вернулся к исходной
  revision `sha256:718536ff8de36cc82030c593a9b8800b52067e3039158216733cb67ea3b5fff5`.
* WebGPU capture `cap-2` зафиксировал 4695 draw calls и 0 validation errors;
  GPU timestamp на текущем адаптере недоступен, поэтому performance timing не
  является доказательством задачи.
* Process остаётся отдельной задачей `MF-404`; Matter tree, Field input и
  Process execution projection остаются в следующих P0-задачах.
