# MF-409 — Один Dark server на Вселенную

## Зачем

Один Mac или AI-server должен одновременно запускать несколько независимых
Вселенных без набора фиксированных доменных портов. Сетевой ingress одной
Вселенной принадлежит Dark; доменные проекции не становятся HTTP services.

## Связь с дорожной картой

Задача упрощает локальное рождение и эксплуатацию нескольких contour до
будущего mesh transport. Она не реализует WebRTC, discovery, STUN/TURN,
Force v2 или публичную доверительную границу.

## Подтверждённые факты

* Текущий runtime выделяет порты `4000`—`4005`.
* Force уже открывается доменами исходящим WebSocket к Dark.
* Monad использует REST registration/RPC и callback HTTP server каждого домена.
* Bulk дополнительно обслуживает browser shell, initial и WebSocket на своём
  listener.
* `MonadChannel`, `MonadRpcPeer`, `MonadRouter` и Force envelopes не зависят от
  REST.

## Решение владельца

* Одна Вселенная имеет один слушающий server в Dark.
* Supervisor только запускает и останавливает процессы.
* Boundary, Matrix, Energy и Bulk не открывают listeners.
* Каждый домен сам открывает к Dark отдельные постоянные Monad и Force
  WebSocket.
* REST Monad сохраняется на Dark для локальных клиентов и агентов.
* Browser ingress Bulk переносится в Dark как gateway; Bulk сохраняет Store,
  observer, capture и Visual semantics.
* Будущие два WebRTC DataChannel должны заменить физические WebSocket без смены
  Monad/Force payload.

## Границы

* Не менять Particle routing, Force history, checkpoint replay или fail-stop.
* Не добавлять WebRTC, signaling, STUN, TURN или mesh discovery.
* Не добавлять process orchestration в supervisor.
* Не менять SQLite schema и Mass persistence.
* Не делать текущий ingress безопасным публичным API без отдельного `AUD-007`.

## Критерии готовности

* В полном contour слушает ровно один TCP port, принадлежащий Dark.
* Boundary, Matrix, Energy и Bulk рождаются без `Bun.serve`.
* Domain Monad является постоянным duplex WebSocket и сохраняет source binding,
  method routing, correlated responses и закрытие provider.
* Существующий Force wire и lifecycle проходят без semantic changes.
* `GET /`, `/initial`, browser updates, browser Particle input и
  `bulk.observer.captureViewport` работают через Dark.
* Dark `/health` агрегирует состояние доменов; Matrix по Monad ждёт готовность
  остальных Force channels.
* Два contour с разными Dark ports могут одновременно родиться на одной машине.
* Локальные targeted tests, `bun run check` и полный cold contour проходят.
* Рабочая Лада на AI-server после отдельного cold restart работает из
  обновлённого `metafor-inference` и слушает только Dark port.

## Проверка результата

* Transport unit/integration tests.
* Runtime one-port и parallel-contour tests.
* HTTP initial + browser WebSocket + capture scenario.
* Проверка listeners и Dark health локально и на AI-server.

## Доказательства реализации

* `bun run check`: `2221 pass`, `0 fail`.
* Два полных холодных contour одновременно родились на `127.0.0.1:45400` и
  `127.0.0.1:45500`; у каждого найден ровно один TCP listener его Dark.
* Через Dark проверены `GET /health`, `GET /`, `GET /initial`, внешний Inflaton,
  его материализация Boundary и последующий browser Store update по WebSocket.
* Duplex Monad WebSocket проверен в обоих направлениях, включая вложенный и
  параллельный RPC без блокировки коррелированных ответов.
* Проверка и cold restart рабочей Лады на AI-server выполняются после
  публикации implementation-коммита.
