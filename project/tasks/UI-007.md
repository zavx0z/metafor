# UI-007 — Создать масштабируемый каталог WebGPU UI

## Коротко

Разработчик открывает одну desktop-среду на собственном WebGPU UI, быстро
находит нужный Element, Component, Node UI либо Widget, выбирает сценарий и
вариант, проверяет настоящий production preview и копирует точный TypeScript.
Система должна оставаться удобной при сотнях компонентов и тысячах stories.

## Зачем

Текущий historical shell подходит по составу, но оставляет большую пустую рамку,
хранит routes и тексты вручную и показывает справа статический contract вместо
рабочего кода. При росте до полной псевдо-HTML библиотеки, сложных editors,
widgets и Node UI плоские списки и eager bundle перестанут масштабироваться.

* UI-001 восстановила Components playground и оставила незавершённой русскую
  локализацию.
* UI-002 создала public `@ui/playground`; UI-004 перевела shared shell и
  Components на retained parents; UI-005 закрепила pathname routes; UI-006

* Архивные owner-решения уже закрепили две панели слева, preview в центре,
  variants снизу, правую последнюю панель и отсутствие бесполезных
  описательных блоков.
  Текущее решение уточняет правую панель как постоянный source+copy и сохраняет
  существующую оболочку/Engine.
* Отдельный `/Users/zavx0z/repozitarium/blender-node-catalog` содержит Blender
  4.5.5 reference inventory. Он используется только при выборе собственных
  контрактов MetaFor; dataset, изображения и Blender examples не импортируются.
* Параллельная задача
  `codex://threads/01a01b5f-ee7b-7092-9846-878dc84b1799` владеет production
  subpath exports, dynamic imports и shared chunks без дублирования Engine.

## Подтверждённые факты

* `planPlaygroundShell(1920, 1080)` ограничивает stage до `1660×860`, оставляя
  вокруг панелей поля `130×110`.
* Current Components registry вручную перечисляет 27 route IDs и не является
  пригодным индексом для сотен компонентов.
* Direct navigation на `/button/basic/contained` в baseline `3936fd930` падает
  до native resize: runtime materialize-ит desktop shell на внутренних
  `800×600`, preview получает слишком малую ширину, retained Button hit —
  отрицательный rect. DOM фиксирует
  `A retained hit requires a finite non-negative local rect`, canvas остаётся
  `300×150`.
* `@ui/playground` уже владеет typed pathname router, FlexBox geometry,
  retained Navigation/Dock/Info, keyboard navigation и no-HMR server; новый
  движок или DOM/iframe shell не нужен.

## Решения владельца

1. Engine, UiRuntime, WebGPU renderer и существующий five-panel shell
   сохраняются. Storybook, Histoire, DOM, iframe или второй runtime не
   добавляются.
2. Workbench является desktop-only. Stage занимает весь canvas с небольшим
   внешним отступом; catalog, sections и source/controls panels допускают
   desktop resize/collapse, а preview получает остаток.
3. Первая левая панель содержит иерархический большой catalog, поиск,
   сворачиваемые группы и виртуализированный список. Вторая показывает sections
   выбранного component.
4. Preview отображает настоящий production UI. Dock снизу содержит variants
   выбранной story и масштабируется горизонтальной виртуализацией.
5. Правая панель постоянно показывает сгенерированный TypeScript и кнопку
   `Копировать`. Ниже располагаются grouped controls и события; они не скрывают
   код.
6. Один typed story descriptor является источником component identity,
   section, variant, args, render, source, controls, tags и optional play.
   Routes, index, preview, source и render test не дублируют эти сведения.
7. Initial bundle содержит только metadata/search index. Story implementation
   загружается lazy factory после выбора. Production import names и split law
   предоставляет отдельный owner delivery-задачи.
8. Видимые navigation, controls и docs пишутся по-русски. API identifiers,
   import specifiers, routes и TypeScript остаются точными.
9. `4192/overview` становится owner-visible эталоном и документацией Workbench.
   Package playgrounds публикуют только собственные stories; shared package не
   получает consumer vocabulary или production dependency.
10. Blender catalog остаётся reference. В Workbench нет Blender-нод, assets и
    examples; показываются только реализованные сущности MetaFor.

## Подзадачи

### UI-007.1 — Стабилизировать direct Components detail bootstrap

Статус и исполнитель: `COMPLETE`, руководитель текущей задачи.

До первой materialization runtime должен получить native desktop metrics.
Прямое открытие `button/basic/contained` и representative detail routes не
создаёт отрицательные hit rect, достигает ready marker и сохраняет один target.

Результат: `UiRuntime.handleResize()` получает native canvas metrics до
регистрации первой Surface. Focused Components/shared tests прошли `9/9`,
playground typecheck и diff-check зелёные. После exact restart/reload direct
route достиг `ready` с canvas `3840×2176`, console `0`; desktop capture
non-black показывает Contained detail, native `1920×1088 @2` восстановлен.

Result checkpoint: `0569634a5c84ce1c3301c2465b279bdcedb475cf`.

### UI-007.2 — Ввести typed story registry и metadata index

Статус и исполнитель: `COMPLETE`, руководитель текущей задачи.

Public contract связывает identity/section/variant/args/render/source/controls,
строит deterministic pathname routes и отделяет metadata index от lazy story
factory. Он не фиксирует production package specifiers и не импортирует
consumer implementations в shared package.

Результат: public `definePlaygroundStories` принимает package-owned hierarchy
`group → component → section → variant`, строит immutable pathname declaration
и плоский metadata/search index. Loader не вызывается при построении catalog,
кеширует exact Promise после выбора и разрешает retry после ошибки. Typed story
module связывает default args, controls, production render, source и optional
play без production specifiers в shared package. Focused registry/router/
boundary tests прошли `10/10`, package typecheck и diff-check зелёные.

Result checkpoint: `b4513d3b73e2829899e03dbb2e8fafeb8abdcd71`.

### UI-007.3 — Заполнить desktop и масштабировать navigation

Статус и исполнитель: `COMPLETE`, руководитель текущей задачи.

Удалить stage max caps, сохранить five-panel FlexBox composition, добавить
desktop panel sizing/collapse, поиск, groups и bounded virtual lists. Mobile
режим не входит в контракт.

Результат: stage max caps и compact branch удалены; desktop использует весь
canvas с `16px` padding, сохраняет five-panel FlexBox и принимает configurable
widths/collapsed panels. Navigation items получили generic group/search metadata
и bounded `{offset, limit}` view; fixture из `1000` items materialize-ит только
выбранные `10` и один group owner. Focused shared/Components/Elements/Node tests
прошли `24/24`, четыре playground typechecks и diff-check зелёные. После exact
restart Components и `4192` дали console `0`, non-black full-viewport desktop
captures; native `1920×1088 @2` восстановлен, target IDs сохранены.

Result checkpoint: `a8750442bc6168ae9faec94ef38c4639fd00d093`.

### UI-007.4 — Добавить source/copy, controls и variants

Статус и исполнитель: `COMPLETE`, руководитель текущей задачи.

Source generator использует exact current args; code всегда виден, copy
возвращает import и рабочий TypeScript. Controls группируются и обновляют тот же
preview/source state; dock показывает variants.

Результат: public retained `PlaygroundStoryPanelSurface` постоянно показывает
TypeScript и copy action, а ниже переключает controls/events. Boolean и select
controls вычисляют следующее значение и передают exact key/value consumer;
source не скрывается. Story registry выдаёт variants текущего component/section.
Focused story/surface/boundary tests прошли `15/15`; тест pointer-путём копирует
полный source, меняет `contained → outlined` и переключает Events. Package
typecheck и diff-check зелёные.

Result checkpoint: `1b21c1172f087460317dca8edc70ee30eb319193`.

### UI-007.5 — Материализовать эталон на 4192

Статус и исполнитель: `IN_PROGRESS`, руководитель текущей задачи.

`@ui/playground` fixture показывает на русском overview устройства Workbench и

## Границы

* Не менять production package exports/entrypoints, code-splitting law либо
  UiRuntime ownership — это отдельная согласованная задача.
* Не вводить DOM layout, iframe preview, React/Vue/Svelte/Vite/Storybook runtime
  или новый UI engine.
* Не переносить Blender dataset/assets/examples в MetaFor.
* Не переписывать одновременно все Components/Elements/Nodes: сначала один
  shared contract и одна representative story.
* Не трогать user-owned `hamiltonian/README.md`.
* Lifecycle/browser evidence выполнять только `$ui-dev`, сохраняя существующие
  listeners и targets.

## Критерии готовности

1. Desktop stage использует доступный canvas без большой внешней рамки.
2. Catalog остаётся отзывчивым на representative большой metadata fixture и не
   загружает implementations до выбора.
3. Preview, variants, controls и source получают состояние из одной story.
4. Кнопка копирования возвращает точный import и TypeScript текущего варианта.
5. Shared fixture `4192/overview` наглядно документирует принятый Workbench.
6. Package boundary не содержит Blender/Node/Field/product vocabulary и не
   получает production runtime dependency.
7. Focused tests/typechecks, DOM/console и exact desktop canvas проходят; один
   target на origin сохраняется.
