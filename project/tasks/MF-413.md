# MF-413 — Единая RPC-поверхность Oracle

## Зачем

Привести имя внутреннего RPC-слоя Dark в соответствие с решением
владельца: в действующем MetaFor этот слой называется Oracle.

## Решение владельца

Oracle — единая request/response поверхность Dark. Через неё клиент:

* задаёт вопросы о текущем мире и его evidence;
* передаёт намерения, способные начать причинное изменение;
* вызывает служебные coordination operations доменов.

Ответ Oracle означает response, rejection, admission или outcome конкретной
operation. Он не становится каноническим фактом только из-за формы RPC.
Изменение живого мира выражается Particle, принимается и маршрутизируется
Force, а Boundary фиксирует его каноническое следствие.

## Подтверждённые факты

* Действующая RPC-поверхность содержит read-only, authoring и control methods.
* `readGraph`, Force history и Process result возвращают разные виды evidence.
* Изменение Field или декларации проходит admission, Force и Boundary;
  простой RPC response не заменяет их.
* Служебные lifecycle, checkpoint, cache, lease и fencing operations могут
  менять operational state, не создавая факт живой Вселенной.

## Границы

* Переименование не меняет RPC payload semantics, routing или Force wire.
* Compatibility aliases и двойная терминология не создаются.
* Oracle не объявляется владельцем Graph, Force history, Boundary или факта.
* Hamiltonian lifecycle/update commands не присваиваются Oracle без отдельного решения.
* Raw evidence прежних запусков и исторические task artifacts, привязанные к
  прежним source revisions, не переписываются задним числом и исключены из
  active build/typecheck.

## Критерии готовности

* Документы-владельцы задают одно имя и один смысл RPC-поверхности.
* Public types, paths, routes, wire discriminants, code и tests используют только Oracle.
* Hamiltonian experiment использует logical Oracle lane рядом с Force.
* Остаточные прежние строки допустимы только в неизменяемом raw evidence и
  исторических task artifacts прежних revisions; в active source, contracts,
  документации и build inputs их нет.
* Focused и полные проверки проходят без deprecated aliases.

## Проверка результата

* Focused Oracle suite: `73 pass`, `0 fail`.
* Корневой `bun run check`: typecheck, 42 ожидаемые type-error proofs и
  `2285 pass`, `0 fail`.
* Active source, contracts, manifests, routes, documentation и build inputs не
  содержат прежнего имени; historical evidence остаётся привязанным к своим
  source revisions и исключено из active build.
* Isolated cold runtime acceptance сохранила текущую one-listener topology:
  Boundary, Energy, Bulk и Matrix подключили отдельные Oracle и Force channels,
  а contour штатно завершился после `--once`.
* Hamiltonian имеет отдельный result commit и свежий browser proof логических
  `oracle`/`force` lanes; production transport этим переименованием не менялся.
