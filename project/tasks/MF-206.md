# MF-206 — Доказать сквозное изменение необязательного Field

Состояние: `REVIEW`. Исполнитель: текущая задача Codex.

## Зачем

Общий структурный путь должен быть доказан одним небольшим пользовательским
изменением через все владельцы.

## Границы

Сценарий проходит:

```text
предложение -> проверка -> source -> execution -> Boundary -> Bulk
```

* Добавить public contract `meta.declaration.apply` с одной закрытой
  декларационной entity и точной source revision.
* В первом slice реализовать Field `add`, `replace`, `remove` и значимый
  `move`; enum variants являются содержимым Field, а не отдельной таблицей API.
* Сохранить один accepted patch, одну Inflaton на изменённую entity и тот же
  live-first/source projection path без повторного чтения живого мира.

## Критерии готовности

Необязательный Field добавляется или изменяется через публичный typed RPC,
существующую Force-history и обработку ошибок, а фактический результат виден в
source projection, Boundary и Bulk. Новая access policy в задачу не входит.

## Доказательства

* Публичный `meta.declaration.apply` типизирован и ограничен одной Field entity
  с точными source revisions; реализованы `add`, `replace`, `remove` и перенос
  необязательного хвостового Field между Meta.
* Операции `mf206-field-add-v1`, `mf206-field-replace-v1` и
  `mf206-field-remove-v1` приняты существующей Force-history. Повтор add с тем
  же operation ID переиспользовал sequence `637`, не создав второй patch.
* Один accepted Field patch проецируется непосредственно в загруженный Dark;
  source-hydration выполняется только при восстановлении утраченной проекции,
  без перечитывания и сравнения принятого patch с живым миром.
* Boundary сохраняет Field и его enum variants одной транзакцией, а перенос
  сохраняет persisted identities. Matrix разрешает только временно
  отсутствующий default Variant при replay старой истории.
* В живом контуре add/replace/remove прошли через Dark, Boundary, Matrix,
  Energy и Bulk. Observer того же Bulk-соединения показал рост Field rows
  `55 -> 56`; связанный PNG изменился. WebGPU capture содержит 2 render pass,
  1569 draw calls и 0 validation errors.
* После проверки `zavx0z/lada-test` удалён из Matter Лады, а обе source
  projection восстановлены побайтно: Лада
  `sha256:718536ff8de36cc82030c593a9b8800b52067e3039158216733cb67ea3b5fff5`,
  `lada-test`
  `sha256:4b4ac579fc397b88d013945c3e3b867065cd9650c6a7743e2d3f73e277b70631`.
* Полная проверка: `bun run check` — 2174 теста, 0 ошибок.

## Известные границы

* GPU timestamps на этом capture недоступны; визуальное доказательство не
  содержит измеренного GPU time.
* Access policy, конкурентное редактирование и отдельный журнал операций не
  входят в этот slice.
