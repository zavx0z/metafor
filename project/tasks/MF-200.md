# MF-200 — Утвердить договор структурной операции

## Зачем

Создание и изменение Meta должны проходить один проверяемый путь, а не набор
несвязанных операций записи и запуска.

## Решение владельца

Владелец утвердил RPC-first создание Meta и live-first structural update.
Source projection подготавливается до commit, но публикуется только после
Boundary commit и применяет тот же patch без повторного чтения живого мира.
Комментарии не сохраняются. Исполнитель: текущая задача Codex.

Первый предметный сценарий: RPC создаёт инертный `zavx0z/lada-test`, затем
Matter `add`, `move` внутрь `zavx0z/lada-chat` и `remove` проходят через один
общий договор.

## Критерии готовности

Каждая фаза имеет владельца, публичную форму данных и однозначную границу
успеха или отказа.
