# BLK-002 — Нодовая система Bulk в Space

## Коротко

Bulk требуется собственное нодовое представление Вселенной в WebGPU
`Space`/`Display`. Оно использует универсальные законы пакета `nodes`, но смысл
Atom, State, Field, Condition, Process и доступного человеку изменения остаётся
у Bulk. Отключённый HUD Node View является неудавшимся экспериментом: его нужно
удалить, а не развивать или принимать за основу новой системы.

Задача сохраняет исторический номер прежнего черновика
`BLK-002 — Детальный просмотр сущности`. Новое обсуждение не создаёт `BLK-004`,
потому что относится к той же незавершённой линии Node View, но заменяет её
неверную исходную постановку.

## Решения владельца

1. Ноды Bulk находятся в `Space` и отображаются через `Display`, а не являются
   отдельной нодовой поверхностью HUD.
2. Текущий отключённый Node View не является прототипом для продолжения. Всё,
   что было добавлено только для него в Bulk и общем HUD, сначала удаляется.
3. Web Components из Metaphor Space не переносятся как технология. Они являются
   историческим доказательством общих смысловых и визуальных принципов; текущая
   реализация строится на WebGPU/Engine.
4. Пакет `nodes` не получает Bulk-, MetaFor- или Hamiltonian-сущности. Он владеет
   универсальной моделью, validation, layout/routing laws и универсально
   названными UI-примитивами и способами сокетов.
5. Формулы раскладки не копируются в Bulk. Bulk измеряет и проецирует собственные
   компоненты в универсальный числовой layout contract пакета `nodes`, затем
   отображает полученную geometry своими компонентами.
6. Один visual socket kind может иметь разный предметный смысл в Bulk,
   Hamiltonian и стороннем проекте. `nodes` описывает только универсальную
   capability/geometry/presentation role; предметную интерпретацию задаёт
   consumer.

## Общие принципы, извлечённые из Metaphor Space

Технологически независимая часть прототипа:

* нодовое представление является производной проекцией причинного мира, а не
  вторым владельцем canonical state;
* крупная сущность раскрывается через отдельные смысловые элементы: Atom/Meta,
  States, Fields/parameters, Conditions, Operators и Transitions;
* Field/parameter остаётся точной адресуемой строкой, а связь заканчивается в
  exact socket этой строки;
* фиксированное представление имеет раздельные вход и выход на противоположных
  сторонах; capability сокета, тип связи, runtime state и движение сообщения не
  подменяют друг друга;
* Condition и Operator являются видимой частью причинного пути, а не только
  текстовой подписью абстрактного edge;
* active State и выполняющийся Process должны быть различимы;
* значение Field показывается и при разрешённом сценарии изменяется контролом,
  соответствующим его типу;
* intrinsic размеры содержимого и точные offsets сокетов известны до layout;
  layout возвращает geometry и не меняет предметную topology;
* состав представления строится из независимых смысловых компонентов, но способ
  их исполнения — Web Components или WebGPU objects — не является доменным
  законом.

## Что из старого прототипа не переносится

Не являются целевыми законами:

* Web Components, closed Shadow DOM и actor-specific lifecycle;
* координация layout через actor patches и `sessionStorage`;
* ELK как runtime-зависимость;
* измерение через DOM `getBoundingClientRect()`;
* прямое изменение actor context из input component;
* старая snapshot-схема и названия component tags;
* отдельный Graph Store или вторая копия сцены.

В текущей архитектуре единственный Bulk Store изменяется Force Particles. Любое
предметное изменение Field должно проходить через допустимый Oracle/Force path,
например `meta.field.value.apply`, а renderer не становится владельцем факта.

## Текущий неудавшийся эксперимент

Код сейчас отключён через `NODE_VIEW_CONNECTED = false`, но остаётся в
dependency graph. Перед новой реализацией требуется удалить только эту
экспериментальную линию:

* `../../quantum/bulk/node-view.ts`;
* Node View imports, controller methods, dock и surface из `../../quantum/bulk/hud.ts`;
* оставшуюся проверку CSS class в `../../quantum/bulk/web/index.ts`;
* `HudNodeView*`, planner/drawer и test из `pkg/ui/hud/node-view.ts` и
  `pkg/ui/hud/node-view.test.ts`, а также export из `pkg/ui/hud/index.ts`;
* `setNodeView` из `types/bulk/hud.ts`.

Очистка не разрешает одновременно строить новую систему и не должна затрагивать
causal timeline, fullscreen, обычный HUD, Bulk Store, Visual или пакет `nodes`.
Она получает отдельную подзадачу после принятия `BLK-002` в граф исполнения.

## Граница с универсальной node-system

Постоянные договоры `nodes` и `@nodes/*` отвечают за универсальные физические
пакеты и контракты:

* identity, exact endpoints, validation и containment;
* чистые детерминированные layout/routing formulas;
* независимые fixed/adaptive policies без загрузки чужого варианта;
* универсально названные socket, edge, viewport и interaction primitives;
* consumer-provided semantic keys, styles и component/content adapters.

`BLK-002` отвечает за:

* проекцию единственного Bulk Store в node-system document;
* смысл Atom, State, Field, Condition, Operator, Transition, Process и Reaction;
* Bulk-specific WebGPU components и их композицию в `Space`/`Display`;
* выбор, навигацию и предметные intent/receipt состояния;
* live-обновление после точных Particle handlers;
* отдельную визуальную и пользовательскую приёмку Bulk.

Недостающие Bulk facts, включая точную доступность Condition predicate или
редактирующего intent, обсуждаются и принимаются в Bulk-задаче. Они не расширяют
универсальную модель `nodes` доменными полями.

## Предполагаемая декомпозиция после принятия

Это порядок будущего обсуждения, а не зарегистрированные подзадачи реализации:

1. удалить отключённый HUD Node View и подтвердить отсутствие его imports;
2. зафиксировать Bulk node projection и доступные данные;
3. определить WebGPU component anatomy и универсальный fixed-layout adapter;
4. реализовать read-only `Space`/`Display` presentation;
5. отдельно принять navigation и Field intent path;
6. доказать live Particle update, производительность и визуальную приёмку.

## Границы

* Пока задача `DRAFT`, не удалять экспериментальный код и не строить новый
  runtime.
* Не переносить Bulk entities, Condition schema или Field controls в `nodes`.
* Не копировать layout/routing formulas в Bulk.
* Не добавлять второй Graph Store, Manifest или browser storage.
* Не читать Boundary, SQLite или Matrix напрямую из Bulk/browser.
* Не считать исходный код Metaphor Space действующим контрактом.
* Не выдавать source write, tests или отдельный playground за visual/live
  acceptance в рабочем Bulk contour.

## Критерии готовности

1. Отключённый HUD Node View удалён отдельным проверенным срезом без изменения
   остальных HUD surfaces.
2. Документ-владелец задаёт смысловую модель Bulk node system и её отношение к
   единственному Bulk Store.
3. Bulk-specific components находятся у Bulk и отображаются через
   `Space`/`Display`; `nodes` не содержит Bulk domain names.
4. Layout/routing выполняется универсальным пакетом `nodes`; в Bulk нет второй
   реализации формул.
5. Exact Field/socket identities, Condition/Transition paths и runtime states
   не восстанавливаются эвристикой renderer.
6. Предметное изменение проходит подтверждённый Oracle/Force path и становится
   видимым только после accepted Particle/projection receipt.
7. Production-like browser build доказывает независимость от adaptive
   Hamiltonian implementation и отсутствие удалённого HUD Node View.
8. Рабочий browser contour подтверждает selection, navigation, live update,
   возврат к общему Space и согласованную визуальную приёмку владельца.
