# UI-004 — Интегрировать retained UI и общий UI skill в main

## Коротко

Собрать в canonical `main` расходящиеся UI/Node результаты, сначала принять
общий `UI dev` и поднять через него существующие playgrounds, затем перенести
закрытый retained parent/child mechanism и довести Elements, Components и их
consumers до одного engine-owned hierarchy. После интеграции package playgrounds
должны работать на общем публичном shell, а NODES-017 продолжает визуальную
доводку без возврата к плоскому immediate-mode пути.

## Зачем

Ветка UI development уже содержит восстановленный Components playground,
принятый `@ui/playground` и общий skill, а закрытая NODES-018 независимо
реализовала retained `Object3D` hierarchy. Простое слияние любой одной ветки не
даёт целого: актуальный `main` сохраняет параллельную Hamiltonian project line,
Node playground WIP не запустил browser entry, Node comparison использует
перемещённый reference asset, а Elements/Components ещё не имеют полного retained
inventory и migration proof.

## Связь с дорожной картой

Работа продолжает действующее направление UI/Node observability из раздела
`Наблюдаемость и управление Hamiltonian`, но не мигрирует Hamiltonian consumer и
не меняет semantic Node/Parameter/Field design. Постоянные retained законы уже
принадлежат Engine, `@ui/elements`, `@ui/components` и `@nodes/ui`; эта карточка
владеет только интеграцией, полным inventory, миграционными срезами и evidence.

## Решения владельца

1. Работа выполняется прямо в canonical checkout и branch `main`; новый branch,
   clone или worktree запрещён. Integration/merge/cherry-pick разрешены, push —
   только по отдельному запросу.
2. Причинный порядок: сначала интегрировать `codex/ui-dev-skill`, затем через
   уже интегрированный `UI dev` поднять и проверить все существующие
   playgrounds, и только после этого интегрировать `codex/nodes-018`.
3. После retained merge сознательно адаптировать WIP `codex/node-layot` к
   integrated public shell; не выбирать project/Node conflicts целиком одной
   стороной.
4. Engine `Object3D` остаётся единственным scene graph. Parallel transform tree,
   local visual scale floors и DOM/CSS renderer запрещены.
5. System называется `FlexBox`; CSS-style является только declarative
   description того же layout.
6. Existing Blender-style Node, Parameter и current Field не заменяются до
   отдельной Blender+Field design stage. В UI-004 меняются retained mechanics и
   dev playground composition.
7. UI Elements/Components больше не frozen: UI-004 полностью мигрирует каждый
   scalable/nested visual subtree, которому полезны parent transform и retained
   lifecycle. Осознанный flat immediate path остаётся только там, где этих
   свойств нет, и получает явную границу в owner doc.
8. Browser/canvas evidence выполняется только background exact CDP через
   `UI dev`. Запрещены `Page.bringToFront`, focus/activate/window APIs,
   AI macOS и screenshot services; canvas читается через `toDataURL`, mobile
   metrics всегда восстанавливаются в `finally`.
9. Existing listeners/processes/targets сохраняются: foreign process не
   присваивается, duplicate не запускается, lifecycle относится только к exact
   checkout/selector/PID/command/listener.
10. Pre-closing проверки NODES-018 не повторяются как приёмка старой ветки;
    проверяется только новый integrated `main`.

## Целевой retained закон

```text
dirty local FlexBox plan
          ↓
atomic materialization changed subtree under exact Object3D parent
          ↓
parent transform only
          ↓
matrixWorld / inverse → frame, clip, culling, hit and wheel
```

Visual Text, Icon, Button, Field, Switcher, padding, gap, radius, border,
stroke и Socket наследуют parent transform. Screen minimum существует только
как отдельный невидимый hit target. Recursive remove/rematerialize/dispose
очищает owned subtree и interaction records без orphan либо double disposal.
