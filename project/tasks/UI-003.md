# UI-003 — Создать общий skill разработки UI и Node playground

## Коротко

Перенести node-local development skill в `pkg/ui` и превратить его в общий
`ui-dev`: агент одной командой запускает, перезапускает, читает logs, проверяет
и останавливает playground нужного UI/Node package, а browser evidence и
profiling получает фоново через exact CDP target.

## Зачем

Текущий `node-system-dev` умеет безопасно обслуживать только Node playground
4016. Для Components, Elements, общего Playground package и Node агент снова
вручную ищет command/port/PID/target и может случайно отнять у владельца focus.
Владелец потребовал UI-аналог `$metafor-dev`, скрывающий эту механику.

## Связанные задачи и история

* NODES-017.7 result `7fd390923` создал versioned node-local skill; correction
  `e29d374fd` перевёл lifecycle в long-lived PTY.
* `$metafor-dev` служит reference: exact checkout ownership, один dispatcher,
  `status/start/restart/logs/stop`, stable CDP target и отдельный visual/
  profiling workflow.
* Owner review запретил automated `Page.bringToFront`, AI macOS screenshots и
  другое управление интерфейсом: canvas evidence читается background CDP.
* UI-002 result `efbad1689` создал `@ui/playground`, поэтому общий skill теперь
  имеет package-level owner в `pkg/ui`.
* По прямому решению владельца работу выполняет тот же пользовательский чат,
  который создавал NODES-017.7, после чего root интегрирует result в node line.

## Решения владельца

1. Новый path: `pkg/ui/.agents/skills/ui-dev`; старый
   `pkg/nodes/.agents/skills/node-system-dev` удаляется переносом без duplicate.
2. Skill охватывает UI Elements, UI Components, shared UI Playground fixtures,
   Node UI и при необходимости Node layout playground как отдельный non-WebGPU
   contour.
3. Dispatcher скрывает package-specific cwd, command, env port, PID/log/target
   и реализует `status/start/restart/logs/stop/health` по образцу metafor-dev.
4. Любой listener сначала точно идентифицируется. Foreign process сохраняется;
   duplicate/adoption/kill по номеру порта запрещены.
5. Browser operations работают по exact target URL/ID в фоне. Automated path
   не вызывает `Page.bringToFront`, `/focus`, window APIs или AI macOS.
6. Canvas capture — `toDataURL` через CDP. Mobile emulation обязательно
   возвращает native metrics даже после failure.
7. Visual profiling включает DOM/console/canvas, browser performance metrics,
   frame/heap evidence и routing к внешнему WebGPU Inspector workflow без
   instrumentation в production source.
8. Skill не меняет UI/Node production implementation и не подменяет explicit
   owner acceptance automated capture.

## Dispatcher contract

```text
ui-dev.sh status  <checkout> <playground>
ui-dev.sh start   <checkout> <playground>
ui-dev.sh restart <checkout> <playground>
ui-dev.sh logs    <checkout> <playground>
ui-dev.sh stop    <checkout> <playground>
ui-dev.sh health  <checkout> <playground>
```

Registry для каждого selector задаёт package owner, cwd, start command, exact
origin/port, ready marker и WebGPU/canvas capability. Недоступный ещё package
playground возвращает typed unsupported state, а не выдумывает command.

## Browser contract

Background helper принимает selector либо exact origin, находит ровно один page
target, выполняет reload/DOM/console/canvas/viewport/profile и никогда не меняет
OS/browser focus. Route-specific URLs поддерживаются полностью. Profiling
возвращает source target ID, viewport/DPR, `Performance.getMetrics`, heap/frame
samples и явную границу GPU capture.

## Границы

* Менять только skill directory, его tests/assets/references и project files.
* Не менять production UI/Node, package playground implementation либо NODES-018.
* Не копировать metafor-dev целиком: переиспользовать его законы, сохраняя
  отдельный UI/package lifecycle.
* Не использовать detached/nongit temp checkout для result.

## Критерии готовности

1. Skill проходит `skill-creator` validation и имеет точный discriminating
   description/openai metadata.
2. Registry и dispatcher покрыты isolated lifecycle tests минимум для two
   selectors, foreign listener и restart/logs/stop.
3. Background exact CDP capture доказан без focus events.
4. Desktop/portrait/landscape restore и route-specific target проходят.
5. Performance evidence structured, repeatable и не требует source changes.
6. Старый node-local skill отсутствует, Node workflow описан в UI skill.
7. Result commit находится в отдельном UI skill worktree и готов к интеграции.
