# UI-009 — Восстановить живые playground после UI exports

## Коротко

Вернуть browser-ready состояние `@ui/elements` на `7901` и `@nodes/ui` на
`4016`, не затрагивая уже работающие Components `4017` и Workbench fixture
`4192`.

## История и причина

* UI-007 закрыла масштабируемый Workbench checkpoint-ом `82a1d177e`.
* UI-008.2 опубликовала exact `@ui/components/*` exports коммитом `462f8fd12`
  в `04:30:27 +03:00`.
* Elements PID `21023` и Node UI PID `23179` были запущены соответственно в
  `03:33` и `03:36`, до нового package manifest. Их long-lived Bun resolver
  продолжает отвечать ошибками `Could not resolve` для
  `@ui/components/button`, `pane`, `text-field`, `typography`; browser
  `entry.js` не собирается и ready marker не достигается.
* Fresh in-memory builds обоих exact entrypoints проходят без logs. Packages и
  exports на диске корректны; `bun install` и product patch не нужны.
* Components PID `60443`, запущенный после exports, и fixture PID `87410`
  достигают `ready`, имеют console `0` и non-black canvas.

## Срез

1. Через `$ui-dev` повторно проверить ownership и перезапустить только selectors
   `elements` и `node-ui` в long-lived PTY.
2. Сохранить по одному существующему browser target на origin и проверить exact
   routes `/layout/flex-css` и `/editor/scene`.
3. Подтвердить DOM ready, console `0`, non-black exact canvas и native desktop
   metrics; затем повторно проверить `components` и `ui-fixture` без restart.
4. Не менять source, package manifests или production delivery, если controlled
   restart полностью устраняет расхождение.

## Критерии готовности

* `7901`, `4016`, `4017`, `4192` одновременно browser-ready.
* На каждом origin остаётся ровно один прежний target.
* Elements и Node UI получают новые только skill-owned PID; Components и fixture
  PID не меняются.
* Все четыре console пусты и exact canvas non-black.
* Причина и пропущенный live acceptance gate записаны без выдачи fresh build за
  доказательство старого процесса.
