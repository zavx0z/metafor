# MF-204 — Принять один Matter patch через Force

## Зачем

Структурный RPC должен сначала причинно изменить живой мир, а source остаётся
проекцией уже принятого изменения.

## Границы

* Один `meta.matter.apply` выполняет одну root-level WIMP operation `add`,
  `move` или `remove`.
* До live commit provider проверяет capability, scope, source revisions и
  строит точные source candidates без публикации.
* Live commit принимает одну Particle через Dark Force history и Boundary.
* Причина RPC и source revisions хранятся в той же Force history entry.
* Source не публикуется в этой задаче: повтор и публикация принадлежат MF-205.
* Патч строится из запроса и source preconditions без перечитывания живого
  мира и без второго operation journal.
* Никакой частичной горячей перезагрузки доменов.

## Критерии готовности

Изолированный предметный сценарий доказывает, что `add`, `move` и `remove`
готовят точный source patch, принимают ровно одну Particle обычным Force-путём,
возвращают точную acceptance identity и оставляют source неизменным.
