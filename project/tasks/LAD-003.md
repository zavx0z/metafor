# LAD-003 — Ответ Лады через Send Tool

## Зачем

Текущий Model Service создаёт `replyDraft`, но Agent не превращает его в
намерение `outgoingMessage`, поэтому готовый Chat Send Tool не запускается.

## Решение владельца

Ответ на принятое явное `@lada` автоматически отправляется один раз в ту же
общую комнату.

## Границы

* Agent не вызывает Chat API напрямую.
* Model Service только создаёт ответ; отправляет существующий Chat Send Tool.
* Ответ причинно связан с исходным `messageKey`.
* Persona передаётся модели как `system` message; reasoning trace не хранится.

## Критерии готовности

* Один принятый inbox message создаёт один model request.
* Успешный model result создаёт одно Agent intention для Send Tool.
* Ack и realtime echo завершают outbox entry и сохраняют sent message key.
* Ошибка модели или отправки наблюдаема и не приводит к скрытому повтору.

## Подтверждённая исходная точка

* Настоящее обращение уже породило один `replyDraft` через локальную
  `qwen3.5:9b`; Chat Send Tool подключён и находится в `ожидание намерения`.
* Текущий Agent очищает исходный `incomingMessageKey` до завершения модели и не
  хранит отдельную причинную ссылку черновика на исходное обращение.
* Persona пока встроена в текст пользовательского prompt, а не передана
  отдельным `system` message. Оба расхождения входят в эту задачу.

## Результат и доказательства

* Agent сохраняет причинный `replyToMessageKey`; существующий `chatOutbox`
  содержит один `intent → pending → sent`, а отдельный журнал не создан.
* Model передаёт persona отдельным `system` message и вызывает Ollama с
  `think: false`; автономная проверка прошла `2 pass`, `11 expect`.
* Настоящее обращение `63d3984a-f9f6-4119-bd37-085354ffcce6` породило ровно
  один ответ `6bae33f2-42d7-465e-8822-6aef98099efe` в той же общей комнате.
* Outbox сохранил оба ключа, ack и realtime echo завершили отправку, а Graph
  очистил `replyDraft`, `replyToMessageKey` и `outgoingMessage` без ошибки.
* После полного холодного старта history содержит три сообщения, outbox — тот
  же единственный `sent`; повторной отправки нет, SSO и WebSocket восстановлены.
* TypeScript-проверки `zavx0z/lada`, `zavx0z/lada-model` и
  `zavx0z/lada-chat` прошли без ошибок.

## Известная особенность

Matrix не каскадирует новый transition только от structural State patch и не
считает повтор того же Field изменением. Одноразовое включение нового маршрута
поэтому использовало два безопасных предметных импульса с восстановлением
исходных значений; обычные будущие inbox и model writes уже сами адресуют
условия router.
