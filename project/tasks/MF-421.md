# MF-421 — Деактивировать невидимый monitor UIDisplay

## Зачем

После помещения живого Hamiltonian graph на `UIDisplay` в engine `Space`
монитор не должен расходовать CPU, GPU и browser-local traffic, когда этот
дисплей полностью находится вне области просмотра пространственного
`ViewPoint`. Простое отсутствие видимых пикселей недостаточно: нужен точный
жизненный цикл monitor/display contour с освобождением ресурсов и причинно
корректным возвращением.

## Основание

Готовая и визуально принятая пространственная модель закреплена постоянным
[Hamiltonian contract](../../hamiltonian/README.md):
`Space → ViewPoint → UIDisplay → infinite graph canvas` и отдельный HUD.
Поэтому объект, чью видимость и ресурсы нужно контролировать, уже определён.

## Решение владельца

Если world-geometry конкретного `UIDisplay` не пересекает область просмотра
актуального `ViewPoint`, полностью деактивировать относящиеся к нему мониторинг
и отрисовку вплоть до выгрузки GPU buffers. Пока monitor display неактивен, не
публиковать предназначенные ему lifecycle/message observations по
BroadcastChannel. При возвращении дисплея восстановить монитор из актуального
retained snapshot и causal frontier без replay накопленной истории.

## Целевой закон

* Источник решения о видимости — пересечение фактического world-space quad или
  bounds `UIDisplay` с frustum текущего engine `ViewPoint`. Это не
  `document.visibilityState`, не открытость HUD и не предположение по
  координатам browser window.
* Любое пересечение дисплея с областью ViewPoint сохраняет состояние `active`.
  Полное отсутствие пересечения переводит только monitor contour этого
  display в `inactive`. Пограничное движение не должно порождать многократные
  activate/deactivate между соседними кадрами.
* Деактивация не останавливает настоящий Hamiltonian runtime, Service Worker,
  Window/Dedicated Worker, Bun process, peer, lease, signaling или transport.
  Она выключает только наблюдатель, projection/layout/routing, transient
  traffic presentation и renderer конкретного monitor display.
* В `inactive` monitor не подписывается и не публикует display-bound сообщения
  через lifecycle BroadcastChannel, не запускает layout/routing, rAF и particle
  animation и не удерживает скрытую очередь событий для поздней выдачи.
* Если один browser-local lifecycle source обслуживает несколько monitor
  displays, BC publication отключается только при отсутствии всех активных
  подписчиков. Один невидимый display не может заглушить другой видимый.
* При деактивации очищаются transient observations, routes, layout/projection
  presentation state и освобождаются GPU vertex/index/uniform buffers,
  geometries, materials и другие retained renderer resources этого graph
  surface. Минимальный activation state не содержит traffic history.
* Возврат в frustum сначала заново создаёт display renderer resources, затем
  получает retained snapshot активных entity/transport и causal frontier и
  только после него принимает live continuation. События периода inactive не
  выходят частицами задним числом; gap показывается явно, если frontier нельзя
  продолжить точно.
* Состояние `active/inactive`, причина перехода, число активных display
  subscribers, размер очередей и количество живых GPU resources доступны для
  автоматической и live-проверки без включения production Inspector.

## Границы

* Не смешивать эту оптимизацию со структурной раскладкой и маршрутизацией graph.
* Не выдавать frustum culling одного render frame за полную деактивацию
  monitor contour и освобождение ресурсов.
* Не прекращать причинные runtime-события или authority только потому, что их
  наблюдатель не виден.
* Не сохранять BC backlog, traffic history или старый layout для ускорения
  возврата.
* Не добавлять polling, если переходы ViewPoint/display уже можно получать из
  событий engine runtime.

## Критерии готовности

* Тест с движением ViewPoint полностью выводит UIDisplay за frustum и получает
  ровно один переход monitor `active → inactive`.
* В устойчивом `inactive` не растут render/rAF, layout/routing, BC send/receive и
  traffic-presentation counters; GPU resource inventory подтверждает
  освобождение graph buffers.
* Настоящие Service Worker, page, worker, Bun и peer runtime продолжают жить и
  не меняют authority из-за невидимости display.
* Возврат того же UIDisplay во frustum даёт один переход `inactive → active`,
  повторное выделение только необходимых buffers и причинно точный текущий
  graph из snapshot/frontier без запоздалой партии сообщений.
* Два display/subscriber доказывают reference-counted поведение: скрытие одного
  не отключает BC для другого, скрытие последнего отключает публикацию.
* CPU/GPU/heap и BC timeline до, во время и после inactive подтверждены на
  чистом exact-target contour; console и WebGPU validation errors отсутствуют.
