# UI-010 — Сделать полный набор универсальных полей по Blender

## Коротко

Обычные панели и Node Editor получают один полный набор точных input controls:
числа, меню, цвета, ramp, curves, ссылки и изменяемые коллекции. Одни и те же
компоненты работают внутри Node Parameter и вне нодовой системы.

## Зачем

Текущий `Field` покрывает только первый набор value kinds и собран крупным
условным renderer. Blender catalog показал отдельные interactions и состояния,
которые сейчас либо упрощены до кнопки/текста, либо отсутствуют. Если добавить
их непосредственно в Node renderer, появятся копии и расходящиеся contracts.

## Связь с дорожной картой

Задача продолжает универсальную UI/Node component line параллельно UI-011:
production controls и playground имеют разных исполнителей и непересекающиеся
границы. Направление зависимостей остаётся
`Engine → Elements → Components → Node UI`.

## Связанные задачи и история

* UI-001 восстанавливает Components playground и переносит его на shared
  package-owned stories. Следующее прямое решение владельца передало execution
  и closing UI-001 руководителю UI-011, а UI-010 разрешило развивать production
  Components параллельно без изменений playground.
* Самостоятельный
  [Blender Node Catalog](/Users/zavx0z/repozitarium/blender-node-catalog/README.md)
  на commit `62bf479` собрал 36 socket presentations, 63 node-owned property
  presentations и 49 source UI mechanisms. Это reference inventory, а не
  автоматически выбранный API MetaFor.
* Исследованы обсуждения
  [Node component library](codex://threads/01a01742-3e9d-7393-aacf-affe36787ba0)

  Прежняя минимальная выборка не является полным набором параметров.

## Подтверждённые факты

* Уже можно переиспользовать `TextField`, `SliderControl`, `Switcher`,
  `Button`/`IconButton`, `Typography`, `List`, `Table`, FlexBox, retained
  `UiSurface`, icons, clipping и input lifecycle.
* Отсутствуют готовые public select/popover, color picker/ramp, curve editor,
  reference/file/search picker и collection mutation/reorder controls.
* Текущий enum циклически меняется кнопкой, color редактируется как hex,
  reference вызывает внешний action, а topology-changing state не выражен
  универсальным control contract.

## Решения владельца

1. `Field` остаётся единым semantic facade, но конкретные controls становятся
   самостоятельными public Components.
2. `@nodes/ui` только компонует controls в Parameter и владеет Node/Socket
   topology; Node-копии universal controls запрещены.
3. Поведение, состояния и compact-пропорции берутся из Blender. Материалы,
   проектный шрифт и общая тема остаются MetaFor.
4. Принятые расхождения сохраняются: `Switcher` вместо checkbox, округлённая
   Node header и ортогональные Links.
5. Пропорции, padding и положения измеряются по exact Blender 4.5.5 reference,
   а не подбираются на глаз.
6. Blender source, assets и полный catalog не копируются в MetaFor.

## Целевые группы controls

* numeric input и slider с subtype, units, hard/soft range, step и precision;
* select/menu, expanded choices и error/undefined states;
* color swatch/picker и ordered color ramp;
* vector/rotation component editor и curve mapping;
* text, file path и contextual search;
* opaque reference picker с browse/clear и owner-supplied actions;
* collection editor с selection, add/remove/reorder;
* disabled, read-only, linked/hidden и compact/regular presentations.

Конкретная группа получает собственную последовательную подзадачу перед
реализацией. Наличие группы в target catalog не означает, что все её варианты
реализуются одним patch.

## Подзадачи

### UI-010.1 — Вынести числовой ввод в public NumberInput

Статус и исполнитель: `COMPLETE` на package contract; live Field story остаётся
общим parent gate UI-011.3.

Классификация: первый production-срез нового parent. Он изменяет один механизм:
скалярный numeric input, который сейчас скрыт внутри монолитного `Field`.

Требование: `NumberInput` является самостоятельным public Component с
controlled number value, integer/float contract, min/max/step/unit,
disabled/read-only и regular/compact presentation. `Field` использует этот же
Component; `SliderControl` остаётся отдельным уже существующим presentation.

Основание и история: NODES-016 ввела scalar normalization и два локальных пути
отрисовки в `Field.ts`; UI-010 owner law требует public controls без Node-копий.
Float/Integer являются самыми частыми value presentations Blender catalog и
дают минимальный проверяемый первый срез.

Наблюдаемое расхождение: regular и compact scalar number напрямую собирают
`TextField`, сами парсят unit и вызывают `normalizeNumberFieldValue`. Отдельного
leaf import и самостоятельного Component contract нет.

Причина: первый набор Fields реализовывался как минимальный единый renderer до
решения разделить concrete controls.

Разрешённое изменение одного механизма: добавить public `NumberInput`, его pure
normalization/parsing tests и exact subpath; перевести только scalar number
ветки `Field` на него. Vector, matrix, slider, playground и Node renderer не
меняются в этом срезе.

Regression: standalone NumberInput и Field возвращают одинаковое normalized
value; integer, min/max, step, unit, invalid input, disabled/read-only и compact
style проверяются focused tests. Exact leaf build не содержит Node/playground.

Среда и приёмка: package tests/typecheck и delivery exact-import proof. Live
Components/Node evidence выполняется совместно с UI-011 после её route patch;
до этого fresh build не выдаётся за loaded playground acceptance.

Подготовительный commit: записывается до implementation patch.

Фактические действия и результат: commit `99f80c0e2` добавил public
`NumberInput` и exact subpath `@ui/components/number-input`. Regular/compact
scalar Field делегируют ему render/parse/normalization; существующий
`normalizeNumberFieldValue` стал однострочным делегатом единственному owner.
Slider, vector, matrix, Node и playground не менялись.

Regression и проверки: Components `17/17`, delivery `8/8`, Components и
delivery typechecks, exact leaf build без Node/playground symbols и diff-check
прошли. Первый delivery run внутри restricted sandbox дал ложный
`Unexpected reading file`; тот же read-only Bun.build suite вне ограничения
прошёл `8/8`.

Live boundary: `socket/float/input` на singleton target UI-011 был DOM-ready,
console `0` и non-black, но detail story показывает только Socket и не вызывает
Field/NumberInput. Этот кадр правильно не сохранён как ложное UI-010 evidence.
Standalone `Field → NumberInput` принимает UI-011.3 Components story; открытый
live gate не блокирует следующие production slices по прямому решению владельца
вести Components и playground параллельно.

### UI-010.2 — Вынести цветовой ввод в public ColorInput

Статус и исполнитель: `IN_PROGRESS`, внутренний исполнитель текущей задачи.

Классификация: следующий production control того же parent. Он изменяет один
механизм: scalar RGBA input, сейчас скрытый внутри `Field`.

Требование: `ColorInput` становится самостоятельным public Component с
controlled normalized RGBA, swatch + exact hex input, alpha, disabled/read-only
и regular/compact presentation. `Field` использует тот же Component.

Основание и история: current regular/compact color branches отдельно собирают
одинаковые swatch/TextField и владеют conversion helpers. UI-010 требует один
public control owner до добавления popup picker и ColorRamp.

Наблюдаемое расхождение и причина: `Field.ts` напрямую рисует color swatch,
парсит/форматирует hex и повторяет эту composition для двух density. Это
наследие минимального монолитного NODES-016 renderer; standalone leaf import
отсутствует.

Разрешённое изменение одного механизма: добавить public `ColorInput`, перенести
к нему scalar RGBA normalization/hex conversion и перевести только regular и
compact color Field branches. Popup ColorPicker, ramp stops, overlay, остальные
Field kinds, Node и playground не меняются.

Regression: standalone ColorInput и обе Field density возвращают одинаковое
RGBA; clamp/alpha/hex invalid input, disabled/read-only, swatch и compact
geometry проверяются focused tests. Exact leaf build исключает Node/playground.

Среда и приёмка: package tests/typecheck/delivery exact build. Live evidence
принадлежит будущей UI-011.3 Components story и остаётся parent gate.

Подготовительный commit: записывается до implementation patch.

## Границы

* Не переносить Socket, Link, Node preview, Node panels или topology semantics в
  `@ui/components`.
* Не создавать параллельный legacy/new Field API, compatibility aliases или
  Node-specific control bundle.
* Не менять layout solver, Hamiltonian либо product integration.
* Общую недостающую возможность Elements сначала оформить отдельным owner
  slice; не скрывать popup/overlay lifecycle внутри одного Field.
* Production leaf imports остаются независимыми и разделяют один Engine,
  Elements и product-owned UiRuntime.

## Критерии готовности

1. Каждый принятый control является отдельным public component и используется
   через единый Field facade.
2. Standalone и Node Parameter показывают один и тот же component/value state.
3. Compact geometry и interaction states сверены с exact Blender reference;
   MetaFor divergences перечислены явно.
4. Controlled immutable callbacks, disabled/read-only и linked/hidden states
   защищены focused tests.
5. Exact subpath builds не дублируют Engine/Elements и не включают playground.
6. Components и Node playground дают DOM/console/canvas evidence; owner visual
   acceptance остаётся отдельным gate.
