# MF-302 — Подключить Create и Matter RPC к живому контуру

## Зачем

Реализованные Create и Matter services должны стать настоящими Monad RPC, через
которые можно создать `zavx0z/lada-test` и безопасно изменить текущую Ладу.

## Границы

* Dark Monad публикует `meta.capabilities.read`,
  `meta.source.revision.read`, `meta.create` и `meta.matter.apply` только после
  установки их services.
* Capability registry выдаёт явно настроенному RPC source точные methods и
  Meta scopes; отсутствие grant закрывает операцию.
* Matter использует существующие Force history, checkpoint applied-through и
  Boundary delivery. Create использует atomic source patch нового peer. Второй
  operation journal и фиктивная Create Particle запрещены.
* Source revision provider возвращает только digest `meta.ts`, без bytes и
  filesystem path.
* После изменения кода перезапускается весь причинно связанный contour, затем
  пользовательский путь выполняется только через RPC.

## Критерии готовности

Проверки доказывают routing identity, capability/scope denial, source revision,
Create repeat и Matter repeat. На живом контуре через RPC создаётся полный
`zavx0z/lada-test`, после чего текущая Лада проходит `add -> move -> remove` с
проверкой receipt, Force acceptance, `meta.ts` и наблюдаемого мира. Git commit
нового peer и удаление его repository в сценарий не входят.
