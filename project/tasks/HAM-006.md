# HAM-006 — Принять прототип Hamiltonian и очистить packages

## Коротко

После последней живой приёмки отдельно запускаемый прототип Hamiltonian
завершает свою работу как испытательный контур. Задача сохраняет его временное
evidence, точно отделяет prototype-only файлы и зависимости, удаляет их из
packages и подтверждает, что clean-room Hamiltonian продолжает работать сам.

## Зачем

Clean-room `server.ts → startup → release → internal / metafor` уже развивается
рядом со старым contour, который запускается через `server_proto.ts`. Пока оба
контура находятся в одних packages, прототип удерживает лишние dependencies,
tests, TypeScript errors и документационные обязанности. Простое удаление
опасно: сначала нужно завершить его живую приёмку и доказать точную границу.

## Связь с дорожной картой

Задача завершает prototype-ветвь разделов
[`Hamiltonian и воплощения`](../ROADMAP.md#hamiltonian-и-воплощения) и
[`Загрузка Hamiltonian`](../ROADMAP.md#загрузка-hamiltonian). Она зависит от
[`MF-424 — Визуально довести Hamiltonian вместе с владельцем`](MF-424.md):
cleanup начинается после завершения оставшейся visual acceptance.

prototype contour и очищает package boundaries.

## Подтверждённое текущее состояние

* `hamiltonian/server_proto.ts` существует и запускает старый runtime через
  `server-runtime.ts`.
* Обычный `hamiltonian/server.ts` импортирует `@hamiltonian/release` и владеет
  clean-room HTTP/WSS entrypoint.
* В дереве остаются prototype roots `browser/`, `core/`, `public/`, `update/`,
  `visual/` и связанные integration tests.
* Корневой `hamiltonian/package.json` всё ещё содержит зависимости обоих
  contours, включая `@hamiltonian/visual`, Web Push, WebRTC и node-system
  packages.
* `MF-424.2` остаётся активной visual acceptance, поэтому source cleanup пока
  закрыт зависимостью.
* Временное доказательство прототипа перенесено из постоянной документации в
  [`prototype-evidence.md`](../artifacts/HAM-006/prototype-evidence.md) и
  удаляется вместе с карточкой после closing review.

## Решения владельца

* Работа получает отдельный номер с префиксом `HAM`.
* Prototype evidence является материалом задачи приёмки и cleanup, а не
  постоянной документацией Hamiltonian.
* Clean-room code остаётся самостоятельной реализацией; prototype source в него
  не переносится.
* Отсутствующая clean-room capability получает отдельного владельца и задачу,
  а не сохраняет весь prototype contour скрытой зависимостью.

## Порядок выполнения

1. После закрытия `MF-424` зафиксировать owner decision о завершении prototype
   line и точный inventory source, dependencies, scripts, tests, docs и routes.
1. Согласовать последний pre-removal commit и отдельное решение об annotated
   tag; Git history остаётся базовым способом сохранения исходников.
1. Одним removal slice удалить только prototype-owned files и entrypoints.
1. Следующим slice удалить ставшие ненужными dependencies, scripts, tests,
   TypeScript scopes, documentation references и package registrations.
1. Выполнить clean-room typecheck/tests/build и живую owner acceptance обычного
   Hamiltonian entrypoint.
1. В closing review перенести только постоянные выводы к package owners,
   удалить карточку и всю директорию `project/artifacts/HAM-006/`.

## Границы

* Подготовка задачи и перенос evidence не разрешают удаление runtime source.
* До завершения `MF-424` отдельно запускаемый prototype contour сохраняется.
* Cleanup не переносит «полезные куски» в startup, release, internal или
  будущий metafor package.
* Git tag сохраняет удобную точку возврата, но не заменяет acceptance и
  dependency audit.
* Новое runtime-поведение, replacement capability или изменение clean-room
  contracts оформляется отдельной работой.

## Критерии готовности

* Владелец завершил последнюю живую приёмку и явно закрыл prototype line.
* Inventory однозначно классифицирует каждый удаляемый source, dependency,
  test, script, route и документ как prototype-only.
* Prototype entrypoint и принадлежащие ему packages/source удалены отдельным
  проверяемым commit без переноса реализации в clean-room.
* Корневые manifests, lockfile, typecheck и tests очищены от prototype-only
  owners.
* Обычные `dev`/`start`, release delivery/update и clean-room browser path
  проходят релевантные автоматические проверки.
* Владелец принимает живой clean-room Hamiltonian после удаления.
* Постоянная документация содержит только действующие contracts; временное
  prototype evidence удалено при закрытии задачи.

## Проверка результата

* Diff последнего pre-removal commit против removal и dependency-cleanup
  commits.
* Полный import/dependency/script/test/documentation audit по inventory.
* `bun run typecheck`, релевантные Hamiltonian tests и production builds.
* Живой запуск и browser acceptance через действующий development contour.
