# UI-006 — Обновлять содержимое маршрута и показывать имя пакета

## Коротко

Переключение раздела playground должно менять не только URL, но и фактическое
содержимое canvas. Заголовок каждой package-playground HTML-страницы должен
содержать только точное имя её пакета.

## Зачем

После перехода Node на общий pathname contract URL и DOM route меняются, но при
клике между `Редактор`, `Сокеты` и `Сравнение` на canvas остаётся прежняя
поверхность. Одновременно HTML titles используют разрозненные подписи
`playground`, `Component Library`, `Fixture` и продуктовые названия вместо
package identity.

## Связанные задачи и история

* Закрытая UI-005 result `8e83443ad` жёстко закрепила pathname в общей route
  declaration и доказала direct browser navigation. Она не проверяла
  client-side transition без reload.
* Node frame plan уже правильно выбирает одну из editor/socket/comparison
  surfaces. Ошибка возникает после выбора route: consumer вызывает
  `runtime.handleResize()`, который при неизменном canvas size возвращается до
  повторного layout.
* `UiRuntime.relayout()` является действующим API принудительного повторного
  применения surface layout без изменения viewport.
* Текущее owner-наблюдение добавляет два новых требования после закрытой UI-005:
  фактическая смена content и точное package name во всех package playground
  HTML titles. UI-005 не восстанавливается.

## Решения владельца

1. Client-side route transition обязан менять фактический canvas content.
2. Route-dependent surface frames повторно применяются через обычный retained
   layout API, а не через fake resize, reload или новый router.
3. HTML title каждого playground внутри `pkg/**/playground` равен точному
   `name` его package.json без слов `playground`, `Library`, `Fixture` и других
   добавок.
4. Точная карта: `@nodes/layout`, `@nodes/ui`, `@ui/components`,
   `@ui/elements`, `@ui/playground`, `@metafor/visual`.
5. Existing browser targets сохраняются; новые вкладки не создавать.

## Подзадачи

### UI-006.1 — Перекладывать Node surfaces при смене route

Статус и исполнитель: `IN_PROGRESS`, руководитель текущей задачи.

Требование: переход между Node route groups без reload повторно применяет
route-dependent frames и запрашивает render. Editor скрывается для Socket,
Socket скрывается для Comparison, reference/detail появляются только в своём
route.

Подтверждённая причина: `applyRoute` вызывает `runtime.handleResize()`, а
`UiRuntime.handleResize()` завершает работу при прежних width/height до
`#applyLayout()`. URL, router state и dataset обновляются, surface rects — нет.

Разрешённое изменение: Node playground route application и regression,
доказывающий route transition layout без resize. Router declaration, production
Node renderer и visual geometry не менять.

Проверка: focused Node layout/consumer tests; один existing target; фактические
frame/content diagnostics до и после client-side route transition; console 0.

### UI-006.2 — Оставить в HTML title только package name

Статус и исполнитель: `WAITING` до UI-006.1, руководитель текущей задачи.

Требование: generated и сохранённые static HTML titles всех package
playground-ов внутри `pkg` совпадают с package.json name. UI dev registry marker
для maintained selectors использует тот же exact title.

Разрешённое изменение: только HTML/server title declarations, registry markers
и exact tests. Видимые canvas headings, route labels и package semantics не
менять.

Проверка: repository inventory всех `pkg/**/playground` HTML/server titles,
focused package tests, UI dev tests и browser DOM title для maintained targets.

## Границы

* Не менять layout geometry и visual design Node/Components/Elements/Visual.
* Не использовать reload как исправление client-side route transition.
* Не создавать, закрывать или фокусировать browser targets.
* Solver-only `@nodes/layout` и `@metafor/visual` не запускать ради статического
  title change.
* Не трогать user-owned `hamiltonian/README.md`.

## Критерии готовности

1. Node route click меняет URL, route state и видимую surface без reload.
2. Route-dependent layout вызывается ровно как layout, а не как resize.
3. Все package playground HTML titles равны package names.
4. Existing maintained targets остаются singleton.
5. Focused tests/typechecks и browser evidence проходят.
