# MF-422 — Выделить layout package и перенести расчёт в Worker

## Зачем

Собственный TypeScript engine доказал placement и routing внутри `@ui/node`,
но вычислительная геометрия смешана с WebGPU surface. Hamiltonian также
вызывает полный расчёт на browser main thread. Нужна самостоятельная
transport-neutral граница, которую можно запускать в Worker без зависимости от
renderer и без изменения координат.

## Связь с дорожной картой

Задача продолжает принятый Hamiltonian graph contour. Она не меняет semantic
model Hamiltonian, hard laws раскладки, renderer или lifecycle transport.

## Решения владельца

* Создать отдельный workspace package `/pkg/layout` для собственной раскладки.
* `pkg/layout` занимается только placement, compound compaction,
  generated gateways и orthogonal routing. UI-модель, card/Flex, viewport,
  incremental editing, Inspector и WebGPU presentation ему не принадлежат.
* Main-thread adapter заранее измеряет и рассчитывает intrinsic card geometry.
  Worker получает ELK-like минимальный `LayoutGraph`: viewport/spacing, node
  sizes, port offsets и semantic edge endpoint IDs. Side/direction выводятся
  из роли edge и не передаются.
* Публичные geometry/Worker contracts вынести из вычислительного `src` в
  `pkg/layout/types` и экспортировать также через `@metafor/layout/types`.
* Добавить в `pkg/layout/README.md` пользовательское русское описание package,
  его договора, обычного и Worker-использования и границы с renderer.
* Полный placement/routing Hamiltonian выполнять в browser Web Worker.
* По алгоритму выбран производительный гибрид: layered median/barycenter
  ordering, bounded compaction по мотивам [Brandes–Köpf](https://boriskoepf.de/papers/gd01a.pdf)
  и sparse visibility A* из подхода [orthogonal connector routing](https://users.monash.edu/~mwybrow/papers/wybrow-gd-2009.pdf).
  Network-simplex оставлен только как ориентир layered-архитектуры, описанной
  [Gansner et al.](https://graphviz.org/documentation/TSE93.pdf).

## Границы

* Не возвращать ELK, Libavoid или другую layout-зависимость.
* Не менять hard laws, численные spacing/clearance и координаты доказанного
  синхронного ядра.
* Точное измерение загруженного renderer-шрифта и card plan остаются на main
  thread; Worker не получает document facts или text metrics.
* Main thread применяет готовый результат и анимирует переход, но не выполняет
  скрытый post-routing.
* Устаревший Worker result не может заменить более новую topology generation
  или другое responsive direction.
* Не менять существующий Hamiltonian lifecycle Dedicated Worker: layout Worker
  является отдельным browser-local вычислительным ресурсом и не изображается
  как domain/lifecycle node.

## Критерии готовности

* `@metafor/layout` является самостоятельным workspace package без зависимости
  от `@ui/node`, Hamiltonian или WebGPU Engine.
* `pkg/layout/types` содержит только serializable intrinsic graph,
  geometry-result и Worker contracts; `pkg/layout/src` — placement/routing и
  protocol implementation.
* Русский README и TypeDoc public contracts позволяют использовать package без
  чтения реализации и ясно отделяют измерение, расчёт geometry и отображение.
* `@ui/node` зависит от `@metafor/layout` и содержит только presentation-код.
* Unit tests layout перенесены к новому владельцу и доказывают прежние hard
  laws, determinism и stable input permutations.
* Worker возвращает тот же `LayoutResult`, что синхронная `layout(graph)`, для
  RIGHT и DOWN; `@ui/node` отдельно материализует `PositionedNodeSystem`.
* Hamiltonian full structural layout идёт через один долгоживущий Worker;
  telemetry-only refresh не запускает его.
* Конкурирующие запросы доказывают latest-generation-wins; ошибка Worker явно
  показана и не включает молчаливый расчёт на main thread.
* Focused tests, root typecheck и точная browser build проходят.
* Открытый Hamiltonian contour после auto-update показывает live graph в
  landscape и portrait без console errors.

## Проверка результата

Результат готов к закрывающей проверке:

* `bun run --cwd pkg/layout typecheck`, root `bun run typecheck` и
  `bun run docs:layout` проходят; TypeDoc собран в `tmp/typedoc/layout`.
* `bun test pkg/layout/src`: 8/8; `bun test pkg/ui/node`: 56/56.
* Полный `bun run test` проходит, включая 23/23 Hamiltonian host tests.
* Host отдаёт `/layout-worker.js` и `/orchestration.js` с `200`; Worker bundle
  не содержит `@ui/node`.
* Live target `9FF2861A38F2F3480A8A404565D9744C` после restart и двух
  auto-update показывает 11 нод/9 связей: `DOWN` при 728×1088 и `RIGHT` при
  1439×900, `hamiltonianLayoutEngine=typescript-worker`, Worker `ready`.
* Захват `/console` длиной 4 секунды во время auto-update/reload вернул
  `count=0`; status остался «11 нод · 9 связей · живой режим».
* Наблюдённый live interval Worker `busy → ready` для landscape graph — около
  607,5 мс. Это не доказывает превосходство над ELK и оставляет отдельное место
  для performance benchmark/optimization без изменения protocol boundary.
