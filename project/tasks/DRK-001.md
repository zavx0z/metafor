# DRK-001 — Закрыть утверждённые public dependencies Dark

## Цель

Довести до проверяемого результата два уже утверждённых
behavior-preserving среза: public Boundary RPC contract и public Create
MetaFor authoring facade. Не маскировать более крупную перестройку listener и
Bulk wiring под продолжение рефакторинга импортов.

## Связь с дорожной картой

Эта задача сохраняет текущий runtime baseline: один process/listener Dark,
отдельные Oracle и Force connections доменов и действующий browser ingress.
Целевой Hamiltonian и перенос listener принадлежат отдельной будущей линии и
не реализуются внутри `DRK-001`.

Состоянием задачи владеет `project/TODO.md`. Этапы 1 и 2 выполнены и приняты
одним общим result slice вместе с `MF-413`: новые Oracle consumers одновременно
несут утверждённые public Boundary/Create dependencies, поэтому искусственный
промежуточный коммит с прежним RPC-деревом не создавался.

## Подтверждённая исходная проблема

* Root TypeScript contour видит весь monorepo, поэтому относительный импорт сам
  по себе не доказывает корректную package boundary.
* Live Dark использовал Boundary RPC constants/types из implementation files.
* Четыре Dark Oracle modules использовали внутренние
  `create-metafor/src/**`.
* `dark/server.ts` сейчас напрямую импортирует Bulk browser/server wiring и
  assets, потому что после `MF-409` именно Dark держит единственный listener.
* Offline checkpoint/dissolve path имеет отдельные прямые Boundary
  dependencies и обратные Boundary/runtime → Dark dependencies.

Последние два пункта не исправляются объявлением случайного public facade.
Они требуют отдельного owner law о runtime topology.

## Явно отложено

### Dark → Bulk browser/server wiring

Прямые Bulk imports в `dark/server.ts` остаются подтверждённым долгом
текущего one-listener baseline. Они не заменяются:

* public composition facade Bulk;
* сборкой Bulk, которую Dark читает как implementation dependency;
* neutral composition root;
* переносом listener в Bulk;
* новым proxy между Bulk и Dark.

Целевое решение возможно только после закона и эксперимента Hamiltonian, когда
listener сможет перестать быть частью домена. До этого `dark/server.ts`
сохраняет текущее поведение.

### Root DSL bootstrap

Side-effect imports корневого package для установки `globalThis.MetaFor`
остаются отдельным optional improvement. Без owner-approved public entry эта
работа не начинается и не блокирует закрытие двух утверждённых срезов.

### Offline checkpoint и dissolve

Future owner и online/cold-recovery contract для Boundary copies, receipts и
обратных imports относятся к отдельному gate. Frozen allowlist не расширяется,
но и не должен быть молча объявлен исправленным.

### Scoped pause

Scoped Atom/Graph pause и crossing events принадлежат отдельной будущей задаче.
Global pause не меняется внутри этой задачи.

## Границы

* Не менять wire/RPC semantics, listener, routes, Force routing/history,
  domain Stores или browser lifecycle.
* Не добавлять shared/public API без отдельного owner decision.
* Не считать удобный импорт или read готовой междоменной границей.
* Не включать `MF-410`, Force v2, WebRTC или Hamiltonian experiment.
* Не читать и не изменять внешний Concept или архивный Production.

## Критерии готовности

* Boundary RPC contract и Create authoring facade имеют точного владельца,
  public entry, manifest и package guards.
* Live Dark не импортирует Boundary implementation или
  `create-metafor/src/**`.
* Frozen offline allowlist и Dark → Bulk wiring названы отложенными, а не
  завершёнными.
* Oracle, Force, listener и browser behavior сохраняют текущий baseline.
* Targeted checks, полный `bun run check`, `git diff --check` и отдельно
  согласованная runtime acceptance имеют фактические результаты.
* Задача не переходит в `REVIEW` без отдельного implementation commit.
