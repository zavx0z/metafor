# MF-410 — Добавить runtime Field input и наблюдение Process

## Зачем

Raw Force Particle не является предметным API: публичный Graph не раскрывает
внутренний Boundary Atom ID, нужный `dark.force.step`.

## Зависимости

* `MF-103` предоставляет history и Mass result reads.
* Типизированные Field declarations уже доступны через
  `meta.declaration.apply`.
* `MF-404` предоставляет авторинг Process тем же structural contract.

## Границы

* Добавить `meta.field.value.apply` с public Atom locator точного Graph
  snapshot, Field key, typed value и ожидаемой causal frontier.
* Разрешать locator во внутреннюю runtime identity только внутри provider и
  проводить одну Gluon либо Higgs через существующую Force-history.
* Добавить `meta.process.execution.read` с public execution identity, Process
  key, status, causal acceptance и доступными result/error data.
* Не раскрывать Boundary row IDs, `MassHandle`, filesystem path или живой
  Energy handle.
* Не добавлять `state.set` и `process.run`: State вычисляет Matrix, Process
  запускает Energy после Field input.
* Новая access policy, scope и конкурентность не входят.

## Критерии готовности

Один доверенный агент предметно меняет runtime Field, наблюдает вычисленный
State, ожидает точный исход Process и связывает success/error с history и Mass
result без прямого запуска Process.

## Результат

* Публичный `meta.field.value.apply` принимает Atom locator, Field key,
  типизированное значение и точную ожидаемую causal frontier. Boundary только
  планирует одну Gluon/Higgs Particle, а Dark условно принимает её в уже
  существующую append-only Force-history.
* Повтор со старой frontier отклоняется до записи новой Particle. Отдельный
  runtime operation journal, source projection и повторное чтение живого мира
  не добавлены.
* Публичный `meta.process.execution.read` соединяет канонический Boundary
  status/result с исходной `photon/test` acceptance и `w+/w- copy` settlement
  из той же Force-history. Наружу выходят только semantic Field keys,
  доступный error и public execution identity.
* Предметный интеграционный сценарий меняет Field, наблюдает вычисленный State
  и читает committed Process result. Отдельные тесты доказывают failed outcome
  и его `w- copy` settlement.
* Mass result остаётся существующим отдельным `energy.mass.result.read`; новый
  Mass store или execution journal не создан.
