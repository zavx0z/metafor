# HAM-001 — Удерживать одну декларацию нодовой системы каждого контура

## Коротко

Hamiltonian должен показывать одну согласованную текущую нодовую систему,
собранную из точных деклараций действующих контуров. Перезапуск
воплощения не оставляет старое поддерево, не смешивает две incarnation и не
превращает дочернюю ноду в корневую из-за потерянного owner.

## Зачем

Частные lifecycle-наблюдения содержат identity и owner, но без retained declaration новая
incarnation может сосуществовать со старой, а transport — сделать orphan видимым
раньше owner. Закон должен быть общим для контуров, а не набором веток по
видам нод.

## Связь с дорожной картой и владельцы

Задача относится к первому этапу Hamiltonian — управлению одной Вселенной на
одном устройстве в [`MF-425`](MF-425.md). Постоянный владелец закона — раздел
`Декларация нодовой системы каждого контура` в
[`hamiltonian/README.md`](../../hamiltonian/README.md). Runtime contract задаёт
`hamiltonian/core/lifecycle.js`.

`NodeSystemDocument`, UI и layout принадлежат `nodes`, `@nodes/ui` и `@nodes/layout`, но не
определяют Hamiltonian ownership. Hamiltonian передаёт им уже согласованные
`parentId`, roots и transport endpoints.

## Подтверждённая основа

* `MF-428.1` ввела ownership-closed browser/profile snapshot; `MF-428.2` доказала его
  replacement/retirement, но не определяла смену server host epoch.
* Исходный frozen regression доказал: после host replacement старый server subtree
  оставался, а RTC новой incarnation мог стать root до видимости owner.
* Принятый server/browser срез доказан offline и exact-target live. Родитель остаётся
  открытым для остальных independently authoritative contours.

## Целевой закон

* Каждый independently authoritative Hamiltonian contour публикует одну current declaration:
  stable logical contour identity, incarnation, exact root, monotonic revision/frontier, owned
  entity и transport.
* Каждая некорневая entity имеет полную owner-chain. Межконтурный transport
  появляется только через validated boundary identity между exact current endpoints.
* Registry атомарно заменяет incarnation одного logical contour и согласует ссылки
  других current declarations до публикации документа.
* Declaration удерживает structural membership до следующей принятой declaration.
  Exact source, продолжающийся в successor, не становится superseded.
* Snapshot/live events одной declaration сходятся независимо от стабильной
  перестановки; stale incarnation и non-monotonic revision не воскрешают retired subtree.
* Presentation не угадывает owner по виду ноды, URL, PID, порядку подключения и не
  поднимает orphan на корень.

## Закрытые подзадачи

### HAM-001.1 — Заменять серверное поддерево при новой incarnation Hamiltonian

Закрыта после independent review. Stable server key выводится из configured Hamiltonian
identity; replacement атомарно удаляет server A, stale boundaries и согласует WSS B.
Source revision зависит от фактически served browser artifacts, а не host epoch; structural page
lifecycle синхронно продвигает browser declaration. Frozen permutations, registry,
host/page integration и exact-target live restart доказали один server B, один browser RTC B,
WSS B и no reload при неизменном browser source.

Result commits: `086d1f663`, `3d3e9439b`, `b8beed697`, `293d3259e`, `c2878cd03`.

### HAM-001.2 — Показывать действующее WebRTC-соединение между браузером и сервером

Закрыта после independent review. Причина отсутствовавших линий: ownership-closed
declarations законно не копировали cross-contour DataChannel, а server boundary producer
проецировал только control WSS. Общий producer теперь принимает retained physical
Oracle/Force `opened/open` observation только между exact current RTC endpoints одной
session; close/replacement удаляет линии. Validator negative matrix, declaration permutations и
физический host integration защищают закон.

Result commit: `2e8a9949849d580b439ab06bec0dd51eb7e7450d`.

### HAM-001.3 — Установить, почему действующие WebRTC-линии не попадают в кадр

Диагностика закрыта после independent review. Current registry содержал оба RTC и две
DataChannel, но long-lived lifecycle projection теряла browser RTC до layout. При replacement
browser declaration она ошибочно помечала superseded весь прежний frontier, включая
page source, который точно продолжался в successor. Regression сравнил fresh successor с
stateful `A → B` и зафиксировал первую расходящуюся границу.

Diagnostic commit: `69eb8d8c7934f8d4f117e21211324124591e42b6`.

### HAM-001.4 — Сохранять ноды, которые продолжаются в новой декларации

Закрыта после independent review. Lifecycle projection не добавляет в superseded set exact
source key, который присутствует в successor frontier; отсутствующий source по-прежнему
retired, а stale live его не воскрешает. Acceptance regression доказывает равенство fresh
successor и stateful `A → B`. Exact-target live canvas показал browser/server RTC одной session
и две линии Oracle/Force.

Result commit: `ba5c7abf0335537b824276e5cb506acab9d80dcf`; live acceptance:
`e4e52604915b1c1a190675edbc3df43ab11e235a`.

## Границы

* Не превращать `NodeSystemDocument` в канонический runtime Store или историю.
* Не переносить Hamiltonian ownership в `nodes`, `@nodes/ui`, `@nodes/layout`, renderer или geometry.
* Не добавлять branches по видам нод и не скрывать invalid topology presentation-фильтрами.
* Не менять Dark, Boundary, Matrix, Energy, Bulk, authority или Force/Oracle protocols без
  отдельной задачи.
* Не считать screenshot или финальный document единственным доказательством:
  acceptance включает input contract, permutations, промежуточные documents и exact-target live.
