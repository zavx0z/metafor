# UI-013 — Восстанавливать UI playground после перезапуска Codex

## Коротко

`$ui-dev` сам распознаёт, что прежняя Codex-сессия потеряла long-lived PTY,
явно сообщает остановку exact selector и безопасно восстанавливает только
нужный package playground до browser evidence.

## История и новое наблюдение

* UI-003 создала registry-driven `$ui-dev` с exact package/PID/listener
  ownership и background-only CDP.
* UI-009 восстановила stale playground после package exports и закрепила
  restart/reload, sandbox и fresh-build evidence laws.
* Действующий `start/restart` намеренно ждёт Bun child в foreground PTY; EXIT/
  TERM cleanup завершает child и удаляет pid/start state. Это предотвращает
  orphan process внутри одной Codex-сессии.
* 2026-08-20 владелец перезапустил Codex. Все прежние PTY исчезли, а следующий
  Components status без подсказки владельца показал `ownership:none`,
  `status:stopped`, listeners `[]`. Skill не имел отдельного resume audit,
  recovery reason или атомарного `ensure`; агент вручную выбрал `start`.
* Первый exact canvas после восстановления был полностью чёрным и отклонён;
  explicit same-route `open` создал renderer activity, после чего повторный
  capture стал non-black. Это отдельный browser-evidence механизм.

Новизна относительно UI-009: package source/exports не менялись и stale
listener отсутствовал. Причина — завершение owning Codex PTY, а не старый Bun
resolver или failed `/entry.js` document.

## Решение и границы

Текущий parent сохраняет exact selector registry и PTY ownership. Он не добавляет
launchd, iTerm/AppleScript, daemon, глобальный service или автозапуск, пока
владелец отдельно не выберет настоящий внешний process owner. Поэтому сервер не
обещает жить, когда Codex выключен; skill обязан автоматически обнаружить и
восстановить его при следующем scoped использовании.

### UI-013.1 — Добавить session-resume audit и `ensure`

Статус и исполнитель: `COMPLETE`, внутренний исполнитель текущей задачи.

Требование: dispatcher принимает `ensure`. Для exact owned+healthy selector он
возвращает текущий structured status без нового PID. Для stopped/no-listener он
запускает exact contour и остаётся его long-lived foreground owner. Foreign
listener сохраняется и даёт typed refusal; owned unhealthy contour не
перезапускается разрушительно без явного `restart`.

Session cleanup записывает bounded last-exit marker. Следующий `status/ensure`
различает manual stop и потерю owning session настолько, насколько это
наблюдаемо из dispatcher, и возвращает recovery hint. Перед первой lifecycle/
browser операцией supervising task выполняет `ensure`, сообщает stopped/reused/
started outcome и хранит PTY. Короткоживущий source subagent не становится
владельцем live contour.

Разрешённое изменение: только
`pkg/ui/.agents/skills/ui-dev/{SKILL.md,references/playgrounds.md,scripts/ui-dev.sh,tests/**}`.
Registry selectors, ports, package servers, browser target semantics и product
runtime не меняются.

Regression: isolated free-port test завершает owning `ensure` process как при
потере Codex PTY, получает stopped + recovery hint, вторым `ensure` поднимает
новый exact PID, а running ensure не создаёт duplicate. Existing start/restart/
stop/foreign tests остаются зелёными. Skill проходит `quick_validate.py`,
shell/diff-check и current Components ensure reuse без PID change.

Подготовительный commit: этот project checkpoint, до skill patch.

Результат: commit `ed06fbc57` добавил `ensure`, atomic `last-exit.json`,
structured outcomes и recovery hint. Healthy exact selector возвращает
`reused` без нового PID; stopped/no-listener запускается как foreground
`started`; foreign и owned-unhealthy сохраняются без hidden kill/restart.
TERM/HUP owner loss получает `owner-session-lost`; explicit manual-stop/restart
marker не перезаписывается cleanup благодаря captured child processStart.

Regression и проверки: isolated lifecycle/registry `9/9` (`81` assertions)
моделирует потерю ensure wrapper, повторный recovery, running reuse, unhealthy и
foreign paths. `bash -n`, skill-creator `quick_validate.py` и diff-check зелёные.
На реальном Components contour `status → ensure → status` сохранил exact PID
`61841`, listener и processStart; ensure вернул `outcome:"reused"`, HTTP/
managed health `true`.

### UI-013.2 — Отклонять idle-black canvas evidence

Статус и исполнитель: `IN_PROGRESS`, внутренний исполнитель текущей задачи.

Требование: browser helper не записывает полностью чёрный WebGPU canvas как
успешное visual evidence. Он либо получает bounded renderer activity и один
повтор, либо возвращает typed `starting-or-idle-black` outcome; бесконечный
retry, focus/window operations и подмена DOM ready запрещены.

Это отдельный mechanism: UI-013.1 владеет process recovery, UI-013.2 — pixel
acceptance. Разрешённое изменение: `scripts/ui-browser.ts`, focused skill tests
и conditional browser reference; lifecycle dispatcher/registry/server source не
меняются. Preparation commit: этот state checkpoint, до browser-helper patch.

## Критерии готовности parent

1. После потери Codex PTY следующий skill invocation сам объясняет stopped
   selector и безопасно восстанавливает exact package contour.
2. Running/foreign/unhealthy states не приводят к duplicate или скрытому kill.
3. Browser evidence выполняется только после successful ensure и остаётся на
   одном background exact target.
4. Black canvas не становится принятым screenshot evidence.
5. External persistent owner остаётся отдельным явным owner decision.
