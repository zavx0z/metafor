# UI-002 — Создать общий пакет Playground для UI-каталогов

## Коротко

Создать `@ui/playground` — переиспользуемую dev-библиотеку для package-owned
playground. Она даёт routes, общий пятипанельный shell, catalog/sections/
preview/dock/info contracts и lifecycle, а конкретный package поставляет свои
демо, данные и surfaces.

## Зачем

Исторические playground `ui/elements` и `ui/components` независимо копировали
одинаковые router, backdrop, panels и layout. Node playground затем снова собрал
собственную перегруженную страницу. Владелец решил сохранить один узнаваемый
шаблон, но вынести его в отдельный UI package вместо копирования между пакетами.

## Решения владельца

1. Package path: `pkg/ui/playground`, public name: `@ui/playground`.
2. Playground — dev infrastructure выше Elements/Components, не часть их
   production component semantics.
3. Система layout называется FlexBox; CSS-style является формой описания.
4. Общими являются route/lifecycle/shell contracts и visual template. Demo
   content, component state и package-specific server routes принадлежат consumer.
5. UI-002 не изменяет `@ui/elements`, `@ui/components`, Node, Parameter, Field,
   Blender renderer или NODES-018 worktree.
6. Existing Components playground не мигрируется до интеграции NODES-018.
   Первый consumer — Node playground в NODES-019.

## Public boundary

* `PlaygroundRouter<Route>` — path/hash routing, subscription и disposal.
* `planPlaygroundShell()` — responsive FlexBox frames для catalog, section,
  preview, dock и info; mobile получает один consumer preview.
* Generic catalog/section/dock/info surfaces получают readonly descriptors и
  callbacks, но не знают Node/Field/Socket либо конкретный package.
* Shared theme задаёт historical backdrop, rounded glass panels, active/inactive
  navigation и spacing tokens.
* Server helper задаёт safe no-HMR dev defaults, но consumer владеет port,
  HTML entry и дополнительными assets.

## Границы

* Не менять current Components/Elements playground либо core package code.
* Не брать Node visual corrections и не перерабатывать Parameter/Field.
* Не создавать DOM/CSS renderer; shell остаётся WebGPU UI с CSS-style FlexBox
  description там, где оно нужно.
* Не превращать playground routes в product routing dependency.

## Критерии готовности

1. Package существует как отдельный workspace и не импортирует Node/Bulk/
   Hamiltonian/product code.
2. Router и shell layout deterministic, typed и покрыты unit tests.
3. Historical desktop geometry и responsive mobile preview доказаны.
4. Generic surfaces не содержат consumer vocabulary.
5. Fixture consumer собирается без HMR и показывает все пять shell regions.
6. NODES-019 может собрать Node playground только из public `@ui/playground`
   contracts и package-specific preview surfaces.
