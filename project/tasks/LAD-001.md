# LAD-001 — Восстановление SSO Лады

## Зачем

Сохранённое `authenticated=true` не доказывает, что Production принимает
сохранённую SSO-cookie после остановки или истечения сессии.

## Подтверждённые факты

* Текущая сохранённая cookie отвечает `401` на `/api/me` и Chat API.
* State `авторизована` теперь возвращается к телефонному пути при
  `authenticated=false` и в `ошибка` при фактической ошибке проверки.
* Отдельный Process состояния `авторизована` проверяет SSO сразу и затем раз в
  минуту; structural patch `lada-auth-session-monitor-process-v1` завершён тем
  же принятым событием Force `4025`, без второй операции.
* Auth находится в `ожидание телефона`, Chat — в `ожидание авторизации`; SMS ещё
  не запрашивалась.
* Телефон и SMS-код уже можно передать через `meta.field.value.apply`.

## Исправленная основа

* Dark применяет принятый Process patch прямо к живой декларации и не
  перечитывает мир для принятия решения.
* Matrix сохраняет различие между отсутствующим optional string (`null`) и
  существующей пустой строкой при структурной перестройке.
* Доказательство: `526d259dd`, профильные `37 pass`, полный `bun run check` —
  `2212 pass`, `0 fail`.

## Решение владельца

При фактическом запросе SMS Codex останавливается и просит код у владельца.

## Границы

* Пароль и отдельный обход Production SSO не добавляются.
* Новая access policy не проектируется.
* Cookie остаётся Mass, а не Field.

## Критерии готовности

* Холодный запуск проверяет сохранённую сессию до подключения Chat.
* `401` или `403` снимает ложный факт авторизации и возвращает телефонный путь.
* После ввода телефона и SMS-кода Auth снова получает подтверждённую сессию.
* Chat начинает подключение только после подтверждённой авторизации.
