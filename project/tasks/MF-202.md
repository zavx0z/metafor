# MF-202 — Реализовать атомарную запись source

## Зачем

Запись предложения не должна частично заменять исходник или молча перетирать
другую revision.

## Границы

* Точный целевой файл.
* Проверка ожидаемой revision.
* Временный файл и атомарное переименование.
* Повторное чтение записанного результата.

## Решение владельца

Source boundary публикует заранее подготовленные candidates того же
accepted patch. Он не читает live world и не строит новый diff.
Для `move` batch захватывает locks в каноническом порядке и откатывает
уже заменённые files при ошибке. Исполнитель: текущая задача Codex.

## Критерии готовности

Ошибка любой фазы сохраняет прежний source, а конкурирующее изменение
обнаруживается до замены.

## Проверка результата

Целевые tests доказывают отдельную preparation, атомарную publication,
read-back, idempotent repeat, batch preflight, cleanup и отказ при stale
revision и чужом lock. Общий TypeScript typecheck проходит.
