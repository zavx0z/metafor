# UI-001 — Создать playground универсальных UI Components

## Коротко

`@ui/components` получает собственный standalone playground, где universal
input components проверяются внутри своей библиотеки и вне Node Editor. Node
playground больше не владеет их каталогом и только импортирует готовые
components в composition examples.

## Зачем

Первый Node playground показывал standalone Fields рядом с Node/Socket сценой и
тем самым создавал ложную ответственность `@nodes/ui`. Владелец уточнил:
параметры ввода используются во всём UI, принадлежат `@ui/components` и должны
разрабатываться в её собственном playground.

## Связанные задачи и история

* Commit `7aab6269a` создал universal `Field`, но первое visual catalog место
  оказалось внутри `pkg/nodes/ui/playground`.
* NODES-017 доказала reuse тех же Fields внутри Node, однако side-by-side экран
  смешал component owners.
* NODES-019 параллельно очищает Node playground до Frame/Node/Socket/Link и
  Blender comparison. UI-001 принимает standalone input catalog целиком.
* Первичный audit текущего snapshot ошибочно не нашёл playground. Расширенный
  Git audit подтвердил готовые `ui/components/playground` и
  `ui/elements/playground`, созданные как shadcn-style component docs.
* Commit `0b3b0b2ca` (`chore: bound the runtime contour`, 15 июля 2026) удалил
  48 101 строку в 139 файлах: все UI playground, весь `ui/panes`, engine examples
  и другие материалы. Playground не был перенесён в `pkg/ui/**`, replacement не
  создан; отдельного project/owner решения удалить dev interfaces не найдено.
* Подтверждённая причина — слишком широкая cleanup boundary: reusable packages,
  runtime contour и dev tooling были удалены одним срезом как единое старое
  дерево. Git сохранил точный готовый интерфейс до удаления.

## Решения владельца

1. Universal inputs принадлежат `@ui/components`, не Node library.
2. Playground находится физически в `pkg/ui/components/playground` и импортирует
   production components только через owner package boundary.
3. Node library может использовать те же instances внутри Node, но не имеет
   отдельной реализации, копии или standalone catalog этих inputs.
4. UI layout называется FlexBox; CSS — способ декларативного описания shell.
5. Boolean example использует общий `Switcher` как основной presentation,
   включая Node composition.
6. Новый дизайн playground не создаётся. Восстанавливается исторический
   пятипанельный интерфейс `catalog → sections → preview + dock → parameters`
   с backdrop, rounded glass panels и route navigation; изменения ограничены
   адаптацией package paths/API и добавлением новых current components.

## Подзадачи

### UI-001.1 — Восстановить готовый historical Components playground

Взять последний готовый визуальный shell до `0b3b0b2ca`, восстановить его в
`pkg/ui/components/playground` и адаптировать к текущим `@ui/elements` /
`@ui/components`. Не восстанавливать удалённые product integrations и panes
только ради сборки: catalog показывает действующие current package exports.

### UI-001.2 — Добавить universal Fields в существующий catalog

Добавить `Field` как current component route внутри восстановленных catalog,
section, preview, dock и parameters panels. Text/number/slider/Switcher/enum/
color/vector/rotation/matrix/reference/read-only используют production Field,
не отдельный новый surface design.

### UI-001.3 — Восстановить owner-visible contour и проверки

Поднять historical-style playground, доказать routes/interaction/desktop/mobile
и package boundary. Отдельно зарегистрировать future восстановление Elements
playground, если оно не входит этот срез.

## Первый catalog

Отдельные sections показывают text, number input, number slider, boolean
Switcher, enum, color, vector, rotation, matrix, reference и read-only Field.
Каждый example имеет controlled state и видимый результат изменения. Catalog
не импортирует Node, Socket, Link или Blender renderer.

## Границы

* Менять `pkg/ui/components/playground/**`, package script/exports только если
  нужны для dev entrypoint, focused tests и project files.
* Не менять component semantics, engine retained hierarchy или Node renderer.
* Не копировать Field implementation в playground.
* Playground является dev-only и не входит production bundle.

## Критерии готовности

1. Standalone server `@ui/components` запускается отдельно от Node playground.
2. Все public Field kinds представлены через production `Field` import.
3. Boolean использует Switcher presentation; controlled callbacks обновляют
   тот же Field state.
4. Catalog полностью русский, разбит на понятные sections и использует FlexBox.
5. Browser DOM/console, desktop и mobile captures проходят без overflow.
6. Bundle не содержит Node/Socket/Link/Blender symbols.
7. Playground остаётся работающим и owner-visible для проверки.
