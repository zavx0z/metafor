# MF-418 — reload текущей версии Hamiltonian

## Зачем

После обновления Hamiltonian follower-вкладка может уже импортировать новую
версию, но сохранить в `sessionStorage` fingerprint прежнего main. При
последующем получении лидерства `reconcileMain()` ошибочно требует ещё один
reload; при нестабильном lifecycle это превращается в reload-цикл.

## Подтверждённые факты

* Window уже загрузил `v61`, а `hamiltonian-main-version` оставался на `v60`.
* `reconcileMain()` сравнивает persisted fingerprint с уже загруженным модулем
  даже при отсутствии main embodiment в текущем page realm.
* Реально работающий старый main уже отдельно обрабатывается в
  `activateVersion()` и требует page reload при смене fingerprint.

## Решение владельца

Исправить дефект сейчас.

## Границы

* Reload нужен только для замены активного main embodiment текущего page realm.
* Уже импортированный модуль follower-вкладки принимается при будущем рождении
  main без дополнительного reload.
* Не менять election, lease/fencing, Service Worker или version cache.

## Критерии готовности

* Pure contract различает активный старый main и вкладку без main.
* Регрессионный тест доказывает отсутствие reload для follower с прежним
  persisted fingerprint.
* При активном main переход на другой fingerprint по-прежнему требует reload.
* Точная обычная Chrome-вкладка стабилизируется на текущем fingerprint.

## Результат

* `reconcileMain()` больше не требует повторный reload по persisted fingerprint,
  если в текущем page realm нет активного main.
* `activateVersion()` по-прежнему требует reload при замене активного main и
  сразу сохраняет успешно импортированный fingerprint для follower-вкладки.
* Focused core test: `21 pass`, `0 fail`, `60 expect()`; отдельный regression
  contract проверяет active main, follower и неизвестный active fingerprint.
* Root typecheck и штатная browser build-команда прошли.
* На отдельном точном Chrome target `v62` восемь последовательных проб сохранили
  один `performance.timeOrigin`, fingerprint, main incarnation, `socket=connected`
  и пустой reload reason. Проверочное окно после приёмки закрыто.
