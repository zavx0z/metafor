# COS-003 — Закрепить правила документации Cosmos

## Коротко

Любой следующий Cosmos-механизм описывается одинаково: короткий проверяемый
закон в документе-владельце и подробная техническая механика во внутрикодовой
TSDoc public contract. Агенты получают это правило автоматически перед
Cosmos-работой.

## Зачем

Корневые правила уже разделяют owner docs и TSDoc, но в `cosmos/.agents` нет
локального workflow. Поэтому при обсуждении общего lifecycle browser/Bun агент
повторял детали в обычном тексте, терял уровень `env` и смешивал `server`,
`server-worker`, `Function()` и `Bun.spawn`.

## Связанные задачи и история

* Закрытая `COS-001` ввела общий `PackageExecutor`, но обсуждение показало, что
  одинаковую ответственность и разные platform implementations нужно всегда
  сначала выражать public interface.
* Закрытая `COS-002` добавила полный TSDoc environment contract и краткую
  таблицу в Cosmos owner document.
* TypeDoc generation/config/scripts были удалены ранее; действующая внутренняя
  документация живёт только в TSDoc рядом с кодом и читается из source/IDE.

## Решения владельца

* Ключевой механизм с одинаковой ответственностью и разной browser/Bun
  реализацией получает общий public interface и platform adapters.
* Документ-владелец кратко отвечает «что, зачем и кто отвечает» и ссылается на
  public source declaration с внутрикодовой TSDoc, не копируя механику.
* TSDoc рядом с public types подробно описывает методы, generics, lifecycle,
  invariants, platform implementations, fail-closed ошибки и связанные tests.
* TSDoc не генерируется и не публикуется как отдельный output или сайт.

## Подзадачи

### COS-003.1 — Создать локальный Cosmos documentation skill

Статус и исполнитель: `IN_PROGRESS`; руководитель текущей задачи.

Требование: создать discoverable skill внутри `cosmos/.agents/skills`,
зафиксировать owner-doc/in-code-TSDoc layering и common-interface law; добавить
обязательный routing из корневого `AGENTS.md` для Cosmos architecture, public
types и documentation work.

Среда и критерий приёмки: skill проходит `quick_validate.py`, root routing
указывает точный существующий path, инструкции не дублируют runtime lifecycle
`$metafor-dev` и `git diff --check` проходит.

Подготовительный commit: `a3fe97799`.

Фактические действия: создан discoverable skill
`cosmos/.agents/skills/cosmos-development/SKILL.md`. Он требует общий public
interface при одинаковой ответственности browser/Bun, сохраняет разные policy
в разных contracts и запрещает смешивать env, runtime technology, namespace и
process identity.

Skill разделяет краткий owner law и глубокий внутрикодовый TSDoc contract,
перечисляет обязательную механику public symbols и роль tests. Owner documents
ссылаются прямо на public source declaration с TSDoc.

Корневой `AGENTS.md` маршрутизирует любую Cosmos architecture/public-contract/
documentation работу в `$cosmos-development`; runtime/browser действия остаются
у отдельного `$metafor-dev`.

Проверки: Skill Creator `quick_validate.py` вернул `Skill is valid!`; routing
path существует, `git diff --check` прошёл. Runtime не изменялся.

Result checkpoint: `e3347ae67`.

### COS-003.2 — Закрепить TSDoc как внутрикодовую документацию

Статус и исполнитель: `COMPLETED`; руководитель текущей задачи.

Требование: удалить из Cosmos skill, root routing и project handoff все понятия
generated TypeDoc, будущего output/site и ссылок на него. Зафиксировать
единственный действующий механизм: подробная документация находится прямо в
TSDoc рядом с public code, а owner docs ссылаются на source declaration.

Основание и связанная история: review `COS-003.1` был остановлен новым решением
владельца до verdict. Repository-wide поиск подтвердил отсутствие TypeDoc
configs, scripts и root dependencies; активные упоминания генерации находятся
только в новом Cosmos skill/routing/task handoff.

Regression или опровергающее доказательство: после закрытия карточки
repository-owned instructions/docs вне immutable history и third-party
`node_modules` не содержат `TypeDoc`, generation promises, output/site paths
или будущих generated links; TSDoc/source/IDE law остаётся однозначным.

Среда и критерий приёмки: Skill Creator validation, repository-wide text audit
и `git diff --check`; runtime не изменяется.

Подготовительный commit: `449b71bf0`.

Фактические действия: root routing теперь называет только подробную
внутрикодовую TSDoc-механику. Cosmos skill определяет TSDoc как внутреннюю
source/IDE-документацию, запрещает отдельную генерацию, публикацию, output/site,
configs, scripts, dependencies и generated URLs. Owner docs всегда ссылаются
прямо на public source declaration.

Repository audit подтвердил: TypeDoc configs/scripts/root dependencies уже
отсутствовали; после correction вне temporary task card, immutable Git history
и third-party `node_modules` нет активных упоминаний TypeDoc или его генерации.

Проверки: Skill Creator `quick_validate.py` вернул `Skill is valid!`, exact
routing/source paths существуют, repository-wide text audit и
`git diff --check` прошли. Runtime не изменялся.

Result checkpoint: `62f1b774e`.

Review finding: owner-раздел package environments в `cosmos/README.md` не
ссылался на public declaration `cosmos/shared/package/environment.ts`, поэтому
цепочка `краткий law → внутрикодовая TSDoc` не была проходима. Correction
добавляет одну контекстную source link без копирования механики.

## Готовый результат для REVIEW

Следующие Cosmos-задачи автоматически получают локальное правило: общий
semantic interface для общей ответственности, краткая документация со ссылкой
на public contract, подробная внутрикодовая TSDoc-механика и tests как
доказательство. Skill не дублирует process/browser workflow и не создаёт
documentation generation/output.

Closing review должна проверить discoverability, отсутствие конфликта с
корневой documentation hierarchy и достаточность инструкций для следующей
artifact-store задачи.

Parent result commits: `e3347ae67`, `62f1b774e`.

## Границы

* Не изменять Cosmos runtime, public types или package versions.
* Не восстанавливать удалённую documentation generation toolchain.
* Не копировать общий project process или `$metafor-dev` lifecycle в новый skill.
* Не превращать один предложенный artifact interface в принятый product law.

## Критерии готовности

* Cosmos-specific skill автоматически применим к architecture/public-contract/
  documentation work.
* Краткий owner doc и глубокая внутрикодовая TSDoc имеют разные обязанности.
* Common responsibility / platform adapter rule сформулирован без привязки к
  одному ещё не принятому interface.
* Generated documentation output, site и будущие ссылки не предполагаются.
