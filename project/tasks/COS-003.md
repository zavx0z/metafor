# COS-003 — Закрепить правила документации Cosmos

## Коротко

Любой следующий Cosmos-механизм описывается одинаково: короткий проверяемый
закон в документе-владельце и подробная техническая механика в TSDoc/TypeDoc
public contract. Агенты получают это правило автоматически перед Cosmos-работой.

## Зачем

Корневые правила уже разделяют owner docs и TSDoc, но в `cosmos/.agents` нет
локального workflow. Поэтому при обсуждении общего lifecycle browser/Bun агент
повторял детали в обычном тексте, терял уровень `env` и смешивал `server`,
`server-worker`, `Function()` и `Bun.spawn`.

## Связанные задачи и история

* Закрытая `COS-001` ввела общий `PackageExecutor`, но обсуждение показало, что
  одинаковую ответственность и разные platform implementations нужно всегда
  сначала выражать public interface.
* Закрытая `COS-002` добавила полный TSDoc environment contract и краткую
  таблицу в Cosmos owner document.
* Действующая toolchain сохраняет TSDoc как source/IDE contract; отдельная
  TypeDoc generation сейчас отсутствует. Нельзя создавать ссылки на
  несуществующий generated site.

## Решения владельца

* Ключевой механизм с одинаковой ответственностью и разной browser/Bun
  реализацией получает общий public interface и platform adapters.
* Документ-владелец кратко отвечает «что, зачем и кто отвечает» и ссылается на
  TypeDoc public symbols, не копируя механику.
* TSDoc рядом с public types подробно описывает методы, generics, lifecycle,
  invariants, platform implementations, fail-closed ошибки и связанные tests.
* Пока generated TypeDoc отсутствует, документация ссылается на public source
  declaration с TSDoc и не притворяется, что TypeDoc URL существует.

## Подзадачи

### COS-003.1 — Создать локальный Cosmos documentation skill

Статус и исполнитель: `COMPLETED`; руководитель текущей задачи.

Требование: создать discoverable skill внутри `cosmos/.agents/skills`,
зафиксировать owner-doc/TypeDoc layering и common-interface law; добавить
обязательный routing из корневого `AGENTS.md` для Cosmos architecture, public
types и documentation work.

Среда и критерий приёмки: skill проходит `quick_validate.py`, root routing
указывает точный существующий path, инструкции не дублируют runtime lifecycle
`$metafor-dev` и `git diff --check` проходит.

Подготовительный commit: `a3fe97799`.

Фактические действия: создан discoverable skill
`cosmos/.agents/skills/cosmos-development/SKILL.md`. Он требует общий public
interface при одинаковой ответственности browser/Bun, сохраняет разные policy
в разных contracts и запрещает смешивать env, runtime technology, namespace и
process identity.

Skill разделяет краткий owner law и глубокий TSDoc/TypeDoc contract, перечисляет
обязательную механику public symbols и роль tests. Поскольку generated TypeDoc
сейчас отсутствует, закреплён fail-closed documentation path: ссылка на public
source declaration с TSDoc до появления реального stable symbol URL.

Корневой `AGENTS.md` маршрутизирует любую Cosmos architecture/public-contract/
documentation работу в `$cosmos-development`; runtime/browser действия остаются
у отдельного `$metafor-dev`.

Проверки: Skill Creator `quick_validate.py` вернул `Skill is valid!`; routing
path существует, `git diff --check` прошёл. Runtime не изменялся.

Result checkpoint: `e3347ae67`.

## Готовый результат для REVIEW

Следующие Cosmos-задачи автоматически получают локальное правило: общий
semantic interface для общей ответственности, краткая документация со ссылкой
на public contract, подробная TSDoc/TypeDoc-механика и tests как доказательство.
Skill не дублирует process/browser workflow и не заявляет отсутствующий TypeDoc
output как существующий.

Closing review должна проверить discoverability, отсутствие конфликта с
корневой documentation hierarchy и достаточность инструкций для следующей
artifact-store задачи.

Parent result commit: `e3347ae67`.

## Границы

* Не изменять Cosmos runtime, public types или package versions.
* Не восстанавливать удалённую TypeDoc toolchain в этой задаче.
* Не копировать общий project process или `$metafor-dev` lifecycle в новый skill.
* Не превращать один предложенный artifact interface в принятый product law.

## Критерии готовности

* Cosmos-specific skill автоматически применим к architecture/public-contract/
  documentation work.
* Краткий owner doc и глубокий TSDoc/TypeDoc имеют разные явные обязанности.
* Common responsibility / platform adapter rule сформулирован без привязки к
  одному ещё не принятому interface.
* Отсутствующий TypeDoc output не маскируется broken link.
