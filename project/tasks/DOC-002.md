# DOC-002 — Привести TSDoc Cosmos к единому Markdown-формату

## Коротко

Вся многострочная внутрикодовая документация Cosmos будет выглядеть одинаково:
между `/**` и `*/` останется чистый Markdown без декоративной звёздочки в
начале каждой строки.

## Зачем

Общий `$tsdoc` теперь задаёт starless-формат многострочных блоков и Markdown для
абзацев, списков, code spans, fenced examples, links и block tags. Cosmos уже
использует TSDoc как единственную глубокую source/IDE-документацию, но его
существующие многострочные блоки всё ещё оформлены прежними ведущими `*`.

## Связанные задачи и история

* Закрытая `COS-003` закрепила внутрикодовый TSDoc без generation/output и
  сохранила отдельный `$cosmos-development` для предметной специфики Cosmos.
* Закрытая `DOC-001` commit-ами `5ccc6f997`, `ccbc13cb0`, `e02bb03de` и
  `396358708` восстановила общие правила документации, current owner README,
  полезный public TSDoc и package artifact convergence.
* `DOC-001` закрыта commit-ом `1e1168bfe` и не восстанавливается. Текущая работа
  является новым repository-wide форматным инвариантом, поэтому получает
  отдельный связанный номер.

## Подтверждённые факты

* Lexical comments `oxc-parser` подтверждают в tracked source `cosmos/` вне
  `node_modules` и `dist` 167 TSDoc blocks в 49 файлах: 19 многострочных
  blocks в 15 файлах и 148 однострочных.
* Первичный regex-инвентарь ошибочно показал ещё два multiline ranges: строки
  glob-patterns `"cosmos/release/**/*"` и `"cosmos/startup/**/*"` внутри test
  source образовали ложные пары `/** ... */`. Форматный regression обязан
  использовать lexical comments, а не regex по произвольному source text.
* Однострочные `/** ... */` уже не имеют декоративного line prefix и не требуют
  изменения.
* Reference parser `@microsoft/tsdoc 0.16.0` принимает starless multiline
  comments и Markdown tags без parser messages.
* Development source maps содержат исходный TSDoc и меняются от форматной
  правки, хотя minified executable JS остаётся byte-identical. Map drift сам по
  себе не является package release и не требует новой version.

## Решения владельца

* Все многострочные TSDoc blocks в tracked Cosmos source приводятся к формату
  без декоративных `*`.
* Существующий текст, Markdown hierarchy, tags, links и code examples сохраняют
  смысл; задача не является переписыванием документации.
* Работа ведётся коммитами.
* Изменение только README, TSDoc comments или skill/documentation instructions
  не является изменением executable package code. Для такого diff не выполняются
  build, publication, version bump, materialization artifacts/maps,
  restart/clear-site-data, typecheck или runtime/test suites.
* Documentation-only diff проверяется только средствами самой документации:
  перечитыванием diff, Markdown/TSDoc parsing, links/anchors и
  `git diff --check`.
* Уже выполненный до correction переход versions `0.1.17/0.1.14/0.1.8` не
  откатывается; новое правило действует на следующие documentation-only changes.

## Подзадачи

### DOC-002.1 — Нормализовать многострочные TSDoc-блоки

Статус и исполнитель: `COMPLETED`; внутренний исполнитель текущей задачи.

Классификация: один repository-wide форматный механизм без изменения runtime
или public contract.

Требование: удалить только декоративный line prefix `*` из всех 19 реальных
многострочных TSDoc blocks в tracked `cosmos/` source, сохранить Markdown
структуру и добавить статическую защиту от возвращения прежнего формата.

Основание и связанная история: `$tsdoc` принят как автоматически применяемый
общий skill; `COS-003` и `DOC-001` уже определили содержание и владельцев TSDoc.

Наблюдаемое расхождение: current Cosmos source использует прежний Javadoc-style
line prefix, хотя новый общий формат требует starless Markdown body.

Причина: существующие blocks были написаны до изменения общего `$tsdoc` format
rule; текущие проверки не контролируют representation comment body.

Разрешённое изменение одного механизма: только formatting TSDoc comments и
static regression внутри Cosmos tests. Смысл текста, signatures и runtime code
не менять.

Regression или опровергающее доказательство: parser-backed audit всех tracked
Cosmos source files не находит decorative-star lines внутри multiline TSDoc и
не считает похожие ranges внутри strings; reference parser принимает каждый
преобразованный block.

Среда и критерий приёмки: `19 → 0` multiline blocks с decorative prefix, все
локальные TSDoc links разрешаются, Cosmos typecheck и relevant tests проходят,
`git diff --check` чист.

Подготовительные commits: `7850af57a`, parser-backed correction `2c6635dc1`.

Фактические действия: 19 реальных multiline TSDoc blocks в 15 tracked Cosmos
source files механически переведены в starless Markdown body. Все 148 one-line
blocks остались byte-identical; tags, links, lists и текст multiline blocks
совпадают с baseline после удаления только прежнего decorative prefix.

В `build-profiles.spec.ts` добавлен lexical regression: он получает tracked
TypeScript `.ts/.tsx/.mts/.cts` через Git, исключает `dist/node_modules`, читает
только реальные block comments `oxc-parser` и возвращает точные file/line для
decorative-star violations. Похожие ranges внутри strings не считаются
comments.

Проверки: lexical inventory `167 = 19 multiline + 148 one-line`, decorative
violations `0`; reference parser принял `19/19` с `messages=[]`; 13 local links
и anchors разрешаются; non-comment source 15 файлов byte-identical baseline.
Package typecheck startup/release/visual, tests typecheck, targeted regression и
`git diff --check` прошли. Полный build-profiles дал `13 pass`, `1 fail` только
на ожидаемом stale startup map SHA; convergence принадлежит `DOC-002.2`.

Result checkpoint: текущий `DOC-002.1` commit.

### DOC-002.2 — Свести форматированный TSDoc с package artifacts

Статус и исполнитель: `COMPLETED` до последующей owner correction;
руководитель текущей задачи.

Классификация: производная materialization уже изменённого source тем же

Требование: выпустить новые package-wide patch versions release, visual и
startup со всеми exact environments/maps и привести managed server/browser
contour к этим версиям.

Основание и связанная история: `DOC-001.4` доказала, что TSDoc изменяет
development source maps и требует atomic release/visual publication плюс
отдельную полную startup materialization.

Разрешённое изменение одного механизма: package versions, compatible startup
dependency и производные immutable artifacts/maps; runtime behavior и package
composition не менять.

Среда и критерий приёмки: source-to-artifact convergence всех environments,
canonical typecheck, полный Cosmos suite, managed exact release child и browser
caches новых версий, Inspector выключен.

Подготовительный commit: `a9b32a72a` после source checkpoint `e89e22ce5`.

Фактические действия: до owner correction штатно опубликованы release `0.1.17`,
visual `0.1.14` и startup `0.1.8` со всеми 16 exact JS/map artifacts. Managed
contour переведён на exact release `0.1.17`, а прежний browser target после
clean startup получил caches startup `0.1.8`, release `0.1.17`, visual

Проверки, успевшие завершиться до correction: exact convergence PASS,
canonical typecheck PASS, Cosmos suite `81 pass`, `0 fail`, doctor PASS;
Inspector выключен. После owner correction эти действия не являются правилом
для documentation-only changes и не повторяются.

Результат и вывод: уже созданные immutable versions не откатываются и не
удаляются. Следующий срез переносит новое docs-only исключение в постоянный
development owner и Cosmos skill.

Result checkpoint: текущий `DOC-002.2` commit.

### DOC-002.3 — Найти все ложные причины сборки документации

Статус и исполнитель: `COMPLETED`; внутренний диагностический исполнитель
текущей задачи.

Классификация: read-only диагностика нового owner requirement до изменения
rules или tests.

Требование или диагностический результат: найти все permanent instructions,
skills, project rules, build/publication code и tests, из которых агент может
вывести, что documentation-only TSDoc change требует package version,
artifacts, runtime lifecycle или test suites.

Основание и связанная история: `DOC-002.2` выполнила ненужную materialization,
потому что `DOC-001.4` и текущие source-map convergence laws трактовали любое
изменение source одинаково.

Наблюдаемое расхождение: owner отделяет documentation-only diff от executable
code change, а действующие формулировки и проверки этого различия не выражают.

Причина подтверждена: documentation owner не выделял docs-only diff;
development owner и Cosmos skill называли любое source/part change новой
version; startup convergence сравнивал и JS, и текущую map с exact artifacts;
server recovery до listener безусловно пересобирал и повторно materialize-ил
существующую map через общий immutable conflict check.

Разрешённое изменение одного механизма: только карточка с parser/search-backed
диагностическим выводом; source, tests, skills и runtime не менять.

Regression или опровергающее доказательство: точный список каждого активного
owner/rule/test с классификацией `изменить`, `сослаться` или `оставить`.

Среда и критерий приёмки: tracked repository-owned files вне immutable history
и third-party source; audit объясняет всю причинную цепочку
`docs diff → version/build/test/restart` без пропусков.

Подготовительный commit: текущий project-коммит регистрации owner correction.

Фактические действия: read-only audit классифицировал active owners и tests.
Изменить нужно documentation reference, Cosmos development reference и skill;
оставить без дублирования — root AGENTS, project process, docs map и owner
README. Исторические `DOC-001/COS-003` остаются только Git evidence.

Результат и вывод: отключать recovery rebuild нельзя — это потеряет fail-closed
защиту executable source. Recovery должна всегда сравнивать rebuilt JS с exact
JS, но существующую exact map сохранять без сравнения нового `sourcesContent`;
отсутствующую map восстанавливать. Обычная publication новой version продолжает
атомарно публиковать JS и map.

Result checkpoint: текущий diagnostic/project commit.

### DOC-002.4 — Закрепить documentation-only lifecycle у постоянных владельцев

Классификация: изменение постоянной documentation/development policy.

Требование: после audit записать один общий documentation-only law у
`$metafor-dev`, точное Cosmos artifact исключение у development owner и краткую
ссылку/специфику в `$cosmos-development`, не дублируя task process.

Разрешённое изменение одного механизма: только permanent Markdown/skill
instructions; executable source, manifests, artifacts и runtime не менять.

Среда и критерий приёмки: следующий агент однозначно выбирает только
doc-specific checks и не запускает build/version/runtime/test lifecycle.

Подготовительный commit: `e251f2571` после diagnostic checkpoint.

Фактические действия: общий documentation owner теперь классифицирует только
чистый README/docs/TSDoc-body/skill-instruction diff и прямо исключает mixed
executable changes. Для documentation-only разрешены только diff reread,
Markdown/TSDoc parse, links/anchors и `git diff --check`; build, publication,
versions, artifacts/maps, runtime lifecycle, typecheck и tests запрещены.

Cosmos development owner сузил SemVer law до executable part/canonical JS
bytes: TSDoc-only `sourcesContent` drift не release, existing exact map остаётся

это следствие и контекстно ссылается на общий classifier.

Проверки: contextual link/anchor разрешается, оба skills прошли structural

publication, versioning, artifacts/maps, restart/clear, typecheck, tests и
runtime/browser не запускались.

Result checkpoint: текущий `DOC-002.4` commit.

Статус и исполнитель: `COMPLETED`; внутренний исполнитель текущей задачи.

Фактические действия: startup convergence rebuild-ит `main/service/server` и

существовать и быть непустой, но её `sourcesContent` не сравнивается с текущим

Результат и вывод: executable drift остаётся fail-closed, documentation-only

### DOC-002.6 — Сохранить server recovery при TSDoc-only drift

Статус и исполнитель: `COMPLETED`; внутренний исполнитель текущей задачи.

Классификация: отдельное изменение recovery materialization policy и её
поведенческих regressions.

Требование: при cold recovery rebuilt JS всегда проходит immutable comparison;
существующая exact map сохраняется независимо от текущего documentation text,
а отсутствующая map восстанавливается. Обычная publication новой version и
общий `publishImmutableArtifact()` не ослабляются.

Основание и связанная история: current recovery вызывается до listener, всегда
выполняет build всех plans и materialize-ит JS/map pairs. После разрешённого
TSDoc-only diff map conflict блокирует запуск, хотя JS identity совпадает.

Regression или опровергающее доказательство: docs-only recovery fixture
успешно переиспользует exact JS/старую map; missing map восстанавливается;
существующий executable drift test продолжает давать immutable conflict.

Среда и критерий приёмки: targeted publication/recovery tests и полный Cosmos
suite проходят после code change. Эти проверки применимы, потому что срез
изменяет executable recovery policy, а не только документацию.

Подготовительный commit: `7d4d665bc` после permanent law `2a1e77e25`.

Фактические действия: recovery использует отдельную materialization policy.
Rebuilt JS всегда передаётся неизменённому `publishImmutableArtifact()` для
exact comparison; existing development map читается и сохраняется без
compare/replace; missing map публикуется из staged map. Ordinary new-version
publication и общий immutable helper не изменены.

Regressions: documentation-only fixture доказывает identical JS/different map
и отсутствие rewrite; missing-map fixture доказывает точное восстановление;
прежний executable source drift продолжает давать immutable conflict.

Проверки: publication/recovery `10 pass`, release/tests typecheck PASS,
canonical `bun run typecheck` PASS, combined full Cosmos suite `83 pass`,
`0 fail`, `git diff --check` PASS. Live runtime/browser/build publication не
затрагивались.

Result checkpoint: текущий combined `DOC-002.5/.6` commit.

## Границы

* Не менять смысл TSDoc, public API, runtime behavior или owner README.
* Не менять однострочные TSDoc blocks.
* Не редактировать `node_modules`, `dist`, generated output или third-party
  source.
* Не создавать TypeDoc generation/output.

## Критерии готовности

* Все tracked multiline TSDoc blocks Cosmos используют starless Markdown body.
* Static regression не допускает возврата decorative line prefix.
* Содержание comments и local links сохранено.
* Documentation-only lifecycle не требует package/materialization convergence;
  executable convergence остаётся отдельным защищённым законом.
* Независимая closing review подтверждает чисто форматную границу.

## Проверка результата

* Для documentation-only срезов: reread diff, TSDoc/Markdown parse,
  links/anchors и `git diff --check`; build/typecheck/tests/runtime lifecycle не
  запускать.
* Для `DOC-002.5/.6`, изменяющих test/recovery code: targeted regressions,
  canonical typecheck и полный Cosmos suite.
* Independent closing review всех постоянных owners и code contracts.
