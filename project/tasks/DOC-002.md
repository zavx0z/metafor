# DOC-002 — Привести TSDoc Cosmos к единому Markdown-формату

## Коротко

Вся многострочная внутрикодовая документация Cosmos будет выглядеть одинаково:
между `/**` и `*/` останется чистый Markdown без декоративной звёздочки в
начале каждой строки.

## Зачем

Общий `$tsdoc` теперь задаёт starless-формат многострочных блоков и Markdown для
абзацев, списков, code spans, fenced examples, links и block tags. Cosmos уже
использует TSDoc как единственную глубокую source/IDE-документацию, но его
существующие многострочные блоки всё ещё оформлены прежними ведущими `*`.

## Связанные задачи и история

* Закрытая `COS-003` закрепила внутрикодовый TSDoc без generation/output и
  сохранила отдельный `$cosmos-development` для предметной специфики Cosmos.
* Закрытая `DOC-001` commit-ами `5ccc6f997`, `ccbc13cb0`, `e02bb03de` и
  `396358708` восстановила общие правила документации, current owner README,
  полезный public TSDoc и package artifact convergence.
* `DOC-001` закрыта commit-ом `1e1168bfe` и не восстанавливается. Текущая работа
  является новым repository-wide форматным инвариантом, поэтому получает
  отдельный связанный номер.

## Подтверждённые факты

* Lexical comments `oxc-parser` подтверждают в tracked source `cosmos/` вне
  `node_modules` и `dist` 167 TSDoc blocks в 49 файлах: 19 многострочных
  blocks в 15 файлах и 148 однострочных.
* Первичный regex-инвентарь ошибочно показал ещё два multiline ranges: строки
  glob-patterns `"cosmos/release/**/*"` и `"cosmos/startup/**/*"` внутри test
  source образовали ложные пары `/** ... */`. Форматный regression обязан
  использовать lexical comments, а не regex по произвольному source text.
* Однострочные `/** ... */` уже не имеют декоративного line prefix и не требуют
  изменения.
* Reference parser `@microsoft/tsdoc 0.16.0` принимает starless multiline
  comments и Markdown tags без parser messages.
* Development source maps содержат исходный текст. Даже чисто форматная правка
  требует новых package-wide versions и exact artifacts/maps для release,
  visual и startup.

## Решения владельца

* Все многострочные TSDoc blocks в tracked Cosmos source приводятся к формату
  без декоративных `*`.
* Существующий текст, Markdown hierarchy, tags, links и code examples сохраняют
  смысл; задача не является переписыванием документации.
* Работа ведётся коммитами.

## Подзадачи

### DOC-002.1 — Нормализовать многострочные TSDoc-блоки

Статус и исполнитель: `COMPLETED`; внутренний исполнитель текущей задачи.

Классификация: один repository-wide форматный механизм без изменения runtime
или public contract.

Требование: удалить только декоративный line prefix `*` из всех 19 реальных
многострочных TSDoc blocks в tracked `cosmos/` source, сохранить Markdown
структуру и добавить статическую защиту от возвращения прежнего формата.

Основание и связанная история: `$tsdoc` принят как автоматически применяемый
общий skill; `COS-003` и `DOC-001` уже определили содержание и владельцев TSDoc.

Наблюдаемое расхождение: current Cosmos source использует прежний Javadoc-style
line prefix, хотя новый общий формат требует starless Markdown body.

Причина: существующие blocks были написаны до изменения общего `$tsdoc` format
rule; текущие проверки не контролируют representation comment body.

Разрешённое изменение одного механизма: только formatting TSDoc comments и
static regression внутри Cosmos tests. Смысл текста, signatures и runtime code
не менять.

Regression или опровергающее доказательство: parser-backed audit всех tracked
Cosmos source files не находит decorative-star lines внутри multiline TSDoc и
не считает похожие ranges внутри strings; reference parser принимает каждый
преобразованный block.

Среда и критерий приёмки: `19 → 0` multiline blocks с decorative prefix, все
локальные TSDoc links разрешаются, Cosmos typecheck и relevant tests проходят,
`git diff --check` чист.

Подготовительные commits: `7850af57a`, parser-backed correction `2c6635dc1`.

Фактические действия: 19 реальных multiline TSDoc blocks в 15 tracked Cosmos
source files механически переведены в starless Markdown body. Все 148 one-line
blocks остались byte-identical; tags, links, lists и текст multiline blocks
совпадают с baseline после удаления только прежнего decorative prefix.

В `build-profiles.spec.ts` добавлен lexical regression: он получает tracked
TypeScript `.ts/.tsx/.mts/.cts` через Git, исключает `dist/node_modules`, читает
только реальные block comments `oxc-parser` и возвращает точные file/line для
decorative-star violations. Похожие ranges внутри strings не считаются
comments.

Проверки: lexical inventory `167 = 19 multiline + 148 one-line`, decorative
violations `0`; reference parser принял `19/19` с `messages=[]`; 13 local links
и anchors разрешаются; non-comment source 15 файлов byte-identical baseline.
Package typecheck startup/release/visual, tests typecheck, targeted regression и
`git diff --check` прошли. Полный build-profiles дал `13 pass`, `1 fail` только
на ожидаемом stale startup map SHA; convergence принадлежит `DOC-002.2`.

Result checkpoint: текущий `DOC-002.1` commit.

### DOC-002.2 — Свести форматированный TSDoc с package artifacts

Статус и исполнитель: `IN_PROGRESS`; руководитель текущей задачи.

Классификация: производная materialization уже изменённого source тем же
доказанным publication-механизмом `DOC-001.4`.

Требование: выпустить новые package-wide patch versions release, visual и
startup со всеми exact environments/maps и привести managed server/browser
contour к этим версиям.

Основание и связанная история: `DOC-001.4` доказала, что TSDoc изменяет
development source maps и требует atomic release/visual publication плюс
отдельную полную startup materialization.

Разрешённое изменение одного механизма: package versions, compatible startup
dependency и производные immutable artifacts/maps; runtime behavior и package
composition не менять.

Среда и критерий приёмки: source-to-artifact convergence всех environments,
canonical typecheck, полный Cosmos suite, managed exact release child и browser
caches новых версий, Inspector выключен.

Подготовительный commit: текущий project-коммит начала после source checkpoint
`e89e22ce5`.

## Границы

* Не менять смысл TSDoc, public API, runtime behavior или owner README.
* Не менять однострочные TSDoc blocks.
* Не редактировать `node_modules`, `dist`, generated output или third-party
  source.
* Не создавать TypeDoc generation/output.

## Критерии готовности

* Все tracked multiline TSDoc blocks Cosmos используют starless Markdown body.
* Static regression не допускает возврата decorative line prefix.
* Содержание comments и local links сохранено.
* Package manifests и exact artifacts/maps сходятся с форматированным source.
* Независимая closing review подтверждает чисто форматную границу.
