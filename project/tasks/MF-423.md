# MF-423 — Собрать семейство пакетов nodes

## Зачем

После выделения layout engine node-system всё ещё разделён по историческим
путям `pkg/layout` и `pkg/ui/node`, а пакет UI содержит модель, validation,
layout adapters и renderer-компоненты одновременно. Это скрывает владельцев
логики и создаёт перевёрнутое имя `@ui/node`.

## Решения владельца

* Корневой пакет называется `nodes` и находится в `pkg/nodes`.
* Чистая раскладка находится в `pkg/nodes/layout` и экспортируется как
  `@nodes/layout`.
* UI-компоненты находятся в `pkg/nodes/ui` и экспортируются как `@nodes/ui`.
* `nodes` владеет node-system model, validation, containment, layout adapter и
  incremental logic; он импортирует измерение/компоненты из `@nodes/ui` и
  числовую геометрию из `@nodes/layout`.
* Все типы layout, включая внутренний integer routing/placement contract,
  находятся в `pkg/nodes/layout/types`, а не среди исполняемого кода `src`.

## Границы

* `@nodes/layout` не зависит от `nodes`, `@nodes/ui`, WebGPU, Hamiltonian или
  UI document.
* `@nodes/ui` не владеет domain/model validation или алгоритмом раскладки.
* Перенос не меняет координаты, hard laws или Worker protocol.
* Существующий dirty `project/README.md` не входит в задачу.

## Критерии готовности

* Workspace и lockfile содержат `nodes`, `@nodes/layout`, `@nodes/ui`; старые
  `@metafor/layout` и `@ui/node` отсутствуют.
* Hamiltonian импортирует каждый слой только через его публичный package export.
* `pkg/nodes/ui` содержит только UI/card/viewport/edge/inspector/surface code.
* Layout protocol, Worker и internal solver types находятся в
  `pkg/nodes/layout/types` и документированы по-русски.
* Focused tests, package/root typecheck, TypeDoc и browser build проходят.
