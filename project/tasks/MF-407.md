# MF-407 — Зафиксировать RPC-поверхность одного агента

## Зачем

Проект не должен уходить в конкурентность и права доступа, пока один агент не
может последовательно выполнить всю необходимую работу через RPC.

## Подтверждённые факты

Проверка public types, Monad providers и обычных тестов показала:

* агенту доступны `readGraph`, `meta.capabilities.read`,
  `meta.source.revision.read`, `meta.create`, `dark.force.pause/step/stack/resume`
  и `bulk.observer.captureViewport`;
* `meta.matter.apply` реализует только inert root-level WIMP и последнюю
  sibling position, хотя операции называются `add`, `move`, `remove`;
* `boundary.initialState.read`, `boundary.initialProjection.read`,
  `boundary.graph.current.read`, `dark.declarationProjection.read`,
  `energy.mass.fence/release` и checkpoint methods являются междоменными либо
  lifecycle providers, а не рабочими методами агента;
* полная Force-history и Mass key-files уже существуют у своих владельцев, но
  клиентских read providers нет;
* raw `dark.force.step` принимает внутренний Particle path, тогда как Graph не
  раскрывает Boundary Atom ID, поэтому он не является предметным Field API.

## Решение владельца

Текущий этап работает с одним доверенным агентом. Новые access policy,
capability scope, конкурентные чтения и writes, ветвление и самоизменение Лады
отложены до завершения всей необходимой функциональной RPC-поверхности.

## Предметный закон runtime

Отдельные RPC `state.set` и `process.run` не нужны и не должны появляться.
Агент меняет Field через `meta.field.value.apply`, Matrix вычисляет State,
Energy исполняет Process. Текущие значения и State читаются через `readGraph`,
причинный путь — через history, сохраняемый результат — через Mass result, а
точный status/error — через Process execution projection.

Enum Variant является частью декларации Field. Transition и Condition являются
частями декларации State. Поэтому для них не создаются отдельные методы.

## Границы

* Составить конечную таблицу действий агента и соответствующих public RPC.
* Для каждого действия отделить уже реализованный контракт от отсутствующего.
* Включить чтение мира, source revisions, history и Mass; Create и Matter;
  все authorable sections canonical Meta DSL; runtime Field input, текущий
  State, причинный запуск и результат Process; наблюдение результата и ошибок.
* Не включать GitHub push, автоматический commit, access policy, graph scope,
  конкурентность, ветвление и самоизменение.
* Разложить отсутствующие RPC на исполнимые задачи без параллельного общего
  write API и без специальных обходов для Лады.

## Критерии готовности

В дорожной карте и графе исполнения существует конечный проверяемый перечень
RPC одного агента; каждый отсутствующий метод имеет утверждённый планируемый
contract, пользовательский сценарий и отдельную исполнимую задачу с
зависимостями.
