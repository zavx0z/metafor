# MF-301 — Реализовать source patch создания peer Meta

## Зачем

`meta.create` должен создавать полный независимый Meta-пакет через существующий
template boundary, не вводя второй генератор, фиктивную live Particle или
отдельный operation journal.

## Границы

* RPC request проходит public validation, capability и точный address scope.
* Чистый template builder строит полный `empty` package в памяти.
* Source patch имеет precondition `target: absent` и публикуется атомарным
  переименованием sibling candidate directory.
* Candidate восстанавливается после частичного заполнения только при точном
  совпадении уже записанных файлов; конфликт не перезаписывается.
* Завершённый target с точными template files и ожидаемым пустым Git repository
  является durable evidence результата. Отдельный журнал Create не создаётся.
* `git init` входит в patch, но install, add, commit и push не выполняются.
* Receipt возвращает request digest, `meta.ts` revision, точный список файлов и
  проверенное состояние Git repository.

## Критерии готовности

Изолированные тесты доказывают нормальное создание, безопасный повтор,
восстановление частичного candidate, конфликт существующего target и отсутствие
Git commit/staging.
