# UI-011 — Перевести все package playgrounds на Workbench

## Коротко

Перевести `@nodes/ui`, `@ui/elements` и `@ui/components` с прежних ручных
route/info screens на принятый `@ui/playground` Workbench: package-owned
stories, конкретные sections, production preview, variants, TypeScript/copy и
controls/events.

## История и подтверждённое расхождение

* NODES-019 разделила перегруженный Node экран на старый пятипанельный catalog,
  но была закрыта до появления typed stories и правой code/copy panel.
* UI-007 создала shared Workbench contract и эталон `4192/overview`, но
  ошибочно была закрыта без миграции package consumers.
* UI-001.4 подготовила отдельный Components-owned перенос. По следующему прямому
  решению владельца её внутренний исполнитель остановлен до code patch, а
  execution/closing UI-001 переданы руководителю UI-011. Соседняя задача владеет
  только production Components и Node components.
* Owner screenshot `project/artifacts/UI-011/owner-node-socket-gap.png`
  показывает `4016/socket/types`: вторая панель содержит абстрактные
  `Типы / Формы / Состояния`, center — aggregate grid 19 Socket types, справа —
  статический `Socket contract`. Это не принятая Workbench structure.
* Current Node и Elements entries создают `PlaygroundInfoSurface` и вручную
  дублируют catalog/sections/dock routes; package-owned stories отсутствуют.

## Решения владельца

1. Все standalone UI playground используют один принятый Workbench composition:
   catalog слева, конкретные sections во второй панели, production preview в
   центре, variants снизу, постоянный TypeScript/copy и controls/events справа.
2. Shared shell/Engine/UiRuntime сохраняются. DOM/iframe/Storybook runtime,
   второй renderer и Blender dataset не добавляются.
3. Package consumer владеет story metadata и lazy implementation; shared
   package не получает Node/Socket/Field vocabulary.
4. В Node UI `Socket` является component. Во второй панели перечисляются
   конкретные Socket types: Boolean, Float, Integer, Vector, Rotation и все
   остальные реализованные типы, а не мета-разделы `Типы / Формы / Состояния`.
5. Для выбранного Socket center показывает один production preview. Dock хранит
   direction variants `input / output / bidirectional`; shape и interaction
   state меняются controls справа и обновляют тот же preview/source state.
6. Aggregate inventory допускается только как отдельная явная documentation
   story, но не заменяет detail story выбранного component.
7. Visible navigation/controls/docs — по-русски; API identifiers, routes,
   import specifiers и TypeScript остаются точными.

## Границы

* Playground changes ограничены `pkg/nodes/ui/playground/**`,
  `pkg/ui/components/playground/**` и `pkg/ui/elements/playground/**`.
* Не менять production `pkg/ui/components/*.ts`, `pkg/nodes/ui/*.ts`, package
  exports либо shared `pkg/ui/playground/**` без нового owner slice.
* Не менять production component semantics ради catalog presentation и не
  дублировать production implementations в stories.
* Не удалять Node Blender comparison, но оставить его package-owned reference,
  а не структуру всего catalog.
* Lifecycle/browser evidence выполнять только `$ui-dev`; один target на origin
  сохраняется.
* Не трогать unrelated Hamiltonian files и параллельные Node layout задачи.

## Критерии готовности

1. Node/Components/Elements entries не создают `PlaygroundInfoSurface` вместо
   code/copy.
2. Все три consumers используют typed story metadata и lazy production imports.
3. Node Socket second panel перечисляет все реализованные Socket types; выбор
   синхронно обновляет preview, dock variants, source и controls.
4. Components и Elements имеют ту же структуру без consumer vocabulary в
   shared package.
5. UI-001 execution/closing завершены этим руководителем без production patch.
6. Visible UI полностью русский; exact code/API/routes не переводятся.
7. Focused tests/typechecks и четыре live desktop contours проходят; screenshot
   не считается owner acceptance.
