# COS-002 — Однозначно описать среды выполнения пакетов

## Коротко

У каждой среды package появляется одно понятное значение: где выполняется её
artifact, к какой платформе он относится и каким build target собирается.
`server` больше нельзя спутать с `server-worker`, а неизвестная небраузерная
среда не становится Bun-средой автоматически.

## Зачем

Текущий общий `PackageEnvironment` перечисляет пять env, но отдельно выделяет
только browser-подмножество. Bun-подмножества нет, смысл каждого литерала рядом
с public type не описан, а package build выбирает `target=bun` как остаточную
ветку после проверки browser environments. Это уже привело к путанице между
Service Worker, Bun process и Bun Worker.

## Связь с дорожной картой

Задача уточняет действующее направление
[`Cosmos: общий package lifecycle`](../ROADMAP.md#cosmos-общий-package-lifecycle)
до server-загрузки `internal` и `metafor` packages.

## Связанные задачи и история

* Commit `befe0e7bf` ввёл полный список environments и browser-подмножество для
  browser Cache Storage и выбора build target.
* Commit `527121f51` переименовал прежний Hamiltonian owner в Cosmos без
  изменения классификации environments.
* Закрытая `COS-001` с кодовым commit `01f8d6755` закрепила общий lifecycle:
  `service` исполняет проверенный artifact через `Function()`, а `server` — в
  отдельном Bun process через `Bun.spawn`. Она не определяла Bun-подмножество и
  не описывала все env рядом с public type.

## Решения владельца

* Полный `PackageEnvironment` явно разделяется на browser и Bun subsets.
* Public module получает хорошее TSDoc-описание назначения контракта, мест его
  использования и смысла каждого env.
* `main` означает Window, `worker` — browser Worker, `service` — Service Worker,
  `server` — отдельный Bun process, `server-worker` — настоящий Bun Worker.
* Build target выбирается только по явной принадлежности browser либо Bun
  subset; остаточная ветка `не browser → bun` запрещена.

## Границы

* Не запускать `internal`, `metafor` или Quantum domains.
* Не менять общий execution lifecycle, process IPC или server ownership.
* Не переименовывать существующие env literals.
* Не добавлять новую build platform кроме browser и Bun.

## Критерии готовности

* Смысл каждого `PackageEnvironment` однозначен в public TSDoc и Cosmos owner
  document.
* Browser и Bun environments имеют отдельные readonly lists, types и guards.
* Build target определяется двумя явными subsets и fail-closed для любого
  неклассифицированного значения.
* Существующие package exports и release/browser behavior не изменены.

## Проверка результата

* Type-level и runtime tests обоих subsets и guards.
* Build-profile test всех пяти env.
