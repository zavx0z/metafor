# LAD-004 — Рабочая Лада: предметный E2E

## Зачем

Отдельные тесты компонентов не доказывают, что Лада действительно отвечает в
Production после полного холодного запуска.

## Границы

* Проверяется текущая общая комната Production и локальная Ollama на `ai-srv`.
* Посторонние сообщения и данные пользователей в артефакты не копируются.
* Новые права, конкурентные writes, самоизменение и Git push не входят.

## Критерии готовности

* Полный contour поднимается штатным сервисом и остаётся живым.
* SSO, Chat WebSocket и `qwen3.5:9b` подтверждены фактическими вызовами.
* Одно новое явное `@lada` получает ровно один осмысленный ответ Лады.
* Graph, Process outcome, Force-history, Mass/outbox и Bulk согласуются с этим
  же сообщением.
* Визуальная проверка подтверждает рабочие States Лады, а снимок Production
  подтверждает фактический ответ.

## Подтверждённая исходная точка

* Полный холодный старт сохраняет один причинный `sent` без дубля; Auth и Chat
  восстанавливаются, локальная Ollama и новый Send Tool проверены в LAD-003.
* Фактический ответ уже находится в общей комнате. В этой задаче остаются
  независимая Bulk/Graph визуальная сверка, снимок Production и итоговая
  проверка проекта.

## Результат и доказательства

* Штатный `metafor-inference-universe.service` после холодного запуска активен;
  SSO восстановлена, Chat находится в `ожидание события`, Send Tool — в
  `ожидание намерения`, Model — в `ожидание`, ошибок в Graph нет.
* Исходное обращение `63d3984a-f9f6-4119-bd37-085354ffcce6` связано с
  единственным ответом `6bae33f2-42d7-465e-8822-6aef98099efe`.
* `meta.process.execution.read` подтверждает `committed` выполнения Send
  `8f1ebb2c-be0f-46fa-bcab-607601c17d89`: acceptance `9614`, settlement `9622`,
  результат содержит тот же sent message key и пустую ошибку.
* `dark.force.history.read` вернул exact frontier `9658`. Bounded Mass-read на
  том же frontier показывает три сообщения, один обработанный inbox и ровно
  один outbox entry со статусом `sent` и теми же source/result keys.
* После холодного запуска Graph хранит `lastSentMessageKey`, но очищает
  `incomingMessage`, `replyDraft`, `replyToMessageKey` и `outgoingMessage`;
  повторной отправки нет.
* Снимок Production подтверждает фактический ответ, а чистый удалённый Bulk
  отображает живую топологию `lada`. Артефакты и ожидания описаны в
  [`artifacts/LAD-004`](../artifacts/LAD-004/README.md).
* Инструментированный диагностический кадр Bulk содержит 8 236 GPU-команд,
  1 565 draws, два render passes и ноль WebGPU validation errors. Чистая
  перезагрузка без Inspector дала ноль console errors.
* Предметная проверка Send Tool прошла `2 pass`, `11 expect`; TypeScript-проверки
  трёх изменённых Meta-пакетов прошли без ошибок. Полный `bun run check` прошёл
  `2217 pass`, `3 skip`, `0 fail`; три пропуска — отдельные Lada proof-тесты,
  исключённые из обычного общего запуска.

## Известное ограничение

Bulk доказывает текущую живую топологию, но подписи вложенных States на общем
масштабе не читаются. Их точные рабочие значения независимо подтверждены
Graph RPC. GPU timestamp-query на этом адаптере недоступен, поэтому GPU time из
диагностического capture не выводится.
