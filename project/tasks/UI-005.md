# UI-005 — Зафиксировать единые маршруты playground в декларации

## Коротко

Все standalone UI/Node playground должны открывать разделы одинаково:
обычным URL-путём вида `/editor/scene`, без отдельного `#`-режима у Node.
Правило принадлежит общей декларации маршрутов `@ui/playground`, поэтому
consumer не может случайно выбрать другое поведение.

## Зачем

Сейчас Elements и Components используют pathname, а Node — hash. Хотя все они
построены на одном `@ui/playground`, режим выбирается отдельно при создании
router и ещё раз в registry UI dev. Из-за этого общий shell допускает разные
URL и требует дублировать одно решение в consumer, browser helper и tests.

## Связанные задачи и история

* UI-002 создала общий `@ui/playground` router с поддержкой двух режимов:
  `path` и `hash`.
* NODES-019 отдельно записала требование active URL hash для Node playground.
  UI-004.14 выполнила его в result `9e87c9bac`, хотя Elements, Components и
  shared fixture уже использовали pathname.
* UI-004 закрыта result/closing commits `53f99d8ef` и `7b180c321`; она не
  восстанавливается. Действующие retained/public-shell результаты остаются
  основанием этой отдельной correction.
* Текущее наблюдение отличается от старого NODES-019: проблема не в выборе
  одного Node URL, а в том, что общий пакет позволяет consumers расходиться в
  самом поведении маршрутов.

## Решения владельца

1. Поведение маршрутов всех playground одинаковое.
2. Pathname фиксируется в общей декларации маршрутов, а не передаётся отдельно
   при создании router.
3. Node использует `/editor/scene`, `/socket/types` и
   `/comparison/blender`, без `/#/…`.
4. UI dev не хранит отдельный `hash/path` switch для selector. Его route target
   строится из той же единственной pathname-семантики.
5. Существующие browser targets не размножать: после исправления один Node
   target навигируется на pathname в том же target ID.

## Подзадачи

### UI-005.1 — Сделать pathname свойством общей декларации

Статус и исполнитель: `COMPLETE`, руководитель текущей задачи.

Требование: public `@ui/playground` предоставляет одну typed route declaration,
которая содержит route IDs, fallback и жёстко заданный pathname contract.
`PlaygroundRouter` принимает declaration целиком; consumer не передаёт mode или
prefix отдельно.

Расхождение: Node создаёт router без options и получает default `hash`, а
Elements/Components/fixture явно передают `{mode: "path"}`. UI dev registry
повторяет это различие полем `routes.mode`.

Причина: первоначальный router оставил mode consumer-level option, после чего
локальный критерий NODES-019 закрепил Node как исключение.

Разрешённое изменение одного механизма: общий route declaration/router,
декларации четырёх maintained playgrounds и соответствующее pathname чтение UI
dev registry/helper. Visual surfaces, demo data, retained hierarchy и server
lifecycle не менять.

Защита: compile-time declaration tests, router tests, package boundary,
consumer tests, UI dev static/lifecycle tests и typechecks. Exact browser proof
использует существующий Node target и не создаёт новую вкладку.

Среда и критерий приёмки: canonical `main`; все selectors публикуют pathname
routes, Node route работает как `/editor/scene`, existing target ID сохранён,
console чиста. Остановленные processes не запускать до отдельного browser
proof; lifecycle выполняется только UI dev.

Результат: public `definePlaygroundRoutes` принимает только route IDs и
fallback, возвращая immutable declaration с единственным
`location: "pathname"`. `PlaygroundRouter` принимает declaration целиком;
consumer options, hash listener, prefix и неиспользуемый второй `VirtualRouter`
удалены. Node, Components, Elements и fixture объявляют exact routes через этот
API. UI dev registry хранит только default route, а target helper отклоняет
`#`, `?`, пустые и ненормализованные paths.

Проверки: affected UI/Node suite `141/141`, `2246` assertions; UI dev `7/7`,
`59` assertions; typechecks `@ui/playground`, Components playground, Elements
playground, Node playground и root — pass; `git diff --check` — pass.

Browser evidence через UI dev: остановленный Node contour поднят в long-lived
session `13172`, PID `8742`, ownership `skill`, port `4016`. Единственный
существующий target `809BF08D88E4582CA819EFE847FE1450` без создания новой
вкладки прошёл `/editor/scene → /socket/types → /editor/scene`; URL и DOM route
совпали, ready marker `ready`, console `0`, native metrics `1920×1088 @2`,
hidden/unfocused. Target оставлен на `/editor/scene`, process running.

Result checkpoint: `8e83443ad0c1c25ce4e1c45f632d6766b0c7b587`.
