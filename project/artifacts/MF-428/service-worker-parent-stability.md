# MF-428 — стабильный browser parent при смене исполнения

Дата наблюдения: 2026-08-11.

Исходное визуальное наблюдение владельца: нода `Service Worker` временами
выходила из compound-ноды `Chrome` после штатной остановки и нового запуска её
внутреннего исполнения.

Причина: entity-наблюдения host и page назначали одной и той же сущности
`ownerId`, равный её собственному `service-worker:*`. Более позднее наблюдение
перезаписывало browser owner в причинной проекции, поэтому layout закономерно
материализовал ноду как root. Следующее наблюдение самого Worker снова
назначало `browser:*`, и нода возвращалась.

После исправления один HTTPS-host наблюдал три штатные замены исполнения и WSS:

| UTC | WSS connection | runtime incarnation | worker identity | device identity |
| --- | --- | --- | --- | --- |
| 04:53:31 | `e2a69d95…` | `9a08b345…` | `72452957…` | `7ad107c3…` |
| 04:54:01 | `341bfb99…` | `7893cf2a…` | `72452957…` | `7ad107c3…` |
| 04:54:31 | `8d573555…` | `4cf15fa9…` | `72452957…` | `7ad107c3…` |
| 04:55:01 | закрыт | остановлено | `72452957…` | `7ad107c3…` |
| 04:55:11 | `eb50e417…` | `04cbbae6…` | `72452957…` | `7ad107c3…` |

Во всех host/Page/Worker entity-наблюдениях Service Worker теперь используется
один owner `browser:7ad107c3…`. Регрессионная проекция проводит ноду через
`active → standby → новое browser-managed исполнение` и после каждого события
требует `parentId = browser:device-a`. Интеграционный host-тест отдельно
проверяет browser owner реально разосланного Web Push status-наблюдения.

Независимое ревью дополнительно обнаружило две граничные причины неверного
состояния. Page-retirement прежнего Worker уже называл владельцем Chrome, а его
SW/host validators всё ещё ожидали прежний self-owner; теперь весь путь требует
один browser owner. Кроме того, отвергнутый socket с неверным `wakeProof` мог
при закрытии публиковать `standby` с подставленным device из URL. Теперь rejected
socket не меняет availability, pending wake не перезаписывается закрытием
старого socket, а зарегистрированный worker/device mapping остаётся
каноническим источником browser owner. Host-регрессия проверяет, что после
forged device и proof retained-состояние той же ноды остаётся `waking/sent`.

Автоматический снимок обычного Chrome не получен: локальный Chrome REST service
вернул macOS Automation error `-1743`. Поэтому этот файл доказывает runtime
переходы и причинный parent contract, но не подменяет визуальное наблюдение
владельца в уже открытом окне.

Чувствительные сведения не сохранены: bearer token, VAPID private key,
PushSubscription endpoint и wake proof отсутствуют. Приведённые identity —
сокращённые случайные локальные идентификаторы стенда.
