# Передача MetaFor: самостоятельная разработка из чатов

Снимок на 15 октября 2026, подготовленный по запросу Владимира. Это передача
конкретной задачи, а не новый источник архитектурных законов или обязательный
процесс управления проектом. Действующие контракты перечислены в
[карте документации](../../../docs/README.md). Начальный запрос следующему
исполнителю находится в [START.md](START.md).

## Цель и главный вывод

Владимир должен продолжать разработку MetaFor из её веб-интерфейса, сохраняя
агентов, беседы, инструменты, результаты и право управлять изменениями при
недоступности платного Codex. Основа должна работать на Mac и одной GPU ai-srv;
бесплатные веб-провайдеры и Codespace подключаются по доступности.

**Рабочая беседа ещё не означает работающего разработчика.** Новые Cosmos-чаты
сохраняют сессии и общаются через ACP, но им пока не назначен Environment для
чтения исходников, правок и проверок. В Storybook этот механизм уже существует.
Нужно подключить его с правильными полномочиями к Cosmos Session, сохранив
Oracle/Force как путь канонических изменений. Второй самодельный агентский
цикл, парсер команд или новый обязательный MCP для этого не нужны.

Рекомендуемый порядок: стабильная беседа → независимый локальный исполнитель →
назначенные инструменты → один подтверждённый цикл разработки → удобное
восстановление → расширение пространственного интерфейса. Это приоритизация
оставшейся работы; новые пункты ниже не объявлены реализованными.

## Что решено пользователем

1. Максимально использовать существующий UX/UI Storybook и Immersive, делать
   компоненты общими. Сохранять стекло, прозрачные подложки и blur. Не создавать
   независимые Canvas/Document для панелей.
2. Главный дисплей каждого Atom — его сведения и управление; чат агента —
   отдельное представление. Выбор ограничен агентами текущего Atom. Сессии
   создаются, выбираются и редактируются как в Storybook; разные новые сессии
   могут иметь разные подключения, закреплённая native-сессия сохраняет identity.
3. Позднее прямое указание: **новые беседы хранятся в Cosmos отдельно от Mass и
   Quantum**. Ранние договорённости о всех чатах в Mass этим уточнены. Legacy
   Quantum Agent/Chat и его Mass не удалять и не смешивать с новым хранилищем.
4. Инфраструктура и восстановление работают конечными автоматами без генерации
   ИИ. Наличие аватара в комнате не запускает модель. ИИ подключается к задаче
   явно. В комнате должен быть хотя бы один представитель; тяжёлое содержимое
   монтируется для посещаемой комнаты.
5. Все обычные действия, авторизация, настройки и диагностика доступны из
   MetaFor. Отдельные viewer URL не являются основным пользовательским путём.
   Диагностика MetaFor — через её Oracle API, без прямого CDP этого приложения.
6. Последнее распределение: Qwen — ai-srv, DeepSeek — Chrome Studio на Mac,
   ChatGPT — Codespace. ChatGPT на ai-srv не устанавливать. Для ai-srv выбран
   отдельный браузерный провайдер на контейнер. Старое пожелание одного общего
   браузера не отменяет это более позднее размещение.
7. Агенты смотрят в центр; над головой — чат, повёрнутый к камере. Имя и пол
   редактируются, начальный вариант сохраняется. Агенты и их дисплеи должны
   помещаться до потолка и учитывать соседей.
8. Общая комната Atom, личные и групповые беседы, включая агент–агент. Чаты —
   отдельные ноды с сокетами; одна связь имеет дуплексное поведение, сообщение
   показывает частицу. Связь с комнатой подключает её участников. Общие чаты
   находятся над сущностями в Cosmos. Это не всё реализовано.
9. В центре комнаты нужен уменьшенный граф текущего subtree; переход через
   контекстное меню. В HUD — добавление агента/группы/чата и понятный возврат.
10. Поля Atom редактируются нодой параметров: черновик нескольких изменений,
    одна кнопка сохранения и одна транзакция. Сокеты пока видимы без соединений.
    Поля развёртывания должны позволить управлять хостом, профилем и запуском;
    наличие редактора само по себе не реализует установщик.

## Самый короткий путь к разработке системы самой на себе

Уже существуют:

- [Cosmos Session composition](../../../cosmos/release/server/conversations.ts):
  готовый Store и ACP transport, но `createSessions` без `environment`.
- [Публичный Session Environment](../../../../storybook/chat/session/contract/environment.ts):
  bootstrap content, execute, dispose; host-assigned executor/session/address,
  authorize и карточки выполнения.
- [Цикл готовой Session](../../../../storybook/chat/session/index.ts): строгое
  целое JSON-сообщение `{name, arguments}`, решение до эффекта и результат той же
  модели. Пример wiring — [Storybook chat server](../../../../storybook/app/server/src/chat.ts).
- Legacy [Quantum Agent](../../../standard/agent/actions.ts) и
  [REPL Tool Atom](../../../standard/repl/run.ts): ранее живой browser → Oracle →
  `bun.evaluate` → ответ был проверен. Это другая история/сессия, не доказательство
  инструментов новых Cosmos-чатов.

Важные ограничения реализации:

1. `mcpServers:[]` у Cosmos само по себе не доказывает отсутствия remote tools:
   Provider peer применяет свой доверенный executor config. Но browser adapter
   выдаёт текст; локальный development executor через Environment ему не подключён.
2. `subject.cwd` Cosmos сейчас указывает на хранилище беседы. Его нельзя выдать
   модели как checkout исходников. Root workspace выбирается host assignment.
3. Текущий Oracle Process scope — `full-root`; Atom subtree scope пока не считать
   реализованным. Oracle authoring registry по точным Meta address не заменяет
   обычный toolbox чтения TS, patch и тестов.
4. Native Bun REPL имеет возможности ОС. `cwd` сам по себе не ограничивает
   файловый доступ. Нужное назначение возможностей определяется владельцем.
5. Общий Project Environment Storybook не распространять на MetaFor автоматически:
   текущие правила Project прямо говорят, что MetaFor не входит в его состав.
6. В текущем Cosmos поддержан `ask`; предавторизованный автономный режим и общий
   бюджет model/tool steps нужно отдельно довести. Не начинать бесконечный loop.
7. Для Ollama недостаточно добавить строку в настройки: текущие guard условия
   `nativeConnect` и `resolveConfiguredProvider` не дают общего допустимого пути.
   Нужно одно доверенное назначение транспорта с проверками identity. Для
   ai-srv рекомендуется использовать существующий Ollama ACP executor через
   peer, сохранив legacy локальный driver; это ещё работа в contracts/code/tests.

Первый зачётный сценарий: в одном Cosmos-чате модель получает точные scope,
revision, правила и catalog; читает один исходник, исправляет небольшой известный
дефект через согласованный patch, запускает одну выданную проверку и показывает
Владимиру реальный diff и receipt с exit code. Нельзя зачесть просто ответ
«исправлено», код в Markdown или зелёный unit test транспорта.

## Приоритетная очередь

Выполнять по одному узкому законченному срезу. Работа с доступом ChatGPT может
идти отдельно, но не блокирует Ollama и host-owned Environment.
Основная последовательность для независимости от платных лимитов: **T2 → T3 →
T4 → T5**. T1 восстанавливает уже авторизованный веб-путь; если он готов раньше,
первую приёмку T3 можно провести на нём. T6 не является зависимостью этой цепочки.

| ID | Приоритет и владелец | Следующий конкретный результат | Проверка готовности |
|---|---|---|---|
| T1 | P0 — Provider/Chrome Studio consumer | Восстановить DeepSeek на уже авторизованном профиле: точный target, существующий диалог, видимый composer; отдельно sender preview | Две последовательные реплики, повторное открытие той же сессии, история и native identity сохранены, неизвестный исход не повторён |
| T2 | P0 — Provider/Cosmos | Подключить существующий Ollama ACP executor на ai-srv через доверенный peer; один небольшой установленный model | Выбор в текущем UI, реальный ответ, streaming/cancel/resume; ноль изменений browser profiles, одна загруженная GPU-модель |
| T3 | P0 — Cosmos + публичный Session Environment | Выдать назначенную среду одной сессии: один source package, read/list/diff, hash-checked patch, одна проверка | Реальные tool cards и полный первый цикл разработки; чужой path, stale revision и отменённое разрешение дают ноль эффекта |
| T4 | P0 — владельцы Session/Environment | Лимит model/tool шагов, дедупликация эффектов, явный failed/unknown/retry, управляемая pending очередь | Разрыв до отправки, после принятия и во время tool: ни дублирования prompt/patch, ни вечного скрытого ожидания; закрытие viewer не отменяет модель |
| T5 | P1 — Cosmos/Provider UI | Рабочий операторский путь: создать агент → session/provider → вход → сообщение → инструменты → stop/recover | Только UI MetaFor, без ручного HTTP/Bun оператором; видимые состояния service/login/model/stream/capture различаются |
| T6 | P1 — MetaFor host assignment + Capsule | Подключить ChatGPT к новому доступному Codespace `bots-work`, сохранив работающий VPN | Отдельно health, ACP, ICE/video/control, ручной Cloudflare/login в MetaFor, ответ и resume; порт управления браузером не публикуется открыто |
| T7 | P1 — владельцы Meta/Field/deploy | Параметры хоста/профиля/артефакта/запуска, явный start/stop/status, наблюдаемые этапы и отказ | Одна новая установка из разрешённых полей; repeated request не создаёт второй ресурс; сохранённый профиль проверенно восстанавливается |
| T8 | P1 — BrowserPreview/публичные native media APIs | Fullscreen keyboard, звук и микрофон во встроенном просмотре | Набор текста с фокусом обычный/fullscreen, звук в обе стороны по явному включению, stop освобождает tracks; Mac microphone пока null |
| T9 | P1 — Visual diagnostics/performance | Измерить первый вход/переход/простой, скрытие Display, lazy history/media, сохранность черновика | Один видимый 10-минутный пользовательский сценарий без frame-suspension и перезапуска; idle без `/agents`/history polling; реальные числа без выдуманного GPU timing |
| T10 | P2 — Cosmos/Immersive consumer | Общие/личные/групповые chat nodes, сокеты, один duplex edge, частица сообщения, участники комнаты | Нет duplicate delivery/циклов; membership и история однозначны; UI редактирует ту же модель |
| T11 | P2 — Visual/публичные graph и avatar APIs | Центральный subtree-граф, перейти/пролёт, масштаб до потолка, ориентация и skinning integration | Проверено на разных размерах комнат и числе участников, без текста за дисплеями; native draw-call evidence при доступном API |
| T12 | P2 — назначенный host исполнения | Новые peers/галактики, Android/PWA, расширенные автономные роли | После приёмки T1–T9; не расширять ночной критический путь |

### Предлагаемый минимальный порог стабильности

Один text provider и Ollama проходят в одном UI: создание/выбор сессии, две
реплики, rename, stop, восстановление после разрыва socket и перезапуска
принадлежащего ACP, сохранение черновика при room/fullscreen/back, один tool
цикл с реальным diff/test. Один сценарий подключения провайдера и одна негативная
проверка прав обязательны. Рутинные повторные полные suites не нужны.

`hf.co/unsloth/Qwen3.8-27B-GGUF:UD-IQ3_XXS` (~11.87 GB),
`qwen3.8:27b-q4_K_M` (~17.74 GB), а также более крупные модели.
Качество и скорость на задачах MetaFor в этом аудите не измерялись.

Рекомендация, не выполненная настройка:

- Начать с установленной 9B-модели, одной очереди и одного активного writer.
  Context сначала ограничить, например 8K, и изменить только по измерению.
  Сравнить 9B и 27B IQ3 на трёх одинаковых маленьких задачах, прежде чем выбрать.
- 27B Q4 больше VRAM уже по весам; не обещать работу целиком на GPU. RAM/offload
  возможны только после отдельной оценки задержки, а не как бесплатный быстрый режим.
- Агенты и комнаты могут быть многочисленными логически; это не повод держать
  отдельную модель и browser session для каждого аватара.
- Веб-модели — дополнительный канал для сложного анализа/проверки в пределах
  доступной квоты. Quota/auth/Cloudflare — явные состояния, а не бесконечный retry.
  Смена провайдера происходит в новой явно выбранной сессии, без скрытого переноса
  незавершённого запроса.
- Передавать задачу, точную ревизию, несколько нужных файлов и компактный
  checkpoint, а не этот многодневный чат в каждый turn. Инструменты читать по запросу.
- Первичный bootstrap: маленький Task → Plan → Patch → Check → Review. Начальный
  предлагаемый бюджет — 8 model steps и одна короткая проверка; увеличение явное.
- Health/reconnect/resource lifecycle выполняются кодом без ИИ. Генерация идёт
  только при задаче. Отдельный процесс Tool остаётся доступным, когда модель занята.
- Нужны snapshots/диффы/checkpoints перед сменой модели и один writer на package.
  Проверяющий может читать параллельно, но не одновременно менять тот же файл.

Бесплатная веб-сессия не предоставляет права на Mac сама по себе. До T3 она
может лишь обсуждать переданные файлы/patch; исполнение выполняет человек или
отдельный уже назначенный инструмент. Нельзя выдавать этот ручной обход за
готовую самостоятельную разработку MetaFor.

## Codespace: актуальное состояние и подключение аккаунта

Старые наблюдения от 14 октября: `zavx0z-en` и `universemolder` при start дали
HTTP 402; Portal credential `zavx0z` — 401, обычный gh login `zavx0z` — без
scope `codespace`. Это причины прежнего отказа, не состояние нового аккаунта.

**Обновление 15 октября:** в связанной задаче уже авторизован `bots-work` и
создан `miniature-happiness-jjjrvqg6x7qgcq97` из `zavx0z/codespace-vpn`.
Свежий GitHub API подтвердил `Available`, `basicLinux32gb`, 2 CPU, 8 GiB RAM,
idle timeout 240 минут. Другая задача сообщила готовность VPN. Capsule/ChatGPT
на новом ресурсе этой проверкой не подтверждены. VPN URI и секреты не копировать.
Нельзя продолжать использовать старое жёстко заданное имя Codespace/account
для нового подключения. Не останавливать и не заменять этот VPN при bootstrap.

Сейчас Владимиру повторять подготовку аккаунта не нужно. Для следующего аккаунта:

1. Войти на github.com нужным аккаунтом, подтвердить email и проверить остаток
   Codespaces compute/storage в Billing. Сам факт нового аккаунта не гарантирует
   разрешение запуска.
2. Выдать ему доступ к нужному repository. Не запрашивать доступ ко всем Repo
   ради одного deployment. При приватном repository согласовать требуемую роль.
3. На Mac выполнить обычную авторизацию с дополнительным scope:

   ```sh
   gh auth login --hostname github.com --git-protocol https --web --scopes codespace
   ```

   В браузере проверить выбранный аккаунт. Токен не отправлять в чат. Сообщить
   только логин; проверить его и `/user/codespaces` под этой точной identity.
4. Явно назначить account/repository/Codespace/profile/release новому подключению
   MetaFor. Сначала status, затем один разрешённый start/create, затем health/ACP/
   viewer/model отдельно. Не открывать control-порт всем ради обхода private URL.
5. При малом бюджете Codespace запускается на необходимую работу. Текущие
   240 минут idle особенно важны для расхода; не менять timeout живого VPN
   без согласованного перехода. Не проектировать бесконечный keep-alive как
   замену quota/billing handling. Stopped Codespace продолжает занимать storage.
6. Старые диски с профилями и незакоммиченными изменениями не удалять, пока
   не подтверждён корректный перенос. Профиль сохраняет/открывает его native owner.

## Границы передачи следующему исполнителю

- Работать в выданном checkout/ветке, не создавать клоны/worktree/ветки автоматически.
- Не читать `production`, его vendor или внешний Concept.
- Не менять платформенные Template/DOM/Renderer/Engine пакеты в UI-задаче.
  Сначала публичный контракт; подтверждённый generic gap передать владельцу.
- Не писать в Boundary SQLite/Mass напрямую. Поля и авторинг — Oracle → Force →
  Boundary; source changes и release — отдельные явно разрешённые возможности.
- Не передавать в модель credentials/browser archives и не раскрывать произвольный
  host execution через публичный viewer или unauthenticated endpoint.
- Не повторять неизвестный model/tool effect. Не смешивать native session IDs,
  логическую Cosmos Session и Quantum Agent refs.
- Не считать gh HTTP 200, Provider `ready`, login, video и ответ модели одним
  признаком готовности. У каждого свой наблюдаемый результат.
- Не останавливать runtime другого чата. Lifecycle MetaFor — только после
  проверки ownership через `.agents/skills/metafor-dev/scripts/metafor-dev.sh`.
- Не объявлять «всё работает» по unit tests. Завершать этап реальным сценарием
  пользователя и оставлять следующему исполнителю проверенные факты/остаток.

## Источники и ограничения цены

Проверено 15 октября 2026. Эти условия могут меняться; покупка не выполнялась.

- [OpenAI: Pricing](https://learn.chatgpt.com/docs/pricing): есть Pro варианты
  $100/$200/$500; переход на $500 не является единственным вариантом продолжения.
  Free описан как GPT-6 Luna в desktop, subject to rollout. Это не обещание
  бесплатной Astra или тождественной доступности web/CLI. Work и Codex делят usage.
  План выше рассчитан на отсутствие обязательной платной модельной зависимости.
- [GitHub: included usage](https://docs.github.com/en/codespaces/troubleshooting/troubleshooting-included-usage):
  compute и storage ограничены отдельно; работающая машина расходует core-hours,
  существующая — storage. Без доступной квоты/биллинга start может быть запрещён.
- [GitHub CLI login](https://cli.github.com/manual/gh_auth_login): штатный web flow
  и дополнительные scopes; [refresh](https://cli.github.com/manual/gh_auth_refresh)
  применяется к уже сохранённому входу. Не сохранять токены в handoff/Git.

Готовая недорогая основа здесь — собственная GPU и уже существующие execution
contracts. Качество модели и полная автономность ещё требуют T1–T4; их нельзя
подменять обещанием бесплатной бесконечной веб-генерации.
