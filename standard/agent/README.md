# Агент

`@metafor/agent` (далее — agent) представляет канонического участника
[стандартной агентной композиции](../../docs/AGENT_UNIVERSES.md#минимальная-стандартная-композиция),
которому передают сообщение или задачу с устойчивой identity. Обычное сообщение
получает свободный ответ модели через собственную беседу. Явное намерение запустить
сценарий требует разрешённого Graph через Oracle Environment: agent просит беседу
выбрать объявленный сценарий и формулирует ответ после проверенного результата.
Состояния, ожидание подтверждений и результат принадлежат Quantum, а не Cosmos.

Явный режим разработки разрешает модели выбрать код для дочернего
`@metafor/repl` (далее — repl) либо конечный ответ. Repl исполняет код только
при назначенной native возможности; его результат, включая ошибку JavaScript,
возвращается в ту же беседу для следующего шага. Agent сохраняет каждый шаг
в собственной Mass и заканчивает цикл ответом или явным исчерпанием бюджета.
По умолчанию бюджет составляет 16 обращений к модели. Неизвестный исход
инструмента завершает задачу без повторной отправки кода.

Служебная обратная связь выбранному Agent сохраняется в его собственной беседе.
Её подтверждение означает сохранение наблюдения; оно не меняет пользовательский
draft, задачу или выполняемый шаг. Беседа добавляет наблюдение в контекст
следующего уже запрошенного обращения к модели.

Каждый Agent материализует одну `@metafor/chat` (далее — chat), одну
`@metafor/scenario` (далее — scenario), одну `@metafor/codespace` (далее — codespace)
и одну repl.
Chat владеет модельной сессией и полным
диалогом в своей Mass; scenario владеет выполнением и повтором сценария. Agent
сохраняет контекст задачи, стабильные запросы и конечный результат в собственной
Mass. Объявленные displays остаются проекционными привязками; они не создают
дополнительный диалог или runtime.

Codespace исполняет явное наблюдение или намерение запуска назначенного рабочего
места через выданную native возможность. Agent передаёт коррелированный запрос
инструменту и сохраняет его подтверждённый результат. Принятие запуска не
утверждает готовность рабочего места. Без запроса codespace остаётся бездействующим.

Декларация может называть разные инструменты; исполнение требует выданного права,
поддержанного обработчика и наблюдаемого Tool Atom. Текущая композиция принимает
объявленный сценарий проверки агентной системы и назначенное нативное исполнение
в явном режиме разработки. Неизвестный обработчик остаётся
явным отказом при намерении запустить инструмент до обращения к модели.

Подтверждение успешного шага требует точного request identity. Ошибка ребёнка
остаётся отказом независимо от identity подтверждения. Неподдержанное намерение модели,
неразрешённый сценарий и отрицательный результат проверки не становятся успехом.
Повтор завершённой задачи возвращает сохранённый ответ; та же identity с другим
режимом, текстом или конфигурацией отклоняется. Незавершённая задача использует
сохранённые запросы, а Chat, Scenario и Repl сохраняют собственные ограничения повторного исполнения.

Обычная реплика передаётся модели буквально и остаётся пользовательским сообщением
в истории. Текст ответа не вызывает инструмент, даже если похож на команду.
Беседа готова принимать сообщения при рождении Agent; соединение с провайдером
создаётся при первом запросе. Чередование разговора и сценариев сохраняет ту же
беседу и её native identity.

Рабочие изменения проходят обычные Process и Boundary commits. В режиме
разработки назначенный repl может изменять исходники и запускать процессы ОС.
Публикация в source-owner является
отдельным явно разрешённым действием в
[принятом порядке рабочего авторинга](../../docs/META_PACKAGES.md#принятый-порядок-рабочего-авторинга).

## Представление owning Atom

Представление получает явную привязку к Atom владельца и читает разрешённую
проекцию его текущего состояния. Общие Chat и Inspector показывают беседу,
инструменты и контекст того же участника. Chat ограничивает frontend окно уже
полученной истории; полная Mass и её транспорт остаются у владельца беседы.

Историю отображает готовая публичная Storybook timeline: обычные сообщения,
сворачиваемые Tool cards, результаты и терминальный вывод. Decision и result
из собственного Chat Mass связываются только по подтверждённым task/step/request
данным. Неоднозначная связь остаётся неизвестной; native ACP события, которых
Mass не сохранила, не достраиваются. Служебная обратная связь имеет собственную
строку. Раскрытие загружает только resident body; сворачивание и уход из истории
освобождают детали, сохраняя identity строки и пользовательский draft.
Приложение размещает public provider pane в своём HUD. Модели и уровни
рассуждения показывает только источник провайдера. Чтение и выбор категории
Inspector не меняют каноническое состояние.

Provider pane использует готовую публичную форму
`@zavx0z/storybook-chat-preferences`, ту же, что настройки Storybook. MetaFor
передаёт компактный каталог подключений, фактические модели и уровни мышления,
раскрывая только эти поля и действующие операции Atom. Storybook HTTP, policy
и настройки подключений не переносятся. Профиль выбирается отдельно; RTC preview
раскрывается в панели «Браузер». Технические identity и registry доступны
только после раскрытия подробностей.

Активный разрешённый RTC preview предоставляет владельцу Capsule PNG через
публичный screenshot provider. Profile и instance закреплены тем же Provider
grant; request correlation и кодирование принадлежат Capsule. Для кодирования
используется off-DOM native video того же полученного stream, без второго UI
или viewer. Закрытие preview освобождает screenshot transport и decoder,
позднее кодирование не отправляет результат. Сохранение профиля сохраняет
preview до запроса кадра владельцем; сам archive и native lifecycle остаются
у владельца профиля. Без активного кадра успех снимка не объявляется.

Именованные области беседы, инструментов и контекста принимают
самостоятельные компоненты. Без переданного компонента остаётся стандартное
содержимое. Компоненты используют Document принимающего приложения; обновление
наблюдения и смена вкладки сохраняют принятые компоненты и их состояние. Такая
композиция не создаёт новый Chat и не выдаёт дополнительных операций.

Ввод сообщения, изменение настроек и вызов инструмента проходят операции
назначенного Environment. Объявленный инструмент становится доступным человеку
только при наличии соответствующей операции у этого назначения. Результат
вызова подтверждает передачу запроса; наблюдаемое состояние приходит из
проекции владельца.

Офис является производным пространственным представлением внутри заданных
Atom или Display призматических границ. Рабочие места следуют
[общему flex-распределению](../../docs/AGENT_UNIVERSES.md#представления-и-слоты)
вдоль стен: собственные размеры и общий gap определяют размещение, свободное
место распределяется равномерно, а угловые зазоры выводятся из габаритов соседей.
При нехватке места персонажи и устройства уменьшаются в одном масштабе;
локальные координаты и bounding box офиса сохраняются. Связи показывают
принадлежность экранов, сохраняя отличие от transport и причинных сил.
Геометрия представления не назначает канонические
координаты Atom.

Персонажи и одинаковые устройства используют общие модели и материалы,
сохраняя собственные положение и позу. Один общий набор instance batches
обслуживает все офисы представления; перенос офиса изменяет матрицы его
экземпляров, сохраняя локальный fit и identity рабочих мест. Содержимое экранов остаётся Display
того же Document. Завершение представления освобождает его экземпляры,
сохраняя заимствованные ресурсы владельца.
