# Provider

`@metafor/provider` (далее — provider) предоставляет назначенные возможности
[окружения и его участников](../../docs/ENVIRONMENTS.md). Развёртывание Meta,
наблюдение ресурсов и получение ответа модели сохраняют отдельные операции
и права. Его Atom владеет реестром доступных исполнителей, настройками и
результатами проверок в своей Mass. [Chat](../chat/README.md) владеет беседой и
обращается к своему provider по явному запросу; обнаружение исполнителей само
по себе не отправляет сообщение модели.

Provider наблюдает свой Graph и разрешённые удалённые миры через
[Oracle](../../docs/DARK.md). Он различает объявление возможности и проверенное
соединение. Atom с точной Meta identity `chrome-studio` либо `capsule`
предоставляет собственное состояние и описание возможностей; дочерний runtime
того же владельца не становится вторым провайдером. Native процесс без Atom не
создаёт вымышленного участника Graph.

Подключённый и допущенный peer может предоставить описание исполнителей своего
мира. Отсутствующее описание, неизвестный удалённый Graph, потерянное соединение
и устаревшая проверка сохраняются явно. Telemetry не заменяет допуск. Начальное
назначение хоста может зарегистрировать проверенную native возможность с её
происхождением; оно не утверждает существование удалённого Atom или мира.
Внешняя конфигурация запуска предоставляет credentials и transport capabilities,
а текущий реестр и выбор исполнителя принадлежат Mass provider.

Участник сохраняет identity мира, выбранные Atom, права и поколение связи по
[закону Atom-связи](../../docs/ENVIRONMENTS.md#связь-на-уровне-atom).
Фотоны обновляют наблюдение только назначенных Atom. Разрыв или смена мира
закрывает актуальность прежней привязки; обычное чтение Oracle восстанавливает
наблюдаемую проекцию без утверждения полноты чужой причинной истории.
Тип окружения выбирает совместимую корневую Meta. Само название Android,
устройства или сервера не выдаёт native возможность установки.

Обнаружение и повторная проверка являются автономными Processes без ИИ. Новый
снимок обновляет наблюдения, сохраняя настройки и происхождение записей.
Исчезнувший участник сохраняется как disconnected, а истёкшая проверка как stale.
Неизвестная либо отключённая запись не является готовым исполнителем.

Root может передать начальное native назначение после первого обнаружения.
Отдельный bootstrap Process однократно заполняет ещё пустой реестр, затем
запрашивает конечную проверку transport/executor admission. Она не проверяет
ответ модели или авторизацию сайта. Существующий непустой реестр bootstrap не
заменяет. Обычное обнаружение потребляет `discoveryRequest` и очищает его.

Явный запрос регистрации через то же обнаружение может дополнить существующий
реестр точным native назначением Codex или браузера. Хост сначала подтверждает своё назначение
и admission; provider сохраняет полученные проверки и объявленные операции,
сохраняя другие записи и настройки. Повтор того же запроса возвращает сохранённый
результат, а другой binding с уже занятой identity отклоняется. Регистрация сама
по себе не создаёт model session и не отправляет сообщение.

Браузерное назначение сначала подтверждает доступный просмотр и управление
через публичный transport владельца. Отдельная проверка ACP подтверждает только
admission операции модели; её отсутствие сохраняет просмотр без возможности
model turn. Ни описание браузера, ни lazy initialize не подтверждают вход на сайт
или ответ модели: результат такой проверки остаётся unknown.

Явное сохранение окна настроек заменяет конфигурацию подключений в Mass только
при совпадении наблюдаемой ревизии. Provider сохраняет название, включение,
параметры подключения и выборы уровней вместе; удаление записи убирает её из
настроек. Отключённое подключение не допускает новое исполнение. Параметры
сами не выдают host capability: проверка сопоставляет подключение с точным
назначением хоста и сохраняет результат отдельно от конфигурации. Недоступное
назначение остаётся сохранённым с явной ошибкой проверки. Адрес сервиса и пути
не запускают произвольный процесс и не заменяют назначенный transport.

На одном уровне root Provider является владельцем общего registry Mass. Provider
внутри Chat получает тот же Mass alias в режиме `registryMode='executor'`: он
читает назначения и ведёт собственный журнал turns, но не меняет реестр,
не применяет bootstrap и не запускает обнаружение или проверки ресурсов.

При явном запросе provider разрешает binding по собственному реестру и проверяет
назначенную хостом native возможность. Устойчивый журнал запросов связывает
identity запроса, исполнителя и native сессию. Завершённый запрос возвращает
сохранённый ответ; повтор identity с другим содержимым отклоняется. Неизвестный
исход отправки не вызывает автоматической повторной отправки.

Ollama использует готовый native adapter моделей и сессий. Хост назначает
точный endpoint и каталог native истории в своей private конфигурации;
подключение UI должно совпасть с этим назначением. Проверка и каталог читают
только установленные модели и объявленные ими параметры без генерации.
Первый явный turn применяет выбранные общие параметры к новой native сессии;
последующие turns сохраняют её identity и собственные изменения настроек.
Ответ модели поступает в тот же Chat и назначенный цикл Agent.

Для сохранённой native сессии пользователь читает текущий каталог моделей и
уровней мышления и выбирает только предложенные исполнителем значения.
Чтение и установка проходят через Process того же provider, сохраняя
принадлежность Chat и native identity. Полученный каталог отражает наблюдаемые
настройки исполнителя; отсутствие вариантов сохраняется явно. Настройка
не отправляет сообщение модели.

Представление получает owning Atom через `useAtom` и обращается к его Mass и
разрешённым Oracle/Force операциям. Оно показывает реестр, проверки и тот же
исполнитель, которым пользуется Chat. Локальная копия настроек UI не становится
источником назначения провайдера.

Назначенный native Oracle раскрывает текущий owning профиль через
`energy.profile.read` и принимает закрытые `profile.open`/`profile.save` через
`energy.profile.intent`. [Публичные типы](../../types/metafor/profile-intent.ts)
задают exact мир, Atom и ожидаемое назначение. Эти операции объявляют
корневые Meta `intel-macos-chrome-studio` и `workspace-capsule`; сохранение Capsule
проходит через native capability её собственного System child.
Receipt подтверждает приём обычного Root Field input, а завершение показывает
сам владелец. [Проверки](../../quantum/energy/peer-oracle.spec.ts) покрывают
локальное и удалённое admission; они не утверждают прохождение реального login.
