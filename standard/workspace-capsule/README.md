# Workspace Capsule

`workspace-capsule` — отдельный корень сетевого рабочего окружения Capsule.
Его конечный автомат подготавливает либо подключает сетевого участника.
По умолчанию профиль открывается только отдельным явным намерением; назначение
профиля не запускает браузер. Разрешённый владельцем запуск профиля при рождении
задаётся отдельно. Стандартный Provider
наблюдает доступных исполнителей; запрос модели требует отдельного намерения.
Agent появляется только по явному разрешению владельца.

Выбор неизменяемого save либо исходного шаблона сохраняется как ссылка
конфигурации. Материалы принадлежат Mass соответствующего участника и Capsule;
декларация ссылки не импортирует профиль. Новый мир создаётся по
[закону корневых окружений](../../docs/ENVIRONMENTS.md#развёртывание).
Существующий Boundary и старые поставки сохраняют свои identity.

`saveId` задаёт immutable источник. При нём optional `templatePath` явно
назначает шаблон запуска, сохраняя identity save. Без `saveId` исходный шаблон
обязателен. Пустой или отсутствующий назначенный save не заменяется пустым
профилем; импорт и проверку сохранения выполняет Capsule до System launch.

Представление выбранной браузерной сессии подключается через WebRTC в Agent
Display. UI-хост владеет receiver и вводом; обычный FSM не требует ИИ.

Явное сохранение передаётся runtime Atom Capsule. Он проверяет принадлежащую
ему edit-сессию, сохраняет admission до вызова публичного lifecycle и
подтверждает новый immutable save вместе с остановкой writer. Корень ожидает
этого результата; принятие Oracle intent само по себе не подтверждает сохранение.
Неизвестный исход сохраняется для наблюдения владельца и не повторяется автоматически.
Отсутствие подключённого поставщика PNG preview обнаруживается до отправки save:
ресурс остаётся работающим, а новый явный запрос возможен после его подключения.

Явная смена совместимого шаблона сохраняет профиль, его рабочие данные и identity
экземпляра. Oracle передаёт намерение корню; Capsule допускает native действие
только через собственный System. Новый шаблон становится наблюдаемым после
подтверждения lifecycle; отказ восстанавливает прежний шаблон, а неизвестный исход
требует наблюдения без автоматического повторения.

Готовность ресурсов и готовность Oracle различаются. Подтверждение полного
назначенного канала приходит от сетевого участника; до него корень ожидает
наблюдение Oracle. Потеря подтверждения возвращает это ожидание, сохраняя ресурсы.

Корень хранит единый реестр Provider в своей Mass. Его Provider-владелец
обновляет этот реестр, а явно подключённый Agent и его Chat используют ту же
привязку без отдельной копии настроек. Начальное разрешение Agent выключено.
