# Беседа агента

`@metafor/chat` (далее — chat) сохраняет отдельную беседу Agent с моделью в
[стандартной агентной композиции](../../docs/AGENT_UNIVERSES.md#минимальная-стандартная-композиция).
Agent передаёт предметный запрос, chat продолжает принадлежащую ему сессию и
возвращает текст ответа либо явный отказ. Проверка смысла ответа и выбор
предметного действия принадлежат Agent.

Служебное наблюдение интерфейса поступает отдельно от пользовательского запроса.
Chat сохраняет его с устойчивой identity и исходной корреляцией и подтверждает
запись без обращения к модели. Повтор той же записи возвращает квитанцию,
а иное содержимое с прежней identity отклоняется. Следующий уже запрошенный
turn получает ещё не переданные наблюдения как служебные данные, без новой
задачи или разрешения выполнять команды. Наблюдение, поступившее во время
model turn, относится к следующему запросу и не меняет отправленный prompt.

История сообщений, продолжение native сессии и результаты завершённых запросов
принадлежат Mass chat. Живое подключение принадлежит Energy собственного
Provider Atom. Chat передаёт ему запрос и принимает подтверждение через
обычные Matter-связи и Fields. После перезапуска беседа продолжается с прежней identity.
Отказ восстановления сохраняет прежнюю беседу и сообщается вызывающему Agent.

Повтор завершённого запроса возвращает сохранённый ответ. Повтор identity с
другим содержимым отклоняется. Если после аварии неизвестно, приняла ли модель
запрос, chat сообщает неопределённый исход и ожидает отдельного решения владельца.
Автоматическая отправка такого запроса и следующего turn приостанавливается.
Доказанный отказ до вызова prompt сохраняется как завершённый неотправленный
запрос. Повтор его identity возвращает отказ; после исправления провайдера
владелец может передать новое сообщение с новой identity, сохраняя ту же беседу.

Собственный `@metafor/provider` (далее — provider) исполняет запрос через
назначенную native-возможность. Его [реестр и проверки](../provider/README.md)
принадлежат канонической Mass. Chat сохраняет ответ, а Agent проверяет
предметное намерение; текст модели сам по себе не является предметным изменением.

При общем реестре уровня дочерний исполнитель читает ту же Mass через
прямую привязку и сохраняет свои turns отдельно; копия каталога не создаётся.
В самостоятельной композиции он владеет локальным реестром. Native-конфигурация
выдаёт transport capability и credentials, сохраняя выбор и проверки в Mass provider.
Продолжение использует тот же сервис, хост, исполнитель и native session.
Смена привязки существующей беседы отклоняется и сохраняет её историю.
Другой сервис или хост получает отдельный Agent с собственным Chat;
недоступность выбранного хоста не вызывает автоматического переключения.
