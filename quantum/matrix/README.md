# Matrix

Matrix решает, в каком `State` находится каждый `Atom`, какой `Transition`
может произойти сейчас и нужно ли после смены состояния начать `Process`.

Matrix не исполняет действия и не записывает канонический мир. Действие
исполняет Energy, а его результат становится частью мира только после проверки
и записи в Boundary.

Этот документ описывает смысл Matrix для всей системы. Техническое устройство,
внутренние структуры и ссылки на подтверждающие проверки находятся в TSDoc
рядом с public contracts.

## Основные понятия

* `State` — текущее состояние Atom.
* `Transition` — разрешённый переход из одного State в другой.
* `Condition` — условие перехода, которое читается по текущим значениям Fields.
* `Process` — действие, привязанное к State и исполняемое Energy.
* `Reaction` — наблюдение целевого Atom за каждым новым подтверждённым State
  другого Atom.
* `Reaction relation` — точная связь source Atom с одной Reaction target Atom,
  заранее разрешённая Boundary из декларативного selector.
* `lock` — местная блокировка одного Atom на время его текущего Process.
* `Photon` — сообщение Matrix о наблюдаемом State и, при наличии Process, о
  начале конкретного выполнения.

## Рождение Matrix

Перед рождением Matrix получает от Boundary один согласованный снимок текущего
мира. Пока этот снимок не подготовлен, Matrix не принимает обычные изменения.

Это единственная полная сборка Matrix. Она происходит один раз в новом
процессе. Во время работы Matrix не принимает второй полный снимок, не заменяет
целиком свой рабочий мир и не пытается родиться повторно в том же процессе.
Если нужна новая полная сборка, прежний процесс завершается, а новый снова
получает согласованный снимок от Boundary.

Для каждого Atom возможны три исходных случая.

### У Atom вообще нет States

Matrix отмечает, что у Atom нет автомата состояний. Fields этого Atom продолжают
существовать и могут меняться, но Matrix не выбирает начальное состояние, не
ищет переходы и не выпускает Photon о State.

### States есть, но текущее состояние ещё не определено

До первого такта Atom остаётся без выбранного State. На первом такте Matrix
вводит его в первый объявленный State.

Если Boundary указал State, которого больше нет в действующей декларации,
Matrix обрабатывает этот случай так же: состояние считается ещё не выбранным.

Если к этому State привязан Process, Matrix создаёт отдельное выполнение,
блокирует только этот Atom и выпускает `photon/test`. Если Process нет, Matrix
выпускает обычный `photon/replace`, а Atom остаётся свободным для следующих
тактов.

Вход в первый State и проверка переходов из него — не одно событие. На первом
такте происходит только вход. Переход из начального State может произойти не
раньше следующего обычного такта.

### Boundary уже хранит действующий State

Matrix восстанавливает именно его. Такой Atom не вводится повторно в первый
State. Следующий обычный такт начинается с восстановленного состояния.

Если согласованный снимок Boundary содержит незавершённое execution текущего
Process-bound State, Matrix не восстанавливает его номер и живое выполнение.
Она блокирует Atom новой execution identity и выпускает новый `photon/test`.
Boundary одной регистрацией переводит прежнее pending execution в
`superseded`; его поздний claim или результат не может изменить мир. Если
незавершённого execution нет, сам факт Process-bound State не является причиной
повторного запуска.

## Обычный такт

Обычный такт начинается после относящегося к Matrix изменения мира: например,
после изменения Field или подтверждённого результата Process.

Для каждого незаблокированного Atom Matrix:

1. читает его текущее состояние и значения Fields;
2. проверяет переходы текущего State в порядке объявления;
3. выбирает первый переход, все условия которого выполнены;
4. меняет State не более одного раза за этот такт;
5. сообщает о новом State через Photon.

Если ни один переход не подходит, State не меняется и новый Photon не
появляется. State без исходящих переходов является конечным и ведёт себя так же.

Если подходят несколько переходов, побеждает первый объявленный. Порядок
переходов поэтому является частью смысла Meta.

## Reaction

Начальный снимок Boundary содержит все точные потенциальные связи Reaction.
Matrix не ищет source Atom перебором и не исполняет фильтр на каждом изменении.
Во время структурной перестройки Boundary присылает только add, replace или
remove соответствующей связи.

Связь слушает только тогда, когда текущее и последнее подтверждённое State
целевого Atom входит в её объявленный набор. Вход в разрешённое State включает
только будущие события: текущее State источника повторно не проигрывается.

После настоящего изменения State Boundary выпускает отдельное подтверждение со
стабильной identity события. Повторный запуск Process в том же State такого
подтверждения не создаёт. Matrix сопоставляет подтверждённое новое State с
точными связями и до завершения обработки отправляет по одному enqueue на каждое
совпадение. Если отправка оборвалась, повтор того же события снова отправляет
полный набор; Boundary возвращает уже сохранённые элементы вместо дубликатов.

Boundary подтверждает durable FIFO-порядок каждого target Atom. Даже первый
элемент сначала становится ожидающим: Matrix отдельно запускает только точный
head подтверждённой очереди. Снимок зависимостей появляется при этом запуске, а
следующий head запускается только после terminal copy предыдущего. Поэтому два
события, каждое выполняющее `count + 1`, читают последовательные значения и дают
итог `+2`. Очереди разных target Atom работают независимо.

При холодном рождении Matrix получает незавершённую очередь из того же снимка
Boundary, не проигрывая заново текущее State источника. Не выбранное прежней
Energy исполнение продолжается с той же identity. Уже выбранное исполнение
завершается как `superseded`, потому что его прежний action мог записать Mass;
после terminal copy Matrix запускает следующий durable head.

Переход target между двумя разрешёнными States не отменяет текущее исполнение.
Выход из всех разрешённых States удаляет ожидающие triggers и переводит текущее
исполнение в `superseded`; уже выполненные записи Mass не откатываются.

## Условия перехода

Условие всегда относится к объявленному Field и использует только операции,
разрешённые для его вида. Краткое значение означает равенство. Несколько
операций внутри одного условия и условия нескольких Fields соединяются через
«и»: переход подходит, только если истинна каждая проверка.

Отсутствие значения не совпадает с обычным пустым значением. `null` означает,
что optional Field не имеет значения. Число `0`, `false`, пустая строка, первый
вариант enum и пустой массив являются существующими значениями. Проверка
`{ null: true }` выбирает только отсутствие, `{ null: false }` — только
существующее значение. Остальные операции требуют существующего значения.

Строковые условия проверяют равенство, вхождение в набор, начало, окончание,
подстроку, длину, включительный диапазон и регулярное выражение. Числовые
условия проверяют сравнения, включительный диапазон и вхождение в набор.
Условия enum проверяют равенство и набор вариантов. Условия массива проверяют
точное равенство, длину, пустоту, наличие элемента, а также выполнение
числового условия каждым или хотя бы одним элементом.

Длина строки считается так же, как в JavaScript. `every` для пустого массива
истинно, а `some` — ложно. Границы `between`, `min` и `max` включаются.

Matrix принимает только полностью известное и правильно записанное условие.
Неизвестная операция, неподходящий Field или неверное значение останавливают
подготовку либо структурное изменение с ошибкой. Условие не может молча
исчезнуть и превратить переход в безусловный.

Для чисел действует одно правило точности: значение Field и границы сравнения
приводятся к ней до такта, а недопустимое число отклоняется. Результат условия
не зависит от выбранного способа вычисления.

## State без Process

После входа в State без Process Atom не блокируется. Matrix сообщает новое
состояние, завершает свой такт и не пытается сразу пройти всю цепочку следующих
переходов. Каждый следующий переход требует следующего такта.

## State с Process

После входа в State с Process Matrix:

1. создаёт уникальный номер выполнения;
2. сохраняет значения Fields, с которыми оно должно начаться;
3. блокирует переходы только этого Atom;
4. сообщает Energy о новом выполнении;
5. принимает первого подходящего исполнителя Energy;
6. выдаёт ему сохранённые значения Fields.

Energy выполняет действие и предлагает результат Boundary. Предложение само по
себе ничего не меняет и не снимает блокировку.

Boundary проверяет, что Atom, State, Process, исполнитель и номер выполнения
всё ещё совпадают. Только после канонической записи результата Boundary
возвращает подтверждение Matrix. Тогда Matrix снимает блокировку и в том же
такте может выбрать следующий State.

Успех и ошибка Process проходят одинаковую проверку. Они различаются видом
результата, но ни один из них не обходит Boundary.

Если ни одна Energy не приняла Process или принятое действие не завершилось,
Atom остаётся заблокированным. Срок ожидания сейчас не задан. Это не
останавливает остальные Atom; недостающий закон зафиксирован в
[`MTX-004`](../../project/tasks/MTX-004.md).

## Что именно блокирует Process

Process не останавливает всю Matrix. Пока один Atom заблокирован:

- его State не меняется;
- его Fields могут получить канонические изменения;
- остальные Atom продолжают свои такты и переходы;
- Matrix продолжает принимать и последовательно завершать другие изменения.

Последовательность Matrix ждёт только завершения текущего изменения самой
Matrix, включая вычисление State и отправку вызванных им Photon. Она не ждёт,
пока Energy закончит Process.

## Изменение структуры мира

Добавление, удаление или перестройка Atom меняет только связанную часть
проекции Matrix. Не относящийся к изменению Atom не должен менять State,
получать новый Photon или повторно запускать Process.

Новый Atom проходит тот же начальный выбор:

- без объявленных States он остаётся без автомата состояний;
- со States и без выбранного State входит в первый объявленный State;
- с уже сохранённым State продолжает с него.

Если у работающего Atom не изменились его собственные State и Process,
постороннее структурное изменение сохраняет его блокировку и номер выполнения.
Например, добавление дочернего Atom не перезапускает Process родителя.

Если изменена декларация WIMP самого Atom, его прежнее выполнение становится
устаревшим. Matrix создаёт новое выполнение только для действительно
затронутых Atom. Energy отсоединяет старое действие; его поздний результат уже
не может изменить мир или снять блокировку нового выполнения.

Enum Field и его Variant rows приходят отдельными canonical Graviton. Boundary
выпускает новые Variant перед Field, но replay уже принятой старой
последовательности может временно показать Matrix Field раньше его default
Variant. В этот промежуток только отсутствующий enum default считается `null`;
следующий Variant перестраивает тот же Atom. Неизвестное сохранённое значение
или Condition по-прежнему является ошибкой.

Authoring State принимается одной Inflaton, но Boundary публикует её canonical
проекцию как State и принадлежащие ему Transition/Condition. При добавлении или
replace State появляется раньше нового состава; прежний состав удаляется до
State replacement. Поэтому Matrix никогда не должна собирать состав из source
или перечитывать Boundary: она применяет упорядоченные Graviton того же commit.

## Общие Fields

Несколько Atom могут читать одно каноническое значение Field. Изменение такого
значения даёт каждому связанному Atom возможность проверить собственные
переходы в его очередном такте. Простое равенство двух значений не создаёт
связь: связь существует только при общей канонической идентичности.

## Порядок одновременных изменений

Изменения, способные поменять Fields, State, блокировку или структуру Matrix,
завершаются в порядке поступления. Они не объединяются и не наблюдают
наполовину применённый результат друг друга.

Это правило не превращает Process в общую блокировку: выполнение Energy
происходит за пределами такта Matrix.

## Устаревшие и ошибочные сообщения

Matrix не принимает сообщение о выполнении, если не совпадает хотя бы одна
часть его идентичности: Atom, State, номер выполнения или выбранная Energy.
Запоздалый ответ старого Process не разблокирует новый и не меняет State.

Ошибочное или неполное описание перехода не становится переходом в первый
State. Оно не участвует в выборе; остальные корректные переходы сохраняют свой
порядок.

Если основной вычислительный контур Matrix отказал во время такта, этот такт
нельзя выдавать за успешный пустой результат. Ошибка возвращается в текущую
причинную доставку, после чего процесс Matrix завершается с ошибкой и его канал
Force разрушается. Force закрывает общий причинный поток, а текущий запуск
Вселенной останавливает остальные процессы.

Matrix не меняет способ вычисления посреди одной причинной последовательности
и не восстанавливает себя внутри того же процесса. Автоматический повторный
запуск и восстановление всего контура сейчас не реализованы; это отдельная
будущая задача [`SYS-001`](../project/tasks/SYS-001.md).

## Граница ответственности

- Boundary владеет каноническим миром и подтверждает результат Process.
- Matrix владеет выбором State, Transition, местной блокировкой и номером
  выполнения Process.
- Energy владеет исполнением Process и живыми ресурсами.
- Bulk показывает уже полученное состояние, но не выбирает его.

Ни Matrix, ни Energy, ни Bulk не читают хранилище Boundary напрямую после
рождения. Дальнейшие изменения приходят им отдельными причинными сообщениями.
