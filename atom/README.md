# @metafor/atom

[← Back to root](../README.md) | **English** | [Русский](README.ru.md)

## Purpose

- Materialises schemas from `@metafor/meta` and keeps them inside the field (`Field`, `Gravity`, `EM`, `Weak`, `Strong`).
- Drives the lifecycle of an atom: init, superposition, processes, reactions, impulse history.
- Exposes APIs for topology control (`Atom.fromSchema`, `Atom.append`, `Atom.createSibling`) and observation of impulses.

## Core concepts

### Self

```ts
atom.self // { atom: string, meta: string, path: string }
```

- `self.path` is the positional path (`0/1/2`) generated by `Field`.
- Full `Self` (with `destroy`) is available in reactions/processes, while filters operate on `SelfInfo`.

### Field

- Stores every atom together with parent/order metadata and the impulse history.
- Provides reservation helpers plus checkpoints for time-travel debugging.

### EM (Electromagnetic)

- Broadcasts impulses (`Photon`) between atoms.
- Exposes `EM.break()` / `EM.resume()` to freeze/resume the stack (used by Inspect/Virtual).

### Photon-based encoding

- **Intensity**: the length of `photon.impulses` mirrors how “bright” the event is (e.g. success updates with multiple patches).
- **Frequency/colour**: the `meta` + `atom` pair identifies the emitter, analogous to wavelength.
- **Polarisation**: JSON Patch `path` + `op` define the direction and type of mutation (context, state, root).
- **Phase**: `timestamp` and the position inside the EM stack describe relative timing.
- **Superposition**: the current state acts as the detector; reactions decide whether to absorb the photon.

This lets any actor interpret an impulse purely from its properties—no direct pointer to the sender is required.

## Creating atoms

### `Atom.fromSchema`

```ts
const atom = Atom.fromSchema({
  meta: userProfile,
  id: "user-1",
  context: { userId: 42 },
  core: { cache: new Map() },
  path: "0/1", // optional, reserved in advance
})
```

- If `path` is omitted it is generated automatically.
- Context/core initial values come from the schema and are patched with provided overrides.

### `Atom.createSibling(targetId, meta, options)`

- Reserves a slot before/after an existing atom.
- Instantiates the sibling on the next macrotask so the parent stays non-blocking.

### `Atom.append(parentId, meta, options)`

- Adds a child to a parent (`parentId === null` means root).
- Index equals the current amount of children.

## Lifecycle

1. **init** — measures the superposition and collapses to the first state.
2. **transition** — sets the state and triggers the associated process.
3. **action → success/error** — executes the process and updates context via `update`.
4. **reactions** — process incoming impulses; successful `equal` may trigger a new measurement.
5. **destroy** — removes the atom from the field and runs teardown (`process.destroy()`).

Public methods are wrapped with `@EM.it`, so each call emits a `Photon` automatically.

## Context updates

```ts
atom.evaluate({ userName: "Neo" })
```

- `evaluate` applies partial updates through `Update<Values>` from `@zavx0z/context`.
- The change propagates as a `Photon` with a `replace` operation at `/context`.

## Runtime reactions

```ts
reactions.run({
  meta: photon.meta,
  atom: photon.atom,
  timestamp: photon.timestamp,
  patch,
  context: atom.λ,
  core: atom.core,
  state: atom.state,
  update: atom.evaluate,
  self: atom.self,
})
```

- A reaction fires only when the atom state matches, the filter returns conditions, and the JSON Patch satisfies them.
- After `equal` succeeds, the atom measures the superposition again and may collapse into a new state.

## History & rollback

- `Field.histories` stores recent impulses; once `MAX_PATCHES` is reached a checkpoint is created.
- `Field.createCheckpoint()` captures snapshots of all atoms.
- `Field.rollbackSystem(timestamp)` restores the field to the closest checkpoint ≤ `timestamp`.
