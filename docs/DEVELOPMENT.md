# Разработка MetaFor

## Ежедневная работа

### Открыть локальную среду

В терминале из рабочего checkout MetaFor:

```bash
metafor status
metafor start
```

Откройте адрес, который напечатала команда. `start` сохраняет уже работающую
среду. Команда использует одну видимую iTerm-сессию; закрытие чата Codex не
завершает её. Для просмотра этой сессии и её сообщений:

```bash
metafor focus
metafor logs
```

Если короткая команда ещё не установлена, её действующий вход из этого же
checkout:

```bash
.agents/skills/metafor-dev/scripts/metafor-command.sh start
```

После изменения серверного кода весь связанный contour перезапускается явно:

```bash
metafor restart
```

`metafor stop` останавливает этот contour, сохраняя окно iTerm. Эти команды
не запускают и не закрывают браузерный профиль. Существующий запуск вне
управляемой сессии требует проверки принадлежности; второй экземпляр поверх
него не запускается.

### Агент, подключения и беседа

Откройте Atom по его адресу или двойным щелчком по комнате в общем обзоре.
Камера подлетает к главному дисплею с инспектором Atom. В HUD нажмите «Войти
в комнату»: главный дисплей скрывается, появляются список агентов и их чаты.
Выберите агента в списке, чтобы открыть его чат на весь экран. «Назад» в HUD
или «Назад в комнату» в окне чата возвращает общий план этой комнаты.
Двойной щелчок по чату над головой открывает тот же чат; история и черновик
сохраняются при переходах. Адрес Atom при этом не меняется.

В боковом HUD «Комната» доступны «Добавить агента», «Добавить группу» и
«Добавить чат». Для нового чата выберите агента этой комнаты. Группа сохраняет
название и выбранных участников; её создание не отправляет сообщения моделям.
Пространственные соединения групп и рассылка общего сообщения участникам
не предоставлены этим интерфейсом.

У каждого агента есть список сессий с созданием, выбором, переименованием и
удалением через те же компоненты, что в Storybook. Настройки провайдера,
модели и уровня рассуждения относятся к выбранной сессии. После закрепления
нативной сессии провайдер сохраняется вместе с её историей; другой провайдер
выбирается в новой сессии. Неизвестный исход отправки не вызывает автоматический
повтор. Архив прежней беседы доступен отдельно для чтения, без возобновления
неподтверждённого нативного запроса.

Имя и пол представления редактируются в настройках чата агента. Начальный
вариант гуманоида выбирается один раз и сохраняется. Изменение внешнего вида
не меняет identity агента и его сессий.

Данные новых бесед, профилей и групп находятся в директории Cosmos
`<stateRoot>/cosmos/conversations`. Её можно назначить отдельно через
`COSMOS_CONVERSATIONS_PATH`. Они не записываются в Mass Atom. Источник истории
и индекс принадлежат используемому хранилищу сессий Storybook; вручную менять
его внутренние файлы для переноса сообщений не следует.

Подключения настраиваются через общий HUD «Настройки». Вход на сайт выполняет
человек в панели «Браузер» при создании агента или в «Настройки агента» его чата.
При ошибке браузерного провайдера рядом с сообщением доступна кнопка
«Открыть браузер провайдера». Она открывает тот же встроенный просмотр.
Показ комнаты и истории не подключает все модели: подготовка провайдера
происходит для выбранного полноэкранного чата. Обновления рабочего пространства
и активной беседы приходят по существующему соединению; периодического чтения
бездействующих чатов нет. Временная ошибка наблюдения сохраняет открытый чат
и черновик, а её сообщение появляется в заголовке и HUD.
Проверка соединения и наличие модели в каталоге
не отправляют prompt и сами по себе не подтверждают авторизацию. Обычная
реплика в новом чате не запускает код и не меняет поля Quantum.

### Изменить поля Atom

Откройте нужный Atom. На общем дисплее сразу открыт одинаковый инспектор.
В «Состояние» нода параметров показывает
объявленные поля. Строки, числа и логические значения редактируются готовыми
полями Immersive, enum — выбором варианта, числовой массив — JSON-массивом,
например `[1, 2, 3]`. Для необязательного поля действие «Очистить» подготавливает
`null`. Поле без наблюдаемого текущего значения недоступно для изменения.

Можно изменить несколько параметров подряд: ввод меняет только черновики.
Счётчик в шапке показывает число изменённых полей. Нажмите кнопку со значком
сохранения в шапке ноды, чтобы сохранить весь набор одной транзакцией.
До ответа поля заблокированы; «Поля сохранены» появляется после причинного
подтверждения применения набора. Следующий Process может изменить значения
снова; его результат наблюдается в состоянии и полях Atom.

Сокеты видны с обеих сторон каждого параметра; создание связей через них
отключено. «Отменить изменения» возвращает все поля к текущему наблюдению.
Фоновое обновление Graph сохраняет введённые черновики и исходные значения
для проверки конфликта. Если одно из изменяемых значений устарело, весь набор
отклоняется, а черновики и ошибка остаются на экране. Для новой попытки с новым
наблюдением отмените изменения и внесите их заново. Смена Atom или мира
завершает редактирование прежнего набора.

У окружения с профилем проверьте `profileName`, `saveId`, `templatePath` и
`workMode` перед явным запросом открытия. Профиль и его сохранение принадлежат
выбранному хосту. Поле имени профиля не импортирует произвольный URL или архив;
импорт и назначение выполняются штатным владельцем профиля.

### Storybook

Для подготовленного Project zavx0z запустите его существующую команду:

```bash
cd /Users/zavx0z/projects/zavx0z
bun run storybook
```

Откройте напечатанный адрес. В интерфейсе используйте панель «Агенты» для
назначений и бесед Storybook. Это отдельная среда; её агенты и история не
становятся агентами MetaFor автоматически.

Для проверки или восстановления агент использует `storybook_status`,
`storybook_search`, `storybook_open` и `storybook_check` через общий вход
среды. Успешная сборка не заменяет открытое рабочее представление.

### Назначенный Codespace

Текущий Codespace Tool управляет одним уже назначенным ресурсом. Создание
нового Codespace и указание адреса импортируемого профиля ещё не предоставлены
его интерфейсом.

В инспекторе самого Codespace Atom запрос задаётся полем `request`, например
`{"id":"status-2026-10-13-1","operation":"status"}`. Для нового наблюдения
используйте новый `id`. Если `ack` уже равен `true`, после подготовки запроса
установите `ack` в `false`. Результат появляется в `response` или `error`.
Операция `start` таким же образом запускает только назначенный Codespace.

Принятый запрос запуска ещё не означает готовность браузера и Provider.
При неизвестном исходе сначала запросите `status`; автоматического повтора
запуска нет. Подробности назначения принадлежат
[инструменту Codespace](../standard/codespace/README.md).

Если GitHub отклоняет запуск с HTTP 402 и сообщением о billing issue,
нужно восстановить доступ по биллингу этого аккаунта или назначить ресурс
другого доступного аккаунта. Переключение VPN не устраняет этот отказ.
HTTP 401 означает, что вход нужно обновить; HTTP 403 с требованием scope
`codespace` — что действующему входу не выдано право управлять Codespaces.
После исправления доступа сначала проверьте состояние ресурса, затем Browser
и Provider. Не удаляйте остановленный Codespace: его диск может содержать
сохранённые профили и незакоммиченные изменения.

### Размещение браузерных провайдеров

Текущая схема подключения: Qwen работает в отдельном Docker-контейнере на
ai-srv, DeepSeek — через Chrome Studio на Mac, ChatGPT — в Codespace.
Браузеры запускаются по запросу. Сохранённый профиль относится к своему хосту;
наличие авторизации на Mac не подтверждает её переносимость в Linux-контейнер.

В HUD выберите подключение нужного хоста. Готовность сервиса, вход в аккаунт,
ответ модели и работа звука с микрофоном проверяются отдельно в этом подключении.
Не требуется запускать все браузеры одновременно.

### Локальные Chrome Studio и Provider

Core, Chrome Studio и Provider имеют отдельные назначения. Для уже
подготовленного локального MacServices launcher из этого checkout:

```bash
python3 .local/oracle-agent-provider/native/mac-services.py status
python3 .local/oracle-agent-provider/native/mac-services.py start studio
python3 .local/oracle-agent-provider/native/mac-services.py start provider
```

Это операторский launcher локальной установки; он не входит в поставку
MetaFor и не заменяет её конфигурацию. `status` показывает готовность и точные
процессы. `start` запускает только отсутствующий сервис и отказывает при
занятом назначенном порте. Он не открывает профиль и не отправляет сообщения
модели. Секреты и назначения хранятся в приватной конфигурации оператора.

Работающий браузер и сохранённая авторизация принадлежат Chrome Studio.
Остановка HTTP-сервиса не является закрытием или сохранением профиля.
После восстановления сервиса отдельно проверяются видео и управление в
панели «Браузер»: ответ health и живой Chrome этого не доказывают. Если
управление не восстановилось, сохраните профиль и его сессию для проверки
владельцем; переоткрытие браузера может изменить текущий захват.

## Установка

Активный workspace задан явным списком корневого `package.json`. Его установка
не обходит весь репозиторий: архивные исходники, templates и внешние репозитории
рядом с MetaFor не становятся участниками автоматически.

Текущие библиотеки визуальной среды принадлежат canonical checkout Immersive.
Публичные package dependencies и корневые overrides связывают их с уже
зарегистрированными локальными Bun links. Глобальные регистрации и исходники
соседних проектов при установке MetaFor не изменяются.

Из корня репозитория:

```bash
bun install --frozen-lockfile --omit peer
```

## Архив Bulk

[Сохранённая реализация Bulk](../quantum/bulk/README.md#архивная-реализация)
архивирована на месте. Из активного workspace исключены:

* `quantum/bulk` вместе с `types`, `gravity`, `strong`, `weak`;
* связанный `pkg/visual`;
* старый server-package `quantum/dark`, чей browser-gateway импортирует Bulk;
* старый Universe launcher `cosmos/internal/supervisor`.

Их manifests и реализация остаются в репозитории. Отдельные packages
`quantum/dark/types` и `quantum/dark/gravity`, остальные библиотеки и проверки
Quantum сохраняют участие в активном составе. Архив не переносится во внешний
Production и не получает новых служебных полей `kind` или `status`.

Стандартные тесты и TypeScript discovery пропускают Bulk, его visual package,
старый supervisor, Dark server entrypoint и принадлежащий ему server test.
Интеграционные проверки Boundary, checkpoint, агентной сессии и Graph,
напрямую импортирующие Bulk, также относятся к сохранённому архивному контуру.
Остальные доменные тесты остаются активными.
Глобальный preload старого Bulk TSX больше не подключается. Проверки архива
сохраняются, но не объявляются пройденными в текущем окружении.

Команды `runtime:universe`, `runtime:universe:once`, `runtime:universe:logs` и
`visual:playground` сняты с рабочего корневого manifest. Восстановление этого
сохранённого контура требует отдельного согласования состава и зависимостей.

## Запуск Cosmos

Рабочий запуск и управление видимым контуром принадлежат
[штатному lifecycle MetaFor](../.agents/skills/metafor-dev/SKILL.md#lifecycle).
Из корня репозитория:

```bash
.agents/skills/metafor-dev/scripts/metafor-dev.sh status "$PWD"
.agents/skills/metafor-dev/scripts/metafor-dev.sh start "$PWD"
```

Cosmos запускает startup, выбранный release и internal Visual. Архив Bulk и
старый Universe не участвуют в этой цепочке. Выпуск, его проверка и обновление
следуют [порядку разработки Cosmos](../.agents/skills/metafor-dev/references/development.md).

## Boundary persistence

Development database по умолчанию:

```text
.metafor/dev.sqlite
```

Нестандартный путь Boundary задаёт `BOUNDARY_PATH`. Эти параметры сохранённого
Quantum-контура не запускают его вместе с Cosmos.

Изолированный test run может перенаправить flat Mass catalog, не касаясь
canonical live `mass/`:

```bash
METAFOR_MASS_PATH=/absolute/temporary/mass bun run test
```

Первый позиционный аргумент `../quantum/boundary/server.ts` имеет приоритет над
`BOUNDARY_PATH`. Parent directory создаётся автоматически. Boundary tests
используют отдельные `:memory:` databases и всегда закрывают их; development
database в tests не открывается.

## Локальная проверка

Рабочий toolchain закреплён в root manifest: Bun `1.4.0` и TypeScript
`7.0.2`. В проекте нет старого TypeScript compatibility package; проверки,
TSDoc и IDE используют один TS 7 contract.

Единый воспроизводимый contour:

```bash
bun run typecheck
bun run test
bun run check
```

`bun run test` задаёт недоступный `FORCE_ADDRESS`, отключает reconnect и
исключает `cluster/**` и перечисленный выше архив из test discovery, чтобы случайно запущенный development
contour и тесты внешних Atom-репозиториев не влияли на suites MetaFor.

Домены можно проверять отдельно без перечисления внутренних файлов:

```bash
bun test create-metafor
bun test boundary
bun test matrix
bun test energy
```

Проверки Matrix с WebGPU требуют устройства, способного выполнить настоящий
вычислительный проход. Его недоступность является невыполненной проверкой, а не
успешным результатом. TSDoc рядом с public contracts содержит ссылки на
конкретные сценарии, подтверждающие технические этапы жизненного цикла.

## Временная Meta

`create-metafor` остаётся active workspace. Генератор можно проверить во
временной директории:

```bash
tmpdir="$(mktemp -d)"
mkdir -p "$tmpdir/repositories"
bun run --filter create-metafor build
bun create-metafor/dist/cli.js capsule --dir "$tmpdir/repositories" --owner zavx0z --lang en
bun create-metafor/dist/cli.js capsule-profile --dir "$tmpdir/repositories" --owner zavx0z --lang en
bun build "$tmpdir/repositories/capsule/meta.ts" --outdir "$tmpdir/dist" --target browser --format esm
bun build "$tmpdir/repositories/capsule-profile/meta.ts" --outdir "$tmpdir/dist-profile" --target browser --format esm
rm -rf "$tmpdir"
```

Resolver разработки читает соседние Git-репозитории с корневым `meta.ts`.
Физический parent не входит в WIMP `src`; owner задаётся отдельно и сохраняется
в repository metadata. Установленная среда получает явное соответствие `src`
проверенным артефактам storage и не ищет исходный checkout.
Третьего сегмента и nested Meta repository нет; composition выполняется через
Meta/Matter/Oracle references. Оба вызова создают полный template, lockfile,
собственный Git и один `Initial commit`.
