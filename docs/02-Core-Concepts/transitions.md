# Переход в Quantum Atom

## Введение

Переход - это ключевой механизм управления изменением состояний в Quantum Atom. Они предоставляют гибкий и мощный способ описания логики изменения состояния системы, что является альтернативой классическим переходам в конечных автоматах.

## Концепция переходов

Переход описывает возможное изменение состояния системы. Переход учитывает контекст системы и состоит из трех ключевых компонентов:

1. Исходное состояние (`from`)
2. Набор целевых состояний (`to`)
3. Триггеры для каждого целевого состояния (подробнее о триггерах см. в [документации по триггерам](triggers.md))

> Для отслеживания изменений состояний см. [документацию по отслеживанию состояний](state-tracking.md)

Структура перехода выглядит следующим образом:

```typescript
interface Transition<C extends Context, S extends string> {
  from: S;
  to: TransitionTo<C, S>[];
}

interface TransitionTo<C extends Context, S extends string> {
  state: S;
  trigger: Trigger<C>;
}
```

## Преимущества переходов

1. **Контекстно-зависимые изменения состояния**: Переходы позволяют определять сложные условия изменения состояния на основе контекста системы.

2. **Декларативное описание логики**: Переходы позволяют описывать бизнес-логику декларативно, упрощая понимание и поддержку сложных систем.

3. **Масштабируемость и сопровождение**: Структура переходов позволяет легко добавлять новые состояния и условия изменения состояний без изменения существующей логики, а также упрощает поддержку системы.

4. **Возможность визуализации**: Структура переходов может быть представлена в виде графа, что позволяет эффективно анализировать и документировать логику изменения состояний.

## Правила срабатывания переходов

1. **Атомарность**: Все условия в триггерах должны выполняться одновременно для срабатывания перехода. (Подробнее о условиях триггеров см. в [документации по триггерам](triggers.md#условия-триггеров))
2. **Приоритетность**: Переходы проверяются в порядке их определения, срабатывает первый подходящий.
3. **Валидация**: Система выполняет проверку типов данных и соответствия условиям триггеров при обработке во время работы приложения. Это обеспечивает корректность данных в момент их фактического использования.

## Пример использования

Рассмотрим пример перехода для системы обработки заказов:

```typescript
const orderProcessingTransition = {
   from: "NEW_ORDER",
   to: [
      {
         state: "PROCESSING",
         trigger: {
            orderStatus: "confirmed",
            itemCount: {min: 1},
            totalAmount: {gt: 0}
         }
      },
      {
         state: "CANCELLED",
         trigger: {
            orderStatus: "cancelled",
            cancellationReason: {include: "customer_request"}
         }
      }
   ]
}
```

В этом примере:

- Состояние заказа изменяется на "PROCESSING", если триггер указывает, что он подтвержден, содержит хотя бы один товар и имеет положительную сумму.
- Состояние заказа изменяется на "CANCELLED", если триггер показывает, что статус "cancelled" и причина отмены включает "customer_request".

Подробнее о структуре и типах триггеров можно узнать в [документации по триггерам](triggers.md#типы-данных-контекста-для-триггеров).

## Лучшие практики

1. **Проектирование переходов**:

   - Начинайте с простых изменений состояний и постепенно усложняйте их при необходимости.
   - Группируйте связанные изменения состояний для лучшей читаемости.

2. **Отладка**:

   - Используйте режим отладки для просмотра процесса проверки переходов.
   - Тщательно тестируйте граничные случаи.

3. **Типизация**:
   - Определяйте четкие типы данных для контекста.
   - Документируйте ограничения и особенности каждого типа изменений состояний.

## Заключение

Система переходов в Quantum Atom предоставляет мощный инструмент для создания сложной логики изменения состояний. Она расширяет возможности классических конечных автоматов, позволяя описывать бизнес-процессы декларативно и учитывать широкий контекст системы, что упрощает разработку и поддержку сложных систем. Для полного понимания работы переходов рекомендуется также ознакомиться с [документацией по триггерам](triggers.md).
