# Процесс обновления в Quantum Atom

## Введение

Обновление контекста является ключевым механизмом в Quantum Atom, который запускает проверку триггеров и может привести к коллапсу (изменению состояния). В этом документе описан процесс обновления и его особенности в последней версии.

## Основной механизм обновления

Обновление контекста осуществляется через метод `update`, который принимает объект с новыми значениями параметров контекста:

```javascript
update({ key1: value1, key2: value2 })
```

Действие метода `update` включает несколько этапов:

1. **Валидация параметров** - проверка типов данных переданных параметров
2. **Обновление значений** - изменение значений параметров в контексте
3. **Запуск проверки триггеров** - анализ триггеров на предмет выполнения условий
4. **Выполнение коллапса** - если триггер активирован, выполняется коллапс (изменение состояния)

## Механизм блокировки процессов

Для предотвращения конфликтов при параллельном выполнении нескольких обновлений в Quantum Atom реализован механизм блокировки процессов:

```javascript
// В metafor.js
get process() {
  return this.#process
}

set process(value) {
  this.#process = value
}
```

Этот механизм работает следующим образом:

1. Перед началом обновления проверяется флаг `process` - если он активен, новое обновление откладывается
2. При старте обновления устанавливается флаг `process = true`
3. После завершения обновления (или в случае ошибки) флаг сбрасывается: `process = false`

```javascript
// Внутренний механизм в metafor.js
_updateExternal = ({ context, srcName = "core", funcName = "unknown" }) => {
  if (this.process) return // Блокировка при активном процессе

  this.process = true // Установка блокировки

  try {
    // Выполнение обновления
  } catch (error) {
    // Обработка ошибок
  } finally {
    this.process = false // Снятие блокировки в любом случае
  }
}
```

## Асинхронные операции

Механизм блокировки позволяет корректно обрабатывать асинхронные операции, предотвращая конфликты при обновлении контекста из нескольких источников. Для асинхронных операций рекомендуется следующий паттерн:

```javascript
actions({
  async fetchData({ update, core }) {
    try {
      const data = await core.api.getData()
      update({ result: data, status: "success" })
    } catch (error) {
      update({ error: error.message, status: "error" })
    }
  },
})
```

## Оповещение о изменениях

Для подписки на изменения контекста используется метод `onUpdate`:

```javascript
name.onUpdate(({context, previous}) => {
    console.log("Контекст изменен:", context, "Предыдущие значения:", previous)
})
```

Этот механизм позволяет внешним системам получать уведомления о изменениях в контексте атома.

## Лучшие практики

1. **Используйте метод `update` целенаправленно** - обновляйте только необходимые параметры контекста
2. **Обрабатывайте ошибки** - всегда оборачивайте код, который может вызвать исключения, в блок try-catch
3. **Используйте `core` для хранения временных данных** - не перегружайте контекст временными значениями
4. **Помните о блокировке** - проектируйте действия с учетом механизма блокировки процессов
5. **Следите за потоком обновлений** - избегайте циклических зависимостей в обновлениях контекста

## Взаимодействие с внешними системами

При интеграции с внешними системами важно помнить, что метод `update` является единственным правильным способом изменения контекста. Прямое изменение объекта контекста может привести к непредсказуемому поведению системы.

## Заключение

Процесс обновления в Quantum Atom представляет собой мощный механизм, обеспечивающий реактивность и предсказуемость системы. Понимание особенностей его работы и правильное использование позволяет создавать надежные и масштабируемые приложения.
