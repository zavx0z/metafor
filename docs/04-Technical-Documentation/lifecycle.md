# Жизненный цикл MetaFor

MetaFor — это фреймворк для управления состояниями в виде конечных автоматов, где **Контекст** служит единственным источником истины, а все переходы (коллапсы) происходят автоматически по триггерам. В этом документе описаны основные стадии жизненного цикла частицы, которые важно понимать при разработке приложений.

## Общие принципы

### Контекст как единственный источник истины

- Все процессы в частице работают в едином контексте, где состояния и действия взаимодействуют с общей моделью данных.
- Контекст можно обновлять в любой момент через метод `update(...)`.
- Любые изменения контекста могут привести к автоматическим переходам между состояниями.

### Триггеры и переходы между состояниями

- При входе в состояние, если оно имеет привязанное действие (Action), система временно блокирует триггеры, чтобы не произошло преждевременных переходов.
- Контекст может обновляться даже в заблокированном состоянии, но переход не произойдёт, пока триггеры заблокированы.
- Как только все действия завершаются, триггеры разблокируются, и система начинает реагировать на обновления контекста.

## Этапы жизненного цикла

### 1. Инициализация

При создании частицы:

```javascript
const todoParticle = MetaFor("todo-list")
  .states("IDLE", "LOADING", "SUCCESS", "ERROR")
  .context((t) => ({
    items: t.array({ default: [] }),
    isLoading: t.boolean({ default: false }),
    error: t.string({ default: null }),
  }))
  .transitions([
    /* ... */
  ])
  .actions({
    /* ... */
  })
  .create({
    state: "IDLE", // Начальное состояние
    context: {
      // Начальный контекст (опционально)
      items: [],
    },
  })
```

- Устанавливается начальное состояние и контекст.
- Если в начальном состоянии есть привязанное действие (Action), оно выполняется автоматически.

### 2. Выполнение действий (Actions)

Actions — это функции, которые автоматически вызываются при входе в состояние:

```javascript
.actions({
  loadItems: ({ update, core, setState }) => {
    update({ isLoading: true });

    // Асинхронная операция
    core.api.fetchItems()
      .then(items => {
        update({ items, isLoading: false });
        setState("SUCCESS");
      })
      .catch(error => {
        update({ error: error.message, isLoading: false });
        setState("ERROR");
      });
  }
})
```

- Действия автоматически вызываются при входе в состояние, если они указаны в конфигурации.
- Внутри действия можно обращаться к Core для работы с ресурсами (сети, таймеры и т.д.).
- Можно вызывать `update(...)` для изменения контекста.
- Можно использовать `setState(...)` для явного перехода в другое состояние.

> **Важно:** Actions не могут вызываться извне напрямую — только автоматически при входе в состояние.

### 3. Переходы между состояниями (Transitions)

Переходы между состояниями происходят автоматически при соблюдении условий триггера:

```javascript
.transitions([
  {
    from: "IDLE",
    to: [
      {
        state: "LOADING",
        trigger: {
          isLoading: true
        },
        action: "loadItems" // Действие, которое будет вызвано при входе в состояние LOADING
      }
    ]
  },
  {
    from: "LOADING",
    to: [
      { state: "SUCCESS", trigger: { items: { length: { gt: 0 } } } },
      { state: "ERROR", trigger: { error: { isNull: false } } }
    ]
  }
])
```

- После окончания действия система проверяет: какой триггер удовлетворён при текущем контексте?
- Если триггер срабатывает, совершается переход в новое состояние (возможно, с новым Action).
- Переходы могут происходить каскадно, если после перехода в новое состояние сразу же срабатывает другой триггер.

### 4. Внешние обновления контекста

Контекст частицы можно обновлять извне в любой момент:

```javascript
// Обновление контекста
todoParticle.update({
  items: [...todoParticle.context.items, { id: 1, text: "Новая задача" }],
})

// Получение текущего контекста
console.log(todoParticle.context)

// Получение текущего состояния
console.log(todoParticle.state)
```

- Любое обновление контекста может привести к автоматическому переходу в другое состояние, если выполнены условия триггера.
- Обновления контекста не блокируются, даже если частица находится в процессе выполнения действия.

## Работа с ресурсами (Core)

Core — это внутреннее «ядро» частицы, которое предоставляет доступ к внешним ресурсам и сервисам:

```javascript
.core(() => ({
  api: {
    fetchItems: async () => {
      const response = await fetch('/api/items');
      return response.json();
    },
    saveItem: async (item) => {
      const response = await fetch('/api/items', {
        method: 'POST',
        body: JSON.stringify(item)
      });
      return response.json();
    }
  },
  storage: {
    saveToLocalStorage: (key, data) => {
      localStorage.setItem(key, JSON.stringify(data));
    },
    getFromLocalStorage: (key) => {
      return JSON.parse(localStorage.getItem(key));
    }
  }
}))
```

- Core используется для работы с внешними ресурсами: API, таймеры, локальное хранилище и т.д.
- Методы Core доступны внутри Action через параметр `core`.
- Core не сериализуется и не передаётся между частицами.

## Практические рекомендации

1. **Используйте контекст как единственный источник истины** — все данные должны храниться в контексте.

2. **Делегируйте асинхронные операции в Actions** — не выполняйте их напрямую в обработчиках событий.

3. **Определяйте чёткие условия переходов** — триггеры должны быть понятными и предсказуемыми.

4. **Используйте Core для работы с внешними ресурсами** — это упрощает тестирование и поддержку кода.

5. **Обновляйте контекст только через `update()`** — не модифицируйте контекст напрямую.

## Заключение

Жизненный цикл MetaFor представляет собой последовательность переходов между состояниями, которые происходят автоматически при выполнении условий триггеров. Понимание этого цикла позволяет создавать предсказуемые и надёжные приложения, где логика состояний чётко отделена от представления.
