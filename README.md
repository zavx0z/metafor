# 🌌 MetaFor: Архитектура FSM в TAKT-ритме

MetaFor построен на разделении **смысла** и **механики**:

- **MONAD** — семантика, намерения, координация
- **BOUNDARY** — детерминированные вычисления переходов
- **BULK** — проявление, исполнение процессов, эффекты среды

---

## 🔷 Базовый принцип

FSM в MetaFor работает не как «последовательные if-ы по одному объекту», а как **пакетный ритм (TAKT)**.

Состояния эволюционируют синхронно:
1. закон вычисляет,
2. замысел интерпретирует,
3. действие исполняет,
4. цикл повторяется.

---

## 🌀 TAKT-цикл (точная логика)

## TAKT 0 — Рождение (undefined)

`createMonad()` создаёт монаду **без установленного текущего состояния**.

Это означает:
- текущее состояние ещё не проявлено,
- это нормальная фаза жизненного цикла.

На первом `updateBoundary()` появляется событие рождения:

- `oldState: undefined`
- `newState: <первое состояние суперпозиции>`

`oldState === undefined` — это **семантический маркер рождения**, а не ошибка.

---

## TAKT 1 — Boundary вычисляет переходы

BOUNDARY выполняет переходы для всех бран пакетно.

Для каждой браны:
1. читает текущее состояние,
2. применяет скомпилированные правила,
3. вычисляет `next_state`,
4. записывает новое состояние,
5. если состояние изменилось — ставит `dirty` и `lock`.

При фактическом переходе:
- помечается изменение,
- автоматически выставляется `lock = 1`.

---

## TAKT 2 — Monad проверяет намерение

MONAD получает пакет изменений и интерпретирует переход:

- если у `newState` **нет намерения** (`intention == null/undefined`)  
  → MONAD автоматически снимает lock;
- если намерение **есть**  
  → lock остаётся, переход передаётся в фазу действия.

---

## TAKT 3 — Weak/Bulk исполняет действие

Для состояний с намерением:
- исполняется процесс (`action`),
- обновляются поля/эффекты,
- по завершении вызывается `releaseLock()`.

---

## TAKT 4 — Boundary снова вычисляет

Следующий такт:
- разблокированные браны снова участвуют в вычислении,
- заблокированные временно пропускаются.

Цикл повторяется.

---

## 🔒 Механика lock: кто ставит и кто снимает

| Уровень | Ставит lock | Снимает lock |
|---|---|---|
| **BOUNDARY** | Автоматически при реальном переходе | Никогда |
| **MONAD** | Никогда | Автоматически, если нет намерения |
| **BULK / Weak** | Никогда | Явно после завершения процесса (`releaseLock`) |

---

## 📣 Семантика событий `onStateChange`

`onStateChange` возвращает **массив изменений за такт**.

Есть два типа событий:

1. **Birth-event**  
   `oldState === undefined`
2. **Runtime-transition**  
   `oldState !== undefined`

Для бизнес-реакций обычно нужны runtime-события:

```ts
const runtimeChanges = changes.filter(c => c.oldState !== undefined)
```

---

## 🧠 Ответственность слоёв

## MONAD (смысл и оркестрация)

- хранит имена состояний и полей,
- хранит намерения,
- фиксирует события переходов,
- решает, снимать lock или держать его,
- не выполняет GPU-вычисления.

## BOUNDARY (механика и детерминизм)

- вычисляет переходы по правилам,
- работает с числовым представлением,
- автоматически ставит lock при переходе,
- не знает «человеческого смысла» состояний.

## BULK (проявление)

- исполняет процессы,
- работает с эффектами среды и иерархией,
- снимает lock после завершения действия.

---

## 🌐 Масса (Mass) и локализация

В MetaFor масса — это не «свойство объекта», а **мера связи со средой исполнения**:

- накапливается в процессе выполнения,
- определяет, где должен исполняться процесс,
- не является частью механики переходов BOUNDARY.

---

## ✅ Практические правила

1. После создания монад запускайте `updateBoundary()`.
2. Не трактуйте `oldState: undefined` как сбой.
3. Явно разделяйте birth-события и runtime-переходы.
4. Для состояний с намерением держите lock до завершения процесса.
5. Для состояний без намерения lock снимается автоматически MONAD-слоем.
6. Думайте TAKT-пакетами, а не поштучными последовательными апдейтами.

---

## 🕯️ Итог

FSM в MetaFor — это ритм:

- **BOUNDARY** фиксирует закон изменения,
- **MONAD** интерпретирует намерение,
- **BULK** воплощает действие.

Так система остаётся детерминированной, масштабируемой и семантически прозрачной — включая фазу рождения из `undefined`.
