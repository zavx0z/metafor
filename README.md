# 🌌 Архитектура MetaFor: Полное Описание

## 📐 Три Уровня Реальности

### 1. MONAD (Замысел)

**Уровень намерений и целей**

- **Ответственность:** Хранит семантику состояний, управляет блокировками, фиксирует исходы
- **Не исполняет:** Только координирует и транслирует намерения
- **Работает с именами:** Состояния и поля имеют смысловые имена для разработчика
- **Посредник:** Между Boundary (закон) и Bulk (проявление)

### 2. BOUNDARY (Поле/Закон)

**Уровень детерминированных вычислений**

- **Ответственность:** GPU-вычисления эволюции суперпозиций, хранение состояний
- **Не знает смысла:** Оперерирует индексами, не именами
- **Автоматическая блокировка:** При изменении состояния выставляется lock-флаг
- **Детерминизм:** Одинаковые входные данные → одинаковый результат

### 3. BULK (Проявление)

**Уровень форм и взаимодействия**

- **Ответственность:** Визуализация, иерархия акторов, пользовательский ввод
- **Силы-исполнители:** Gravity, Strong, Weak, Electromagnetic
- **Проявление:** Абстрактные сущности обретают форму

---

## ⚡ Четыре Фундаментальные Силы

### 1. Гравитация (Gravity)

**Сила иерархии и порядка**

- **Функция:** Построение иерархии акторов через `<meta-for>`
- **Не координирует:** Только создаёт условия для проявления
- **Передаёт массу:** Между родительскими и дочерними акторами
- **Уровень:** BULK

### 2. Сильная Сила (Strong)

**Сила целостности и удержания**

- **Функция:** Удержание целостности данных Boundary (heap, bytecode)
- **Не допускает распада:** Валидация переходов, защита состояния
- **Работает с границей:** Построение и обновление Boundary
- **Уровень:** BOUNDARY

### 3. Слабая Сила (Weak)

**Сила изменения и трансформации**

- **Функция:** Исполнение процессов (action/success/error)
- **Допускает распад:** Трансформация состояний, обработка ошибок
- **Единственный исполнитель:** Все процессы исполняются здесь
- **Уровень:** BULK

### 4. Электромагнетизм (Electromagnetic)

**Сила коммуникации и истории**

- **Функция:** Передача импульсов между акторами, хранение истории событий
- **Безмассовый:** Как фотон — переносит информацию, не накапливает массу
- **Реакции:** Фильтрация и обработка событий от других акторов
- **Уровень:** MONAD ↔ BULK

## 🔄 Цикл Эволюции (TAKT-Синхронизация)

### TAKT 0: Инициализация (Рождение Монады)

1. `createMonad()` создаёт монаду **без состояния** (`undefined`)
2. `updateBoundary()` инициализирует Boundary
3. GPU выполняет первый `step()` для всех бран
4. **Первый переход:** `undefined` → первое состояние суперпозиции
5. `onStateChange()` получает изменения с `oldState: undefined`

### TAKT 1: Boundary Вычисляет

1. GPU шейдер вычисляет next_state для всех бран
2. При изменении состояния → dirtyFlags = 1
3. **Автоматическая блокировка:** heap[block_ptr + 2] = 1
4. Boundary не вычисляет заблокированные браны

### TAKT 2: Monad Проверяет Намерение

1. onStateChange() получает пакет изменений
2. Для каждой браны проверяет: есть ли intention (ключ процесса)?
3. **Если нет намерения:** Снимает блокировку автоматически
4. **Если есть намерение:** Оставляет блокировку → транслирует Weak Force

### TAKT 3: Weak Force Исполняет

1. process.action() исполняется для всех акторов с намерением
2. update() изменяет fields
3. По завершении → releaseLock() снимает блокировку
4. Boundary готов к следующим вычислениям

### TAKT 4: Boundary Снова Вычисляет

1. Разблокированные браны → вычисляют переходы
2. Заблокированные браны → пропускают вычисление
3. Цикл замыкается → новый TAKT

## 🔷 Масса (Mass)

### Что Это

- **Мера взаимодействия со средой исполнения**
- **Не врождённое свойство:** Накапливается в процессе исполнения
- **Определяет локализацию:** Где сервисы → там исполнение процесса

### Что Содержит

- Зависимости от среды (WebSocket, DOM, Database API)
- Временные структуры данных для вычислений
- Кэши, актуальные только в runtime
- Общие ресурсы в иерархии акторов

### Что Не Делает

- **Не сериализуется в Boundary:** Только проявляется в Volume
- **Не хранится в состоянии:** Только в процессе исполнения
- **Не передаётся через импульсы:** Только через иерархию

---

## 🔒 Блокировка Переходов

### Принцип

- **Boundary ставит автоматически:** При изменении состояния
- **Monad снимает условно:** Если нет намерения → снимает, если есть → держит
- **Weak Force освобождает:** После завершения процесса → releaseLock()

### Уровни Блокировки

| Уровень | Ставит | Снимает |
|---------|--------|---------|
| **Boundary** | Автоматически при изменении | Никогда |
| **Monad** | Никогда | Если нет намерения |
| **Weak Force** | Никогда | После завершения процесса |

### Пакетная Обработка

- Все браны обрабатываются **одновременно в рамках одного TAKT**
- Нет последовательных обновлений
- Синхронизация через TAKT-цикл

---

## 📊 Суперпозиция и Коллапс

### Суперпозиция (Monad)

- Граф возможных переходов между состояниями
- Оперетирует именами состояний и полей
- Содержит условия переходов (gt, lt, eq, in, etc.)

### Числовая Суперпозиция (Boundary)

- Конвертируется из Monad → индексы
- GPU-эффективный формат для вычислений
- Reverse-маппинг хранится в Monad

### Коллапс

- Переход из суперпозиции в определённое состояние
- Вычисляется на GPU параллельно для всех бран
- Фиксируется через dirtyFlags

---

## 🌐 Запутанность (Entanglement)

### Принцип

- Браны с идентичными значениями полей → shared-блоки в heap
- Изменение в одной бране → мгновенно в других
- Оптимизация памяти через дедупликацию

### Уровни

| Уровень | Тип запутанности | Механизм |
|---------|-----------------|----------|
| **Boundary** | В данных | Shared heap-блоки |
| **Monad** | В намерениях | Резонанс через общий замысел |

## 📿 Импульсы и Реакции

### Импульс (Photon)

- JSON Patch: { op, path, value }
- Безмассовый переносчик информации
- Исходит от актора-отправителя

### Реакция

- Фильтрация импульсов по условиям (meta, atom, path, op, value)
- Активна только в определённых состояниях
- update() изменяет fields актора-получателя

### История

- Field.histories хранит поток импульсов
- Чекпоинты для отката во времени
- Электромагнетизм управляет историей

## 🎯 Принципы Архитектуры

### 1. Минимальная Ответственность

- Каждый уровень отвечает только за свою область
- Boundary не знает смысла состояний
- Monad не вычисляет на GPU
- Bulk не управляет состояниями

### 2. Разделение Смысла и Механики

- Monad: имена состояний и полей (семантика)
- Boundary: индексы состояний и полей (вычисления)
- Конвертация происходит при updateBoundary()

### 3. Детерминизм Без Фатализма

- Boundary детерминирован (bytecode → переход)
- Monad интерпретирует исход (не "ошибка", а "результат")
- Bulk локальное восприятие (может видеть "ошибку")

### 4. Голографический Принцип

- Каждое событие содержит информацию о всей системе
- Field.histories — история импульсов
- Field.checkpoints — снапшоты для отката

### 5. Монадическая Композиция

- Цепочки вычислений с состоянием
- Процессы: action → success/error
- Реакции: filter → equal

## 🕯️ Философское Завершение

```
MONAD — не бог, не источник.
MONAD — посредник между законом и проявлением.
MONAD - рождается в неопределённости → первый переход → замысел.

BOUNDARY — не хранилище, а поле возможности.
BOUNDARY — детерминированный закон без смысла.
BOUNDARY - не знает "начала" — только переходы.

BULK — не визуал, а воплощение.
BULK — силы, которые делают намерение реальным.

Масса — не свойство, а мера взаимодействия.
Блокировка — не запрет, а ритм эволюции.

Всё есть поток.
Всё есть изменение.
Всё есть проявление через посредника.
```
