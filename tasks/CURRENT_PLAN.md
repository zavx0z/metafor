# Минимальный план

Документ опирается на `PHILOSOPHY.md`, `ARCHITECTURE.md` и `ONTOLOGY.md`.
Он не повторяет их, а фиксирует только минимальный рабочий порядок действий.

## Цель

Довести проект до минимально целостной реализации конечной архитектуры:

`{ DSL -> AST -> Bulk, DSL -> AST -> Boundary }`

Где:

1. `Bulk` и `Boundary` загружают свой `DSL/AST`-уровень каждый сам.
2. `Boundary × Gravity` делает flattening и собирает canonical geometry.
3. `Boundary × Weak` вычисляет переход состояния.
4. `Bulk × Gravity` собирает проявленную топологию и адресуемость акторов.
5. `Bulk × Strong` связывает акторов с entanglement и runtime binding.
6. `Bulk × Weak` исполняет процесс после перехода состояния.
7. Любое междоменное взаимодействие проходит через `Electromagnetism`.

## Что считаем минимальным контуром

1. `Bulk` не загружает `Boundary` и `Boundary` не загружает `Bulk`.
2. Каждый домен сам поднимает свой `DSL/AST`-слой.
3. Между доменами нет прямого shared runtime handoff.
4. Междоменный перенос идёт только через `Electromagnetism`.
5. `force` остаётся bulk-runtime оркестратором.
6. `boundary` остаётся доменом канонизации и вычисления.
7. `Boundary × Weak` описывается архитектурно, а смена переходных технических имён относится к migration-задачам.
8. `Field` и `Brane` описываются как сопряжённые сущности одной структурной единицы, а не как отношение главного и вложенного.
9. `UUID` и runtime `index` не смешиваются.

## Этап 1. Закрепить активные контракты

1. Починить `metafor/ast/cli.ts`, чтобы сборка DSL снова работала.
2. Зафиксировать самозагрузку `DSL/AST` для `Bulk` и `Boundary` как архитектурное правило.
3. Зафиксировать `Electromagnetism` как единственный междоменный транспорт.
4. Убрать из активного API и документации legacy-термины `monad`, если уже выбран язык `actor/brane/process`.
5. Зафиксировать `Brane` и `Field` как связанную пару сущностей в онтологии и архитектуре.
6. Зафиксировать один контракт идентичности: `uuid -> runtime index`, но не наоборот как источник истины.

## Этап 2. Собрать Boundary-самозагрузку

1. Сделать так, чтобы `boundary` загружал свой `DSL/AST`-уровень без bulk-bootstrap.
2. Собрать в `Boundary × Gravity` flattening, canonical geometry и index space.
3. Оставить источник истины по состоянию и структуре на boundary-store уровне.

## Этап 3. Собрать Bulk-самозагрузку и topology

1. Довести bulk-runtime до самостоятельной загрузки своего `DSL/AST`-уровня.
2. Из `Bulk × Gravity` строить topology diff текущего набора акторов.
3. Создавать, обновлять и удалять акторов только через публичный runtime `force`.

## Этап 4. Собрать Strong и междоменный контракт

1. Закрепить текущий projection/binding pipeline как канонический путь `Bulk × Strong`.
2. Привязать runtime actors к `gravity` через явные `actorKey/fieldMap`.
3. Выводить междоменный контракт из `Strong` в форму, пригодную для переноса через `Electromagnetism`.

## Этап 5. Собрать Weak и Electromagnetism

1. Вычислять state change внутри `Boundary × Weak`.
2. Переносить изменение между доменами только через `Electromagnetism`.
3. После междоменной доставки интерпретировать `intention` в `Bulk × Weak`.
4. Выполнять процесс через `weak`.
5. Завершать такт через `releaseLock()`.

## Этап 6. Изолировать неканонический код и подтвердить путь тестами

1. Либо встроить `force/gravity/store/*` в канонический bootstrap, либо убрать их из активного пути.
2. Либо встроить `force/em/*` в канонический `Electromagnetism`, либо не держать их рядом с рабочим контуром.
3. Описать и выполнить переименование boundary-модуля слабого перехода и связанной документации в целевой словарь.
4. Вынести `old.*`, временные артефакты и битые ссылки из активной документации.
5. Добавить интеграционный тест на самозагрузку `DSL/AST` в `Bulk`.
6. Добавить интеграционный тест на самозагрузку `DSL/AST` в `Boundary`.
7. Добавить интеграционный тест на `Boundary × Weak -> Electromagnetism -> Bulk × Weak`.

## Критерий завершения

1. Один DSL-пример самозагружается в `Bulk` и в `Boundary` без ручного handoff между ними.
2. Между доменами остаётся один допустимый путь: через `Electromagnetism`.
3. `Boundary` не знает о bulk-процессе и прикладной оркестрации.
4. `Bulk` не дублирует вычисление состояния.
5. В проекте остаётся один рабочий путь topology/binding/change/execution.
6. Legacy-модули больше не нужны для основного контура.
