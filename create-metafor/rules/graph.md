# Правила построения графа зависимостей

## 🎯 Назначение

Документ описывает правила визуализации типов и связей между модулями `@dsl/meta` с помощью Draw.io.

---

## 1. Структура таблицы типов

### 1.1. Формат таблицы

Каждый тип из `@dsl/meta` представляется в виде таблицы с заголовком:

```
<TypeName> @dsl/meta
```

**Пример:**

```
Meta @dsl/meta
Mass @dsl/meta
```

### 1.2. Колонки таблицы

| Колонка | Ширина | Описание |
| ------- | ------ | -------- |
| property | ~110px | Имя поля типа |
| type | ~155px | Тип поля (с дженериками) |
| label | ~245px | Описание поля на русском |

### 1.3. Стиль элементов

| Элемент | Стиль |
| ------- | ----- |
| Заголовок таблицы | `shape=table;startSize=30;fontSize=16` |
| Строка таблицы | `shape=tableRow;horizontal=0` |
| Ячейка property | `shape=partialRectangle;align=left;fontSize=16` |
| Ячейка type | `shape=partialRectangle;fontSize=12` |
| Ячейка label | `shape=partialRectangle;align=left;fontSize=12` |

## 2. Правила именования

### 2.1. Заголовок таблицы

**Формат:**

```
<TypeName> @dsl/meta
```

**Примеры:**

- ✅ `Meta @dsl/meta`
- ✅ `Mass @dsl/meta`
- ✅ `ProcessesSchema @dsl/meta`
- ❌ `Meta` (без указания модуля)
- ❌ `@dsl/meta Meta` (неверный порядок)

### 2.2. Типы в колонке type

**Правила:**

1. **Примитивы:** `string`, `number`, `boolean`, `any`
2. **Опциональные:** `string?`, `ProcessesSchema?`
3. **Дженерики:** `Superposition<𝛴, ɸ>`, `ParseNode[]`
4. **Массивы:** `ParseNode[]`, `string[]`

**Примеры:**

```
string
string?
Superposition<𝛴, ɸ>
ProcessesSchema?
ParseNode[]
m?
```

## 3. Связи между таблицами

### 3.1. Типы связей

| Тип | Описание | Пример |
| --- | -------- | ------ |
| **Ссылка на тип** | Поле ссылается на другой тип | `mass` → `Mass` |
| **Вложенность** | Тип содержит другой тип | `Meta` содержит `ProcessesSchema` |

### 3.2. Визуализация связи

**Стиль ребра:**

```xml
style="edgeStyle=none;html=1;exitX=1;exitY=0.5;exitDx=0;exitDy=0;"
```

**Направление:**

- От строки с полем → к таблице типа
- Выход из правой границы строки (`exitX=1`)
- Вход в левую границу таблицы (по умолчанию)

**Пример:**

```xml
<mxCell id="96" style="edgeStyle=none;html=1;exitX=1;exitY=0.5;" edge="1" source="87" target="91"/>
```

Где:
- `source="87"` — строка `mass` в таблице `Meta`
- `target="91"` — таблица `Mass @dsl/meta`

---

## 4. Расположение на холсте

### 4.1. Координаты

**Правила:**

1. Таблицы не должны перекрываться
2. Связанные таблицы располагаются рядом
3. Источник связи → слева, целевая таблица → справа

**Пример:**

```
Meta @dsl/meta          Mass @dsl/meta
x: 250, y: -900         x: 790, y: -580
```

### 4.2. Размеры

**Таблица Meta:**

- Ширина: 510px
- Высота: 300px (9 строк × 30px + заголовок 30px)

**Таблица Mass:**

- Ширина: 240px
- Высота: 60px (1 строка × 30px + заголовок 30px)

## 6. Чек-лист перед сохранением

- [ ] Заголовок таблицы в формате `<TypeName> @dsl/meta`
- [ ] Три колонки: property, type, label
- [ ] Шрифт описания (label) = 12px
- [ ] Шрифт типа (type) = 12px для сложных типов
- [ ] Связи идут от строки поля к таблице типа
- [ ] Таблицы не перекрываются
- [ ] Все поля типа описаны в таблице

---

## 7. Экспорт в Draw.io

**Порядок действий:**

1. Создать таблицу через меню **Insert → Advanced → Table**
2. Задать стиль заголовка: `shape=table;startSize=30`
3. Заполнить строки данными
4. Создать связь через **Insert → Link → Arrow**
5. Задать стиль связи: `edgeStyle=none;exitX=1;exitY=0.5`
6. Сохранить файл `.drawio`

**Проверка:**

- Открыть файл в Draw.io
- Убедиться, что все связи корректны
- Проверить читаемость текста

## 8. Data Flow диаграммы

### 8.1. Назначение

Data Flow диаграммы показывают **поток данных** от входных типов к конечной структуре данных. В отличие от графа зависимостей, акцент делается на **выходных данных**, которые получаются после применения API.

### 8.2. Структура Data Flow

**Уровни диаграммы:**

```
┌─────────────┐     ┌─────────────┐     ┌─────────────────┐
│ Входные     │     │ Промежуточ- │     │ Выходные        │
│ типы        │ ──→ │ ные типы    │ ──→ │ данные          │
│ (Types)     │     │ (FieldType) │     │ (SchemaType)    │
└─────────────┘     └─────────────┘     └─────────────────┘
```

**Пример для `@dsl/meta`:**

```
Types @zavx0z/context    FieldType (выход)    SchemaType
┌──────────────┐         ┌──────────────┐     ┌─────────────┐
│ string       │───────→ │ string       │ ──→ │ SchemaType  │
│ number       │───────→ │ number       │ ──→ │ SchemaType  │
│ boolean      │───────→ │ boolean      │ ──→ │ SchemaType  │
│ enum         │───────→ │ enum         │ ──→ │ SchemaType  │
│ array        │───────→ │ array        │ ──→ │ SchemaType  │
└──────────────┘         └──────────────┘     └─────────────┘
```

### 8.3. Таблицы выходных данных

#### 8.3.1. Формат заголовка

Заголовок таблицы указывает **тип данных** без суффиксов `.required()` / `.optional()`:

**Примеры:**

- ✅ `string`
- ✅ `number`
- ✅ `boolean`
- ✅ `enum`
- ✅ `array`
- ❌ `string.required()` (избыточно)
- ❌ `FieldType<string>` (избыточно)

#### 8.3.2. Структура таблицы

Каждая таблица выходных данных имеет **три колонки**:

| Колонка | Ширина | Описание |
| ------- | ------ | -------- |
| property | ~100px | Имя поля структуры |
| type | ~100px | Тип поля |
| label | ~150px | Описание на русском |

**Пример для `string`:**

```
┌────────────────────────────────────────────┐
│ string                                     │
├───────────┬─────────────┬──────────────────┤
│ property  │ type        │ label            │
├───────────┼─────────────┼──────────────────┤
│ type      │ "string"    │ Тип поля         │
│ required  │ boolean     │ Обязательность   │
│ default   │ string?     │ Значение по ум.  │
└───────────┴─────────────┴──────────────────┘
```

#### 8.3.3. Типы полей

**Правила для колонки `type`:**

1. **Строковые литералы:** `"string"`, `"number"`, `"boolean"`, `"enum"`, `"array"`
2. **Булевы типы:** `boolean` (для поля `required`)
3. **Опциональные типы:** `string?`, `number?`, `boolean?`, `T?`, `T[]?`
4. **Дженерики:** `T`, `T[]`

**Примеры для всех типов:**

```typescript
// string
{ type: "string", required: boolean, default: string? }

// number
{ type: "number", required: boolean, default: number? }

// boolean
{ type: "boolean", required: boolean, default: boolean? }

// enum
{ type: "enum", values: T[], default: T? }

// array
{ type: "array", required: boolean, default: T[]? }
```

### 8.4. Стили для Data Flow

#### 8.4.1. Таблицы

| Элемент | Стиль |
| ------- | ----- |
| Заголовок | `shape=table;startSize=30;fontSize=16` |
| Строка | `shape=tableRow;horizontal=0` |
| Ячейка property | `shape=partialRectangle;align=left;fontSize=14` |
| Ячейка type | `shape=partialRectangle;fontSize=12` |
| Ячейка label | `shape=partialRectangle;align=left;fontSize=12` |

#### 8.4.2. Связи

**Стиль ребра:**

```xml
style="edgeStyle=none;html=1;exitX=1;exitY=0.5;exitDx=0;exitDy=0;"
```

**Направление:**

- От типа в таблице `Types` → к таблице выходных данных
- Выход из правой границы строки типа
- Вход в левую границу таблицы выходных данных

### 8.5. Расположение на холсте

**Правила:**

1. **Таблица Types** — слева (источник)
2. **Таблицы выходных данных** — справа (цель)
3. **Расстояние между таблицами** — ~100-200px
4. **Таблицы выходных данных** — группируются по 2 в ряд

**Пример компоновки:**

```
Types @zavx0z/context
┌─────────────────┐
│ string ─────────┼──→ string       ┌──→ number
│ number ─────────┼──→ number       │
│ boolean ────────┼──→ boolean      │
│ enum ───────────┼──→ enum         └──→ array
│ array ──────────┘──→ array
```

**Координаты (пример):**

```
Types:           x: 820,  y: -795,  w: 310px, h: 180px
string:          x: 1170, y: -480,  w: 350px, h: 120px
number:          x: 1550, y: -480,  w: 350px, h: 120px
boolean:         x: 1170, y: -330,  w: 350px, h: 120px
enum:            x: 1550, y: -330,  w: 350px, h: 120px
array:           x: 1170, y: -180,  w: 350px, h: 120px
```

### 8.6. Процесс создания Data Flow

**Пошаговая инструкция:**

1. **Определить входные типы**
   - Какие типы импортируются (например, из `@zavx0z/context`)
   - Создать таблицу `Types @zavx0z/context`

2. **Определить выходные структуры**
   - Какие данные получаются после применения API
   - Для каждого типа — отдельная таблица

3. **Создать таблицы выходных данных**
   - Заголовок: только название типа (`string`, `number`, ...)
   - Колонки: `property`, `type`, `label`
   - Заполнить поля структуры

4. **Создать связи**
   - От каждого типа в `Types` → к соответствующей таблице
   - Стиль: `edgeStyle=none;exitX=1;exitY=0.5`

5. **Расположить на холсте**
   - `Types` — слева
   - Выходные таблицы — справа, сгруппированы
   - Избегать перекрытий

6. **Проверить**
   - Все ли типы охвачены
   - Корректны ли типы полей
   - Читаемость текста

### 8.7. Чек-лист для Data Flow

- [ ] Заголовки таблиц без суффиксов `.required()` / `.optional()`
- [ ] Три колонки: property, type, label
- [ ] Строковые литералы в кавычках: `"string"`, `"number"`
- [ ] Опциональные типы: `string?`, `T?`, `T[]?`
- [ ] Связи от типов → к выходным таблицам
- [ ] Таблицы не перекрываются
- [ ] Шрифт описания (label) = 12px
- [ ] Шрифт типа (type) = 12px
