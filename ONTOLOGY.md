## 🏛 Детальное описание уровней

### **1. BOUNDARY — Полевой уровень (ткань реальности)**

**Философия:** Фундаментальный уровень существования. Поле содержит все возможные состояния материи, но не определяет, *какое* из них реализуется.

**Назначение:**

- Хранит все возможные состояния системы
- Вычисляет переходы между состояниями по законам (правилам)
- Не знает о смысле состояний — только чистая эволюция

**Ключевой принцип:** Boundary не знает о *смысле* состояний. Он лишь вычисляет переходы по законам (правилам).

---

### **2. MONAD — Душа (божественный замысел)**

**Философия:** Уровень намерений и целей. Monad определяет:

- **Кто я?** (процессы — action)
- **К чему стремлюсь?** (success/error обработчики)
- **Как реагирую на мир?** (реакции)
- **Какие пути доступны?** (суперпозиции состояний)

**Назначение:**

- Процессы — намерения действовать
- Реакции — отклик на события мироздания
- Состояния — возможные пути эволюции
- Стек импульсов — поток времени
- Блокировки — свобода воли

**Ключевой принцип:** Monad *использует* Boundary для вычисления состояний, но *определяет* какие состояния имеют смысл.

---

### **3. BULK — Царство форм (проявление)**

**Философия:** Уровень проявления. Здесь абстрактные сущности из Monad обретают форму и становятся видимыми/ощутимыми.

**Назначение:**

- Агенты — персонификации фундаментальных сил
- Визуализация — отрисовка состояний
- Взаимодействие — пользовательский ввод

**Агенты-силы:**

- **Gravity** — сила иерархии и порядка
- **Electromagnetic** — сила взаимодействия
- **Strong** — сила стабильности (удерживает состояние)
- **Weak** — сила изменения (допускает распад)

**Ключевой принцип:** Bulk *воплощает* сущности из Monad, используя данные из Boundary.

## 🎯 Пример: атом "git"

### Декларация (meta)

```typescript
import "@metafor/meta"

const meta = MetaFor("git")
  .context((t) => ({
    src: t.string.required("./tmp/edit.json", { label: "JSON-patch путь" }),
    patches: t.array.required<string>([], { label: "разделенные патчи" }),
  }))
  .states({
    коммит: { завершено: {} },
    завершено: null,
  })
  .core()
  .processes((process, destroy) => ({
    коммит: process()
      .action(({ context }) => { return {} })
      .success(({ update }) => update({ src: "", patches: [] })),
    завершено: destroy(),
  }))
  .reactions()
  .view()

export default meta
```

### Компиляция (build → JSON)

```json
{
  "name": "git",
  "states": { "коммит": { "завершено": {} }, "завершено": null },
  "context": {
    "src": { "type": "string", "required": true, "default": "./tmp/edit.json" },
    "patches": { "type": "array<string>", "required": true, "default": [] }
  },
  "processes": {
    "коммит": {
      "type": "action",
      "action": { "src": "({ context }) => { return {} }" },
      "success": { "src": "({ update }) => { update({ src: \"\", patches: [] }) }", "write": ["src", "patches"] }
    },
    "завершено": { "type": "finally", "before": { "src": "() => {}" } }
  },
  "brane": { ... },
  "braneSchema": { ... }
}
```

### Выполнение (monad + boundary)

```typescript
// Monad загружает JSON
const monad = new Monad(jsonSchema)

// Boundary инициализирует GPU
const boundary = new Boundary(device)
await boundary.init({ fields: json.braneSchema, branes: [json.brane] })

// Выполнение процесса
await monad.execute("коммит")

// Эволюция состояния
boundary.step()

// Измерение
const states = await boundary.getStates()
// => ["завершено"]
```

### Воплощение (bulk)

```typescript
// Создание агента
const gitAtom = Bulk.createAgent(json)

// Отрисовка
document.body.appendChild(gitAtom.render())

// Взаимодействие
gitAtom.on("commit", () => monad.execute("коммит"))
```

## 🌟 Принципы ТКП

### 1. Минимальная ответственность

Каждый уровень отвечает только за свою область:

- **Boundary** — вычисление переходов (не знает смысла)
- **Monad** — намерения и цели (не вычисляет GPU)
- **Bulk** — проявление и взаимодействие (не управляет состояниями)

### 2. Разделение пространства и иерархии

- **Boundary** — пространство состояний (голографическое хранилище)
- **Monad** — динамика и цели (управление эволюцией)
- **Bulk** — иерархия и порядок (агенты-силы)

### 3. Голографический принцип

Каждое событие (импульс) содержит информацию о всей системе:

- `Field.histories` — история импульсов
- `Field.checkpoints` — снапшоты для отката
- `rollbackSystem()` — путешествие во времени

### 4. Монадическая композиция

Цепочки вычислений с состоянием:

- Процессы: `action → success/error`
- Реакции: `filter → equal`
- Стек: `lock → step → resume`

## 📈 Эволюция архитектуры

### Было (atom)

```
@metafor/atom (смешанная ответственность)
├── Field, Fields — поле
├── Gravity — иерархия
├── EM — взаимодействие
├── Weak, Strong — процессы
└── Atom — воплощение
```

### Стало (разделение)

```
@metafor/monad (душа)
├── MetaFor — DSL
├── processes — намерения
├── reactions — отклики
├── states — пути
└── Weak, Strong — основа

@metafor/boundary (поле)
├── Boundary — GPU
├── BraneManager — память
├── RulesCompiler — байт-код
└── StringAtlas — строки

@metafor/bulk (формы)
├── Atom — сущность
├── GravityAgent — сила иерархии
├── ElectromagneticAgent — сила взаимодействия
├── virtual — визуализация
└── inspect — отладка
```

## 📚 Глоссарий

| Термин | Определение |
|--------|-------------|
| **Атом** | Единица действия и контекста, воплощённая сущность |
| **Брана** | Носитель данных поля в куче (heap) |
| **Голографический принцип** | Каждое событие содержит информацию о всей системе |
| **Декогеренция** | Проверка условий перехода между состояниями |
| **Импульс** | Событие изменения (JSON Patch) |
| **Коллапс** | Переход из суперпозиции в определённое состояние |
| **Монада** | Исполнительный механизм души (процессы, реакции) |
| **Поле** | Квантовое пространство всех возможных состояний |
| **Суперпозиция** | Граф возможных переходов между состояниями |
| **Чекпоинт** | Снапшот системы для отката во времени |
