# Онтология MetaFor

> Теория Квантового Программирования: эволюция архитектуры

## 🌌 Три уровня реальности

**BULK** — Царство форм и проявлений. "То, что мы видим — формы, цвета, движения"

**MONAD** — Сущность, божественный замысел. "То, что определяет КЕМ быть и КУДА стремиться"

**BOUNDARY** — Полевой уровень, квантовое пространство. "То, из чего соткана ткань бытия"

---

## 🏛 Детальное описание уровней

### BOUNDARY — Полевая граница (GPU-фасад)

**Философия:** Граница между классическим и квантовым мирами. Boundary управляет полями и бранами, вычисляя переходы между состояниями на GPU.

**Структура:**

* **Fields (поля)** — Статика: схема типов полей для GPU
* **Branes (браны)** — Динамика: возмущения квантовых полей с params, state, superposition

**Назначение:**

* Хранит схему полей (fields) — типы для GPU
* Управляет бранами (branes) — носителями данных
* Вычисляет переходы между состояниями по законам (правилам)
* Не знает о смысле состояний — только чистая эволюция

**Ключевой принцип:** Boundary не знает о *смысле* состояний. Он лишь вычисляет переходы по законам (правилам).

---

### MONAD — Сущность (божественный замысел)

**Философия:** Уровень намерений и целей. Monad определяет:

* **Кто я?** (процессы — action)
* **К чему стремлюсь?** (success/error обработчики)
* **Как реагирую на мир?** (реакции)
* **Какие пути доступны?** (суперпозиции состояний)

**Назначение:**

* Процессы — намерения действовать
* Реакции — отклик на события мироздания
* Состояния — возможные пути эволюции
* Стек импульсов — поток времени
* Блокировки — свобода воли

**Ключевой принцип:** Monad *использует* Boundary для вычисления состояний, но *определяет* какие состояния имеют смысл.

---

### BULK — Царство форм (проявление)

**Философия:** Уровень проявления. Здесь абстрактные сущности из Monad обретают форму и становятся видимыми/ощутимыми.

**Назначение:**

* Агенты — персонификации фундаментальных сил
* Визуализация — отрисовка состояний
* Взаимодействие — пользовательский ввод

**Агенты-силы:**

* **Gravity** — сила иерархии и порядка
* **Electromagnetic** — сила взаимодействия
* **Strong** — сила стабильности (удерживает состояние)
* **Weak** — сила изменения (допускает распад)

**Ключевой принцип:** Bulk *воплощает* сущности из Monad, используя данные из Boundary.

---

## 🔄 Цикл существования

**META (DSL)** → Язык описания сущностей

**BUILD (компилятор)** → Трансляция деклараций в промежуточный формат

**MONAD (сущность)** → Выполняет процессы, реагирует на события, управляет переходами

**BOUNDARY (поле)** → Вычисляет эволюцию суперпозиций, измеряет состояния

**BULK (формы)** → Воплощённая сущность, агенты, визуализация

---

## 📊 Архитектура

### MONAD (сущность)

* Processes — намерения (action/success/error)
* Reactions — отклики на события
* States — граф переходов (decoherence)
* **Superposition** — формат суперпозиции с именами состояний и полей

### BOUNDARY (поле)

* GPU — вычисление эволюции суперпозиций
* Branes — носители данных (params, state, superposition)
* **NumericSuperposition** — формат суперпозиции с числовыми индексами

### BULK (формы)

* Agents — персонификации сил (Gravity, Electromagnetic...)
* Render — визуализация и взаимодействие

## 🔌 Интерфейсы между уровнями

### Почему разные форматы данных?

**Принцип соответствия:** Каждый уровень реальности использует формат данных, соответствующий его природе.

| Уровень | Формат | Почему |
| ------- | ------ | ------ |
| **MONAD** | `Superposition` (имена) | **Семантика.** Монада — это сущность с намерениями. Имена (`"IDLE"`, `"PATROL"`, `"hp"`) несут *смысл* для разработчика и DSL. |
| **BOUNDARY** | `NumericSuperposition` (индексы) | **Вычисления.** Boundary — это полевой уровень. Индексы (`0`, `1`, `2`) эффективны для GPU. Имена состояний хранятся в Monad для reverse-маппинга. |
| **BULK** | Визуальные формы | **Проявление.** Bulk — это царство форм. Агенты и визуализация требуют конкретных представлений (3D-модели, спрайты, цвета). |

### MONAD → BOUNDARY: Конвертация суперпозиции

**Конвертер:** `convertToNumeric(superposition, fieldNameIndex)`

**Что происходит:**

```typescript
// MONAD (смысл)
{
  IDLE: { PATROL: { hp: { gt: 50 } } },
  PATROL: null
}

// ↓ convertToNumeric()

// BOUNDARY (вычисления)
{
  transitions: [
    [{ to: 1, conditions: { 0: { gt: 50 } } }],  // Из IDLE → PATROL
    [null]                                        // PATROL — терминальное
  ]
}
```

**Reverse-маппинг (BOUNDARY → MONAD):**

Boundary возвращает индексы состояний: `[0, 1, 2]`

Monad хранит свою мапу для обратного преобразования:

```typescript
// Monad хранит: states: ["IDLE", "PATROL", "DEAD"]
const states = ["IDLE", "PATROL", "DEAD"]
const indices = [0, 2, 1]  // от Boundary

// Reverse-маппинг:
states.filter((_, i) => indices.includes(i))
// → ["IDLE", "DEAD", "PATROL"]
```

**Ключевой принцип:** Boundary не знает имён состояний — только индексы для GPU-вычислений. MONAD определяет *смысл* состояний, BOUNDARY вычисляет *переходы* между ними.

## 🌟 Принципы ТКП

### Минимальная ответственность

Каждый уровень отвечает только за свою область:

* **Boundary** — вычисление переходов (не знает смысла)
* **Monad** — намерения и цели (не вычисляет GPU)
* **Bulk** — проявление и взаимодействие (не управляет состояниями)

### Разделение пространства и иерархии

* **Boundary** — пространство состояний (голографическое хранилище)
* **Monad** — динамика и цели (управление эволюцией)
* **Bulk** — иерархия и порядок (агенты-силы)

### Голографический принцип

Каждое событие (импульс) содержит информацию о всей системе:

* `Field.histories` — история импульсов
* `Field.checkpoints` — снапшоты для отката
* `rollbackSystem()` — путешествие во времени

### Монадическая композиция

Цепочки вычислений с состоянием:

* Процессы: `action → success/error`
* Реакции: `filter → equal`
* Стек: `lock → step → resume`

## 📈 Эволюция архитектуры

**Было (atom)** — смешанная ответственность: Field, Gravity, EM, Weak, Strong, Atom

**Стало (разделение):**

* **monad (сущность)** — MetaFor DSL, processes, reactions, states, Weak, Strong
* **boundary (поле)** — Boundary GPU, BraneManager, RulesCompiler, StringAtlas
* **bulk (формы)** — Atom, GravityAgent, ElectromagneticAgent, virtual, inspect

## 📚 Глоссарий

| Термин | Определение |
| ------ | ----------- |
| **Атом** | Единица действия и контекста, воплощённая сущность |
| **Boundary** | Полевая граница — GPU-фасад для вычисления состояний |
| **Брана** | Возмущение квантовых полей. Содержит: superposition, state, params |
| **build** | Компилятор: преобразует MetaFor DSL → MonadJson |
| **Fields (boundary)** | Технические типы для GPU: `{ type: FieldType.F32, options?: {...} }` |
| **Fields (monad)** | Семантика для ИИ: `{ type, required, label, default }` |
| **MonadJson** | Формат JSON для monad: `{ fields, superposition, processes, reactions }` |
| **Superposition** | Формат суперпозиции уровня MONAD (имена состояний и полей). Несёт *смысл* для разработчика. |
| **NumericSuperposition** | Формат суперпозиции уровня BOUNDARY (числовые индексы). Эффектен для GPU-вычислений. |
| **convertToNumeric()** | Конвертер: `Superposition → NumericSuperposition`. Переводит смысл в индексы. |
| **params** | Значения полей (извлекаются из `fields[].default`) |
| **state** | Текущее состояние браны (одно из суперпозиции) |
| **superposition** | Все возможные состояния браны + граф переходов между ними |
| **FieldType** | Числовые типы для GPU: `F32`, `BOOL`, `STRING_PTR`, `ARRAY_PTR`, `U32` |
| **convertAllFields()** | Функция преобразования строковых типов в FieldType |
| **Голографический принцип** | Каждое событие содержит информацию о всей системе |
| **Декогеренция** | Проверка условий перехода между состояниями |
| **Импульс** | Событие изменения (JSON Patch) |
| **Коллапс** | Переход из суперпозиции в определённое состояние |
| **Монада** | Исполнительный механизм сущности (процессы, реакции) |
| **Поле** | Квантовое пространство всех возможных состояний |
| **Чекпоинт** | Снапшот системы для отката во времени |
