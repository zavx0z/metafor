# Онтология MetaFor

> Теория Квантового Программирования: эволюция архитектуры

## 🌌 Три уровня реальности

**BULK** — Царство форм и проявлений. «То, что мы видим — формы, цвета, движения»

**FORCE** — Взаимодействие и эмерджентные акторы. «То, что определяет КАК действовать и КУДА стремиться»

**BOUNDARY** — Полевой уровень, квантовое пространство. «То, из чего соткана ткань бытия»

---

## 🏛 Детальное описание уровней

### BOUNDARY — Полевая граница (GPU-фасад)

**Философия:** Граница между классическим и квантовым мирами. Boundary управляет полями и бранами, вычисляя переходы между состояниями на GPU.

**Структура:**

- **Fields (поля)** — Статика: схема типов полей для GPU
- **Branes (браны)** — Динамика: возмущения квантовых полей с params, state, superposition

**Назначение:**

- Хранит схему полей (fields) — типы для GPU
- Управляет бранами (branes) — носителями данных
- Вычисляет переходы между состояниями по законам (правилам)
- Не знает о смысле состояний — только чистая эволюция

**Ключевой принцип:** Boundary не знает о *смысле* состояний. Он лишь вычисляет переходы по законам (правилам).

---

### FORCE — Взаимодействие (эмерджентные акторы)

**Философия:** Уровень намерений и целей. Force определяет:

- **Кто я?** (процессы — action)
- **К чему стремлюсь?** (success/error обработчики)
- **Как реагирую на мир?** (реакции)
- **Какие пути доступны?** (суперпозиции состояний)

**Назначение:**

- Процессы — намерения действовать
- Реакции — отклик на события мироздания
- Состояния — возможные пути эволюции
- Стек импульсов — поток времени
- Блокировки — свобода воли

**Ключевой принцип:** Force *использует* Boundary для вычисления состояний, но *определяет* какие состояния имеют смысл.

**Актор как эмерджентное свойство:** Актор — это не сущность, а эмерджентный паттерн взаимодействия сил. Актор возникает из комбинации:
- Поля данных (Boundary)
- Процессы и намерения (Force)
- Визуальное проявление (Bulk)

---

### BULK — Царство форм (проявление)

**Философия:** Уровень проявления. Здесь абстрактные взаимодействия из Force обретают форму и становятся видимыми/ощутимыми.

**Назначение:**

- Визуализация — отрисовка состояний
- Взаимодействие — пользовательский ввод

**Компоненты BULK:**

- **gravity** — визуализация иерархии акторов через `<meta-for>`
- **view** — CSS-стили компонента

**Ключевой принцип:** Bulk *воплощает* взаимодействия из Force, используя данные из Boundary.

---

## 🔄 TAKT-цикл (актуальная модель)

### TAKT 0 — updateBoundary(): Commit + Birth

- Синхронизация топологии акторов в Boundary
- Birth-events: oldState === undefined
- НЕ выполняет runtime-переходы
- Эмитит сигналы создания

### TAKT 1 — updateActors(): Runtime evolution

- Применение обновлений полей
- Выполнение шага FSM в Boundary
- Формирование runtime-events при изменении состояния

### TAKT 2 — Интерпретация в FORCE

- Birth: инициализационная оркестрация
- Runtime: проверка intention → auto-unlock или удержание lock

### TAKT 3 — Исполнение в FORCE

- Выполнение процессов (action)
- releaseLock() после завершения

---

## ⏳ Lock как время

Lock — это не технический флаг блокировки. Это онтологический маркер **времени** в пространстве-времени Boundary.

### Свойства Lock как времени

| Свойство | Проявление в MetaFor | Физический аналог |
| -------- | -------------------- | ----------------- |
| **Однонаправленность** | Boundary ставит → Force снимает | Стрела времени |
| **Фиксация момента** | `lock = 1` замораживает эволюцию | Настоящее фиксировано |
| **Дискретность** | TAKT-цикл (шаги эволюции) | Планковское время |
| **Необратимость** | После `releaseLock()` нет возврата к старому состоянию | Энтропия |

### Boundary как пространство-время

- **Heap** — пространство (где находятся данные полей)
- **Lock** — время (когда зафиксировано состояние)
- **Bytecode** — законы физики (детерминированные правила эволюции)
- **TAKT** — квант времени (дискретный шаг эволюции)

**Lock = граница между «сейчас» и «потом».**

---

## 🔒 Lock Lifecycle (техническая спецификация)

| Слой | Ставит lock | Снимает lock | Механизм |
| ---- | ----------- | ------------ | -------- |
| **BOUNDARY** | При runtime-переходе (heap[block_ptr+2]=1) | Никогда | Авто-блокировка в шейдере |
| **FORCE** | Никогда | Если нет intention | _updateMatrixHeap(unlockUpdates) |
| **FORCE** | Никогда | Явно через releaseLock() | updateActors([{lock:false}]) |

## 🧠 Оптимизации Boundary

### StringAtlas

- Интернирование строк (UTF-32, один символ = одно u32)
- Сброс при write() — все string_id до сброса невалидны
- Двухступенчатое сравнение: hash → посимвольная проверка

### Dirty Flags

- Атомарные флаги изменений (1 u32 на брану)
- Экономия 90-99% readback bandwidth при разреженных изменениях
- In-place обновление states buffer (без копирования)

### Entangled Branes

- Shared блоки для бран с идентичными полями
- Оптимизация памяти при множественных клонах
- Автоматическое определение групп при prepareData()

### ARRAY Поля

- Временная зона в heap (резервирование при инициализации)
- Очистка после update() — данные не сохраняются между шагами
- Формат: [length, element1, element2, ...]

## 🔄 Цикл существования

**META (DSL)** → Язык описания взаимодействий

**BUILD (компилятор)** → Трансляция деклараций в промежуточный формат

**FORCE (взаимодействие)** → Выполняет процессы, реагирует на события, управляет переходами

**BOUNDARY (поле)** → Хранит поля/значения/коллапсы в `fields`, вычисляет эволюцию суперпозиций, измеряет состояния

**BULK (формы)** → Воплощённое взаимодействие, визуализация

**FORCE (силы)** → Применение эффектов, исполнение процессов

## 📊 Архитектура

### FORCE (взаимодействие)

- Processes — намерения (action/success/error)
- Reactions — отклики на события
- **Superposition** — граф переходов (decoherence) с именами состояний и полей
- **Fields** — схема полей (примитивы: string, number, boolean, enum, array)

### BOUNDARY (поле)

- GPU — вычисление эволюции суперпозиций
- Branes — носители данных (params, state, superposition)
- **NumericSuperposition** — формат суперпозиции с числовыми индексами

### BULK (формы)

- **gravity** — визуализация иерархии через `<meta-for>`
- **view** — CSS-стили компонента

### FORCE (силы)

- **force/gravity** — сила иерархии и порядка (чистая функция)
- **force/em** — сила взаимодействия (чистая функция)
- **force/strong** — сила стабильности (чистая функция)
- **force/weak** — сила изменения (чистая функция)

## 🔌 Интерфейсы между уровнями

### Почему разные форматы данных?

**Принцип соответствия:** Каждый уровень реальности использует формат данных, соответствующий его природе.

| Уровень | Формат | Почему |
| ------- | ------ | ------ |
| **FORCE** | `Superposition` (имена) | **Семантика.** Force — это взаимодействие с намерениями. Имена (`"IDLE"`, `"PATROL"`, `"hp"`) несут *смысл* для разработчика и DSL. |
| **BOUNDARY** | `NumericSuperposition` (индексы) | **Вычисления.** Boundary — это полевой уровень. Индексы (`0`, `1`, `2`) эффективны для GPU. Имена состояний хранятся в Force для reverse-маппинга. |
| **FORCE** | Чистые функции | **Эффекты.** Силы применяют эффекты к системе через чистые функции. |
| **BULK** | Визуальные формы | **Проявление.** Bulk — это царство форм. Визуализация требует конкретных представлений (3D-модели, спрайты, цвета). |

### FORCE → BOUNDARY: Конвертация суперпозиции

**Конвертер:** `convertToNumeric(superposition, fieldNameIndex)`

**Что происходит:**

```typescript
// FORCE (смысл)
{
  IDLE: { PATROL: { hp: { gt: 50 } } },
  PATROL: null
}
// ↓ convertToNumeric()
// BOUNDARY (вычисления)
{
  collapses: [
    [[1, { 0: { gt: 50 } }]],  // Из IDLE → PATROL (кортеж [to, conditions])
    [null]                      // PATROL — терминальное
  ]
}
```

**Reverse-маппинг (BOUNDARY → FORCE):**

Boundary возвращает индексы состояний: `[0, 1, 2]`
Force хранит свою мапу для обратного преобразования:

```typescript
// Force хранит: superposition: ["IDLE", "PATROL", "DEAD"]
const superposition = ["IDLE", "PATROL", "DEAD"]
const indices = [0, 2, 1]  // от Boundary
// Reverse-маппинг:
superposition.filter((_, i) => indices.includes(i))
// → ["IDLE", "DEAD", "PATROL"]
```

**Ключевой принцип:** Boundary не знает имён состояний — только индексы для GPU-вычислений. Force определяет *смысл* состояний, Boundary вычисляет *переходы* между ними.

## 🌟 Принципы ТКП

### Минимальная ответственность

Каждый уровень отвечает только за свою область:

- **Boundary** — вычисление переходов (не знает смысла)
- **Force** — намерения и цели (не вычисляет GPU)
- **Bulk** — проявление и взаимодействие (не управляет состояниями)

### Разделение пространства и иерархии

- **Boundary** — пространство состояний (голографическое хранилище)
- **Force** — динамика и цели (управление эволюцией)
- **Bulk** — иерархия и порядок (агенты-силы)

### Голографический принцип

Каждое событие (импульс) содержит информацию о всей системе:

- `Field.histories` — история импульсов
- `Field.checkpoints` — снапшоты для отката
- `rollbackSystem()` — путешествие во времени

### Монадическая композиция

Цепочки вычислений с состоянием:

- Процессы: `action → success/error`
- Реакции: `filter → equal`
- Стек TAKT-цикла: `commit(updateBoundary) → birth-signal → runtime-step(updateActors) → releaseLock`

---

## 🌐 Голографический принцип

**Определение:** Boundary хранит всю информацию о системе в голографической форме. Каждая брана содержит не только свои данные, но и связи со всей системой через запутанные поля.

### Проявления голографического принципа

| Аспект | Реализация |
| ------ | ---------- |
| **Heap** | Единое пространство данных, где каждая брана — возмущение поля |
| **Entangled Branes** | Shared блоки для бран с идентичными полями — информация дублируется системно |
| **StringAtlas** | Интернирование строк — каждое уникальное значение хранится в одном экземпляре |
| **Histories** | История импульсов — каждое событие содержит информацию об изменении всей системы |
| **Checkpoints** | Снапшоты для отката — возможность «путешествия во времени» |

### Двусторонняя связь BULK ↔ FORCE ↔ BOUNDARY

```text
BULK (проявление)
  ↕
  Принимает ввод пользователя → передаёт в FORCE
  Отображает состояния ← получает из FORCE
  
FORCE (взаимодействие)
  ↕
  Интерпретирует ввод → пишет в BOUNDARY
  Читает состояния ← получает из BOUNDARY
  
BOUNDARY (поле)
  ↕
  Хранит всю информацию в heap
  Вычисляет эволюцию по законам (bytecode)
```

**Ключевой принцип:** BULK принимает ввод пользователя, FORCE интерпретирует и пишет в Boundary, Boundary хранит состояние всей системы.

## 📈 Эволюция архитектуры

**Было (atom)** — смешанная ответственность: Field, Gravity, EM, Weak, Strong, Atom

**Стало (разделение):**

- **force (взаимодействие)** — MetaFor DSL, processes, reactions, superposition
- **boundary (поле)** — Boundary GPU, BraneManager, RulesCompiler, StringAtlas
- **force/** — фундаментальные силы (чистые функции): Gravity, EM, Weak, Strong
- **bulk (формы)** — gravity (визуализация), view (стили)

## 📚 Глоссарий

| Термин | Определение |
| ------ | ----------- |
| **Актор** | Эмерджентный паттерн взаимодействия сил (Force + Boundary + Bulk) |
| **Атом** | Единица действия и контекста, воплощённое взаимодействие |
| **Boundary** | Полевая граница — GPU-фасад для вычисления состояний |
| **Брана** | Возмущение квантовых полей. Содержит: superposition, state, params |
| **build** | Компилятор: преобразует MetaFor DSL → ActorJson |
| **Fields (boundary)** | Технические типы для GPU: `{ type: FieldType.F32, options?: {...} }` |
| **Fields (force)** | Семантика для ИИ: `{ type, required, label, default }` |
| **ActorJson** | Формат JSON для force: `{ fields, superposition, processes, reactions, bulk }` |

| **NumericSuperposition** | Формат суперпозиции уровня BOUNDARY (числовые индексы). Эффектен для GPU-вычислений. |

| **state** | Текущее состояние браны (одно из суперпозиции) |

| **Electromagnetic** | Фундаментальная сила взаимодействия (чистая функция в `force/em`) |
| **Strong** | Фундаментальная сила стабильности (чистая функция в `force/strong`) |
| **Weak** | Фундаментальная сила изменения (чистая функция в `force/weak`) |

| **Декогеренция** | Проверка условий перехода между состояниями |
| **Импульс** | Событие изменения (JSON Patch) |
| **Коллапс** | Переход из суперпозиции в определённое состояние |
| **Force (взаимодействие)** | Исполнительный механизм (процессы, реакции, намерения) |
| **Поле** | Квантовое пространство всех возможных состояний |
| **Чекпоинт** | Снапшот системы для отката во времени |
