# 🧩 @metafor/inspect — Отладка акторов

[← Главная](../../README.ru.md) | [English](README.md) | **Русский**

Инструмент для пошаговой отладки и анализа поведения акторов в MetaFor. Реализует три подхода к отладке асинхронного и параллельного кода, каждый из которых даёт разный уровень контроля над временем, контекстом и порядком выполнения.

---

## 🎯 Обзор подходов

| Подход                   | Цель                                | Ключевая идея                                           | Статус         |
| :----------------------- | :---------------------------------- | :------------------------------------------------------ | :------------- |
| **1. Depth‑First Trace** | Просмотр последовательности вызовов | Рекурсивный проход вглубь асинхронных цепочек акторов   | ✅ Реализовано |
| **2. Snapshot & Replay** | Анализ состояния во времени         | Сохранение снимков и воспроизведение истории выполнения | 🕓 В процессе  |
| **3. Logical Threads**   | Управление параллельными задачами   | Разделение асинхронных вызовов на логические потоки     | 🕓 В процессе  |

---

## 🔍 Подходы к отладке

### 1. Depth‑First Trace (реализовано)

**Проход вглубь** — линейное представление асинхронных вызовов акторов как единого стека.  
Асинхронные цепочки раскрываются рекурсивно, позволяя просматривать контекст выполнения «в глубину» без разрыва логики взаимодействия между акторами.

**Преимущества:**

- ✅ Удобно для анализа последовательности действий акторов
- ✅ Интегрировано с системой задач MetaFor (TaskType, Electromagnetic)
- ✅ Используется по умолчанию как основной режим трассировки

**Ограничения:**

- ⚠️ Не отражает реальный порядок исполнения (`event loop` остаётся вне модели)

### 2. Snapshot & Replay (в процессе)

**Снимки и откаты** — механизм записи состояния акторов и обратимых изменений (патчей) с возможностью воспроизведения.  
Позволяет «перематывать» выполнение к любой точке истории, анализировать побочные эффекты и состояние системы акторов во времени.

**Возможности:**

- ✅ Восстановление или повторение любой последовательности событий акторов
- 🕓 Реализация через `Field.getSnapshotByLastMessage()` и систему снимков акторов
- 🕓 Интеграция с системой контекстов и состояний MetaFor

**Требования:**

- ⚠️ Требует meta-акторов для большей части внешних ресурсов (WebSocket, таймеры и т. д.)

### 3. Logical Threads (в процессе)

**Логические потоки** — модель пошагового выполнения асинхронных задач как отдельных «виртуальных стеков».  
Виртуальные стеки - это и есть акторы. Возможность отладки ветки дерева графа взаимодействий между акторами.

**Возможности:**

- ✅ Детерминированное управление параллельными сценариями акторов
- ✅ Частично реализовано через систему задач и стек управления в `Electromagnetic`
- 🕓 Интеграция с системой состояний и переходов акторов

**Планы:**

- 📌 Полная интеграция с системой BroadcastChannel и межакторными сообщениями

## 🚀 Быстрый старт

### Веб-компонент `meta-inspect`

Веб-компонент для пошаговой отладки акторов в браузере с интуитивным интерфейсом управления.

#### Подключение

1. **Импорт модуля:**

   ```html
   <script type="module" src="@metafor/inspect/web/debugger"></script>
   ```

2. **Добавление компонента:**

   ```html
   <!-- с паузой на старте -->
   <meta-inspect brk></meta-inspect>

   <!-- без паузы на старте -->
   <meta-inspect></meta-inspect>
   ```

#### Атрибуты

- **`brk`** — при наличии ставит систему на паузу сразу после подключения компонента. Удаление атрибута снимает паузу

## ⚙️ Функциональность

### ✅ Реализовано

- **Элемент управления:** фиксированная панель с кнопками — «перезагрузка», «пауза/продолжить», «шаг»
- **Пауза/возобновление:** глобальная система акторов (`Atom.break()` / `Atom.resume()`)
- **Пошаговое выполнение:** следующего сообщения (`Atom.step()`)
- **Остановка на старте:** через атрибут `brk`
- **Индикатор состояния:** кнопка показывает действие — ▶ (возобновить), ⏸ (поставить на паузу)

### 🕓 В разработке

- [ ] **Замедление (slow‑mo):** пошаговое выполнение с задержкой
- [ ] **Интеграция логгера:** в дебаггер для детального анализа
- [ ] **Точки останова:** по параметрам сообщения (meta, atom, path, timestamp, src, patches)
