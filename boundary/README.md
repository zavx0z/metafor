# Boundary / Fields / Matrix — Stored Data Contract (Holographic Principle)

Этот проект **метафора-first**: метафора — это архитектурное правило, а не украшение.

## Онтология (метафора = правило)

- **Boundary** — это *граница/горизонт событий*.
  - Входящие структуры **флаттенятся**: иерархия исчезает, остаются отношения/индексы.
  - Flattening происходит **до** записи в Fields.

- **Fields** — это *слой отпечатка на границе*.
  - То, что записывается, **дедуплицируется** и уплотняется.
  - Deduplication происходит **в момент записи**.

- **Matrix** — это *исполнитель*.
  - Matrix потребляет уже готовый отпечаток.
  - CPU исполняет напрямую по индексным данным.
  - GPU строит буферы из тех же данных и считает на них.

## Инварианты

### 1) Инвариант глобального стора

Глобальный store Boundary должен содержать **только**:

- **Flattened + deduplicated** данные (итог Fields, отпечаток на границе)
- **Runtime-результаты**, которые Matrix пишет обратно (например, обновлённые состояния)

Глобальный store **не должен** содержать:

- промежуточные результаты flattening
- временные структуры подготовки
- backend-local буферы
- GPU-only payload
- объектные графы, которые можно было расплющить
- **packed execution forms** (heap, bytecode, blockPtrs) — это derived данные

### 2) Инвариант "ничего не лишнего"

Никакие данные не могут жить в глобальном store, если они:

- **не читаются Matrix**, и
- **не записываются Matrix** как результат вычисления.

Если значение не читается и не пишется Matrix — ему **нельзя** быть в global store.

### 3) Единый источник истины

**Boundary store — единственный источник истины** для обоих backend-ов:

- CPU читает его напрямую (indexed access)
- GPU строит буферы только из него через `deriveMatrixData()`

Никаких параллельных "скрытых" истин быть не должно.

**Критически важно:**
- `fieldSchema` НЕ хранится отдельно — схема в `boundary$.fields`
- `packed heap` НЕ хранится — это derived execution form
- `bytecode` НЕ хранится — это compiled execution form
- String atlas НЕ хранится — GPU материализует локально из `stringTable`

### 4) Инвариант derived data

Derived execution данные (heap, bytecode, blockPtrs, GPU buffers):

- **Никогда** не становятся источником истины
- **Всегда** пересчитываются из canonical store при необходимости
- **Не мутируют** canonical store — только читают

## Ответственность слоёв

### Boundary (flattening)

Boundary переводит DSL/объектный ввод в **плоскую реляционную форму**:

- объекты → индексы
- вложенность → relations
- transitions/conditions как object graph → flattened IR

Boundary может использовать локальные переменные/локальные структуры как промежуточные.

**Boundary не должен сохранять промежуточные структуры в global store.**

### Fields (deduplication + compaction)

Fields отвечает за:

- дедупликацию всего, что можно дедуплицировать
- уплотнение до минимального индексного представления
- производство финального **stored imprint**

Строки:

- Fields дедуплицирует строки в каноническую **string table**
- В stored data строки представлены только **индексами**
- Никаких GPU atlas/buffer export как канонического stored form
- UTF-32 packing и hash registry живут только в `matrix/gpu/*`

### Matrix (execution)

Matrix получает stored imprint (global store) и:

- CPU: исполняет напрямую по индексам
- GPU: строит буферы локально через `deriveMatrixData()` и исполняет на них

Matrix может писать в global store runtime-результаты (например, новые состояния).

**Matrix НЕ хранит separate schema truth** — всё читается из `boundary$.fields`.
**Matrix НЕ тянет implementation helpers из Fields** — derived packing живёт в `matrix/*`.

## Практический принцип (вес vs гибкость)

Stored imprint должен быть:

- максимально компактным
- индексным и дедуплицированным
- достаточно стабильным, чтобы эволюционировать без переписывания всего

Execution packing (особенно GPU buffers) должен происходить **как можно позже**,
чтобы contract оставался гибким и лёгким.

## Чеклист для ревью

1. Данные **флаттенятся** до Fields?
2. Данные **дедуплицируются** в Fields?
3. Каждое поле global store **читается или пишется Matrix**?
4. CPU может исполнять **напрямую по индексам**?
5. GPU строит буферы **только** из stored data?
6. Строки в stored data — **индексы**, а GPU конвертирует текст локально?
7. **Нет ли внешнего fieldSchema** вне boundary store?
8. **Нет ли packed heap/bytecode** как canonical truth?
9. **Не протекают ли GPU string packing / heap helpers обратно в Fields?**

Если хоть один пункт = "нет", изменение нарушает контракт.

## Архитектурные слои

```
┌─────────────────────────────────────────────────────────────┐
│                      Input (Data DSL)                       │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                    Boundary (flatten)                       │
│              flattenBoundaryData() → FlattenedBoundaryInput │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│              Fields (deduplicate + assemble)                │
│         assembleStoredBoundaryData() → BoundaryData         │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│              Boundary Store (canonical truth)               │
│  boundary$: { fields, stringTable, branes, states, ... }    │
└─────────────────────────────────────────────────────────────┘
                            ↓
        ┌───────────────────┴───────────────────┐
        ↓                                       ↓
┌──────────────────┐                  ┌──────────────────┐
│   CPU Runtime    │                  │   GPU Runtime    │
│  direct indexed  │                  │ deriveMatrixData │
│     execution    │                  │  → packed forms  │
└──────────────────┘                  └──────────────────┘
```
