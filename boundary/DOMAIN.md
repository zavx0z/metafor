# Доменный контракт Boundary

Boundary хранит канонический текущий мир. Он различает изменение существующего
Matter и его явное удаление.

## Идентичность Matter

Закон:

> `replace` изменяет тот же Matter. Только `remove` удаляет Matter.

Простой пример:

```text
Browser #10
├── Screenshot #11
└── Control #12
```

Если меняется только `Browser.energyBinding`, после commit остаются те же
`#10`, `#11`, `#12`. Дети по-прежнему ссылаются на `#10`.

Boundary поэтому не удаляет базовую строку `matter_particle` при `replace`:

1. проверяет нового родителя и запрещает цикл;
2. сохраняет `matter_particle.id`;
3. обновляет базовую строку на месте;
4. заменяет только subtype и bindings;
5. делает всё в одной SQLite transaction.

Удаление базовой строки и её каскад разрешены только для явного `remove`.

## Невмешательство в Process

Доменный закон: уже выполняющийся Process принадлежит своему Atom и должен
закончить начатую работу. Изменение декларации не имеет права отменить,
перезапустить или заменить его.

Текущий in-place fix полностью закрывает потерю дочерних деклараций и не
вызывает `removeMatterInstances` или `destroy`. Для обычной замены binding
существующий runtime сохраняется.

Настоящая смена `parent`, `kind`, WIMP `src` или topology-controller может
потребовать переноса materialized runtime. Этот случай пока не гарантирует
закон невмешательства и не считается готовым: перенос должен сохранить Atom и
Process identity, а не удалить старый runtime или создать второй.

## Проверка

Регрессия в `incremental.spec.ts` заменяет родительский Macho Matter с дочерним
Axion и конечным WIMP. Она проверяет неизменность всей ветки declaration IDs,
runtime origins, отсутствие утечки старого binding и чистый
`PRAGMA foreign_key_check`.
