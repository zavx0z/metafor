# Сборка

Сборка подготавливает полный граф артефактов объявленной версии пакета для его
окружений. Пакет задаёт публичные входы и ресурсы через `package.json#exports`.
Решение о необходимости подготовки версии и её публикация принадлежат
[выпуску](../release/README.md).

[Сценарий сборки](spec/scenario.spec.ts) раскрывает окружения, публичный граф,
development и production, compiler plugins, loaders и источники зависимостей.
[Исполнение запросов](spec/execution.spec.ts) описывает общую незавершённую
работу, разные цели, повтор и прерывание. [Ошибочные случаи](spec/failures.spec.ts)
задают недопустимые декларации, конфигурации и результаты компилятора.

Публичный `createPackageBuilder({resolvePackage, profile})` создаёт отдельный
сборщик. `preparePackage(name, {outdir, version})` готовит все окружения;
`buildPackage(name, options)` используется для отдельного окружения при
продолжении незавершённой подготовки. Разрешение имени в каталог задаёт
потребитель. Ожидающие сборки и общая проверка типов принадлежат экземпляру.

Компилятор запускается в дочернем Bun-процессе. Пакет владеет проверкой exports,
команд, loaders, plugins, полного графа outputs и внешних source maps.
Browser-safe identity API экспортируется отдельно через `/identity` и не
подключает серверный сборщик в браузер. Существующий формат `.cosmos` в адресах
артефактов и таблица `cosmos.package-build` сохранены как формат данных.

Основные примеры исполняют настоящий сборщик в изолированных каталогах.
Оставшиеся `test.todo` обозначают ещё не подключённые утверждения спецификации;
они не считаются пройденными проверками. Интеграционные регрессии Cosmos
проверяют тот же публичный API.


Фикстуры не входят в рабочий выпуск Cosmos. Их собственные TypeScript-проекты
проверяются отдельно от исходников MetaFor, чтобы локальные JSX-объявления
примеров не расширяли типы приложения.
