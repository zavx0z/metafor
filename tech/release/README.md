# Выпуск

Выпуск — подготовка и публикация полного согласованного состава версий пакетов.
Он имеет три варианта: первый выпуск, новый выпуск и продолжение прерванного.
Опубликованная версия пакета используется без повторной сборки. Доставка и
активация опубликованного выпуска принадлежат следующим процессам.

[Сценарий выпуска](spec/scenario.spec.ts) раскрывает первоначальный состав,
обновление одного пакета или группы и использование готовых версий.
[Продолжение публикации](spec/recovery.spec.ts) различает незавершённую новую
версию и уже опубликованный выпуск. [Ошибочные случаи](spec/failures.spec.ts)
проверяют сохранность предшественника и отказ от замены immutable bytes.
[Изменение версии](spec/versions.spec.ts), [совместимость зависимостей](spec/compatibility.spec.ts)
и [порядок запросов](spec/concurrency.spec.ts) раскрывают отдельные свойства той же операции.

Данные примеров описывают manifests, опубликованные и подготовленные артефакты,
запрос и возможный отказ внешней операции до начала исполнения. Это снимки
изолированных фикстур, а не утверждённый формат хранилища или публичный API.
Общие проверки объявлены один раз; частные группы выбираются по имени варианта.

`createRelease({root, builder, isMember})` создаёт механизм выпуска с собственной
очередью. `publishPackages(changes)` принимает patch/minor/major, а
`recoverPublication()` подготавливает первый состав либо продолжает root intent.
`releasedPackages()` ждёт окончания публикации и читает подтверждённый состав.
Cosmos передаёт свои политики через `server/services.ts`.

Подготовленные окружения и копии байтов сохраняются под `.release/` корня
потребителя до записи версий дочерних пакетов. Это внутреннее доказательство
выполненной подготовки, полученное из проверенного результата компилятора;
оно не заменяет авторский `exports` и не вводит новый browser manifest.
После перезапуска сохраняются окружения, публичные адреса, eager/lazy и карты
именно подготовленной версии, даже если текущие исходники уже изменены.

Готовая версия не пересобирается при запуске, изменении исходников или профиля,
потере JS либо map. Отсутствующие файлы восстанавливаются из копий с проверкой
SHA-256 и размера. Повреждённая или отсутствующая подтверждённая копия — ошибка.
Существующие артефакты прежнего формата принимаются по сохранённым байтам и
import edges; для этого компилятор не вызывается.

Именованные примеры первого выпуска, обновления и восстановления исполняют
публичный API на материализованных JSON-фикстурах. Проверки версий и
совместимости тоже исполняются. Оставшиеся `test.todo` — незавершённое
подключение отдельных утверждений,
а не доказательство поведения. Перенесённый API дополнительно проверяется
интеграционными тестами публикации, восстановления, конфликтов и доставки.
