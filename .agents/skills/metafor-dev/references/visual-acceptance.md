# Визуальная приёмка Bulk

Читайте этот файл только для живой проверки наблюдаемого результата.

## Подготовка

1. Доказать здоровье всех сервисов через `metafor-dev.mjs doctor`.
2. Если пользователь наблюдает разработку рядом с чатом, использовать браузер
   Codex и сделать его видимым.
3. Не открывать дублирующую вкладку Chrome, если пользователь явно не попросил
   Chrome.
4. Открыть или переиспользовать точную вкладку `http://localhost:4004/`.

## Базовая проверка

Проверить одним компактным чтением:

- URL и title `MetaFor`;
- `document.readyState === "complete"`;
- наличие canvas и ненулевые client dimensions;
- доступность WebGPU, если браузерная поверхность позволяет прочитать её
  напрямую; иначе успешную WebGPU-инициализацию подтвердить canvas, отсутствием
  ошибки bootstrap и runtime evidence;
- отсутствие новых browser errors;
- соединение browser Bulk с Force по runtime evidence.
- отсутствие панели Settings/Scene, статуса, Root SRC и ручного пересчёта;
- из служебного HUD допустима только кнопка полноэкранного режима.

Пустая сетка допустима, пока Meta не загружена. Чёрный экран без canvas,
ошибка WebGPU или отсутствующее соединение — неуспешная приёмка.

## Проверка изменения

До отправки Particle сформулировать ожидаемый причинный путь и видимое
проявление. После отправки проверить:

1. внешний вход;
2. решение центрального Force о релевантности;
3. движение к домену-владельцу;
4. ожидание, принятие или отклонение;
5. доменное повторное испускание;
6. подтверждённое последствие.

`inflaton-add` на каждом запуске использует новый SRC. Приёмка считается
успешной только после появления именно этого свежего Atom в canonical state и
его проявления в уже открытой вкладке Bulk без перезагрузки. Ранее созданный
Atom с тем же именем не является доказательством текущего причинного пути.

Boundary не должен предметно получать raw agent Inflaton, но Bulk должен
проявлять его путь к Dark. Наблюдение не превращает raw Particle в canonical
world state.

Для `meta-read` исходный `inflaton/test` должен проявиться только как вход к
Dark. Затем Bulk показывает отдельные сформированные Dark частицы по мере
послойного чтения; отдельного завершающего `inflaton/test` быть не должно.

Для `meta-remove` исходный `inflaton/remove path=wimp` также остаётся agent
входом к Dark. Boundary получает только переиспущенный Dark Inflaton и после
удаления не должен показывать Atom или declaration удалённого репозитория;
соседние репозитории сохраняются.

Если проверяется direct Field binding, изменение одного участника должно одним
видимым тактом обновить parent/children/siblings, использующие общий Value.
Промежуточное расхождение значений или повторное последовательное обновление
участников считается ошибкой.

## Evidence

- Для визуального суждения сначала одним предложением описать ожидаемый кадр.
- Делать один адресный screenshot или canvas capture, а не серию полных экранов.
- Сравнить ожидание с изображением и явно назвать расхождение.
- Логи прикладывать только как вторичное machine evidence.
- Оставить вкладку Bulk открытой, если пользователь продолжает наблюдение.
