# Workflow через GitHub Issues

Правила работы с задачами через GitHub Issues.

## Создание задачи (по явному запросу)

**Создание issue выполняется только по явному запросу пользователя.**

1. **Заголовок** — краткое описание (глаголы в верхнем регистре: РЕАЛИЗОВАТЬ, ИСПРАВИТЬ, УДАЛИТЬ)
2. **Описание** — цель, контекст, действия, ограничения, результат
3. **Метки** — при необходимости
4. **Project** — добавить в GitHub Project для трекинга

## Выполнение задачи

### 1. Обсуждение в issue (по явному запросу)

**Комментарии в issue добавляются только по явному запросу пользователя.**

- Фиксируй ключевые решения в комментариях
- Предложения по изменению контракта/архитектуры требуют обсуждения

### 2. Реализация

- Делай изменения в рабочей директории
- Пиши тесты для фиксации контракта (если применимо)

### 3. Коммит (по явному запросу)

**Коммит выполняется только по явному запросу пользователя** (например, «закоммить», «сделай коммит», «commit»).

Формат сообщения:

```
[тип/тип] область — описание

### Основные изменения:
- суть изменений строго из diff

### Улучшения кода:
- рефакторинг, конфиги, зависимости

### Исправления в тестах:
- только если изменены test/spec файлы
```

**Типы (приоритет):**

1. `feat` — новая функциональность
2. `fix` — исправление ошибки
3. `refactor` — рефакторинг без изменения поведения
4. `type` — изменения типов
5. `test` — добавление/изменение тестов
6. `docs` — документация

**Области:**

- `dark`, `boundary`, `bulk` — домены
- `metafor` — ядро (DSL, AST)
- `app` — приложения
- `tests` — интеграционные тесты
- `types`, `rules` — общие

**Важно:**

- Заголовок макс. 72 символа
- Порядок слов в описании совпадает с порядком типов
- `Refs #<number>` — привязка к issue (не закрывает)
- `Closes #<number>` — только при полном завершении

**Пример:**

```
[refactor/test] dark — удалить tag из Wimp и обновить тесты

### Основные изменения:
- Удалено поле tag из типа Wimp
- Обновлены JSDoc примеры

### Улучшения кода:
- Упрощён контракт частицы

### Исправления в тестах:
- Обновлены тесты wimp.test.ts

Refs #26
```

### 4. Пуш (по явному запросу)

**Пуш выполняется только по явному запросу пользователя** (например, «запушить», «сделай push»).

```bash
git push origin <branch>
```

GitHub автоматически прикрепит коммит к issue.

## Закрытие задачи (по явному запросу)

**Закрытие issue выполняется только по явному запросу пользователя.**

- Вручную после проверки
- Автоматически при `Closes #<number>`
