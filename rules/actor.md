Этот документ описывает этапы и правила создания конечного автомата с использованием **бесконечно-конечного автомата** и **акторной модели**.

## Этапы создания конечного автомата

### 1. Частица - Укажите название автомата

Задайте уникальное имя для вашего автомата, которое будет использоваться как идентификатор в системе. Имя должно быть в формате kebab-case.

### 2. states - Определите состояния

Составьте список всех возможных состояний вашего автомата. Каждое состояние должно быть четко описано.

### 3. context - Определите контекст

Контекст описывает параметры, определяющие текущее состояние системы. Укажите типы параметров и их значения по умолчанию.

### 4. transitions - Определите переходы

Определите правила переходов между состояниями, включая начальные и конечные состояния, триггеры и связанные действия.

### 5. core - Определите ядро (core)

Реализуйте основную логику взаимодействия с внешними системами и обработки событий. Типы данных указываются только в ядре, используя JSDoc. Другие части автомата не требуют явной типизации.

### 6. actions - Определите действия

Опишите логику выполнения операций при наступлении событий или переходов между состояниями. Название действия должно быть определено в переходах и не может вызываться извне. Действие автоматически срабатывает при входе в определенное состояние. Во время выполнения действия автомат блокируется и не может обрабатывать другие действия, пока текущее действие не завершится.

### 7. reactions - Определите реакции (необязательно)

Реакция срабатывает на изменение состояния другой частицы и может изменять только контекст текущей частицы. Реакции получают данные через **BroadcastChannel** в виде патчей и применяют их к контексту частицы.

### 8. view - Определите представление (View) (необязательно)

View представляет собой отображение данных из контекста и состояний частицы в пользовательском интерфейсе. Оно реализовано с использованием библиотеки с **JSX-подобным синтаксисом**, позволяя декларативно описывать реактивные изменения контекста и состояния частицы.

### 9. create - Соберите автомат

Соберите все компоненты в один автомат с помощью метода `create`. Можно исключать необязательные этапы, такие как реакции и представление (View), если они не требуются.

## Практические рекомендации

1. **Определяйте необходимые этапы создания частицы.** Частица может быть:

   - **Серверной** – без представления, работающей через соединения по **WebRTC, WebSocket или BroadcastChannel**. **BroadcastChannel** всегда доступен из коробки.
   - **Клиентской** – с представлением (View) в браузере или без него, работающей через **BroadcastChannel**, который доступен по умолчанию.
   - **Web Worker** – работающей в фоне браузера, обменивающейся данными через **BroadcastChannel**.
   - **Service Worker** – работающей в фоне браузера, обменивающейся данными через **BroadcastChannel**.

2. **Применяйте объект конфигурации** для динамического создания частиц или когда конфигурация может быть получена из внешнего источника.
3. **Определяйте начальное состояние и контекст** при создании частицы, чтобы избежать неопределенного поведения.
4. **Используйте реакции**, если необходимо, для создания частиц, которые взаимодействуют с другими частицами. Реакции получают обновления через **BroadcastChannel** и применяют их в виде патчей к контексту частицы.
5. **Добавляйте представление (View)**, если необходимо визуальное отображение данных. View реализовано с использованием **JSX-подобного синтаксиса**, позволяя декларативно описывать реактивные изменения контекста и состояния частицы.
6. **Применяйте пользовательские сервисы** для инкапсуляции внешних зависимостей и упрощения тестирования.
