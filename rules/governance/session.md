# Session History

This rule defines when and how to use prior discussion from the current work context.

## Purpose

Use session history only when it is needed to recover context, decisions, or prior constraints.

## When to apply

Use session history if:

- the user asks to remember or summarize prior discussion;
- the current request depends on earlier decisions;
- the user refers to something said earlier;
- you need to restore context after a long thread.

Do not use session history if:

- the request is self-contained;
- the user has clearly started a new topic;
- scanning history would add noise rather than clarity.

## Requirements

When using session history:

1. Identify the key topic or decision to recover.
2. Pull only the relevant prior points.
3. Summarize decisions, constraints, and unresolved questions.
4. Prefer conclusions over raw chronology unless the user asks for chronology.
5. Carry forward only information that is still relevant to the current task.

## Forbidden

Do not:

- dump long chat history;
- revive outdated context when the user changed direction;
- treat vague recollection as confirmed fact;
- overload the answer with unnecessary recap.

## Checklist

- [ ] History was needed for the task
- [ ] Only relevant prior context was used
- [ ] The summary reflects decisions, not noise
- [ ] Outdated context was not revived
