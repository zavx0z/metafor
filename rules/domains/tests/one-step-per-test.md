# Один шаг на тест

Если `describe` описывает сценарий или pipeline, каждый `test` должен фиксировать один отдельный шаг этого сценария.

## Правило

- один `test` = один шаг и одна точка проверки
- создание сущности, её дополнительная настройка и её использование не надо сливать в один тест, если это разные стадии
- generator создаётся отдельным тестом, а его проходы проверяются отдельными тестами
- уровни layer-generator проверяются по одному уровню на тест
- название теста должно совпадать с фактическим шагом: `create`, `assign`, `generate`, `store`

## Что это означает на практике

Правильная последовательность для сценарного теста выглядит так:

```ts
test("load", async () => {
  ast = await loadMetaAST(src)
})

test("create wimp", () => {
  wimp = new Wimp(src)
})

test("assign mass to wimp", () => {
  wimp = new Wimp(src)
  wimp.mass = ref.mass
})

test("create generator", () => {
  generator = particleGenerator(wimp, ast.matter, ast.fields)
})

test("generate first level", () => {
  const firstLevel = generator.next()
})

test("generate second level", () => {
  const secondLevel = generator.next()
})
```

## Зачем это нужно

- границы контракта читаются сразу
- проще видеть, на каком именно шаге сломалось поведение
- тест не маскирует две разные ошибки одной общей проверкой
- stateful flow остаётся линейным и прозрачным

## Что не делать

- не совмещать создание generator и проверку нескольких уровней в одном тесте
- не прятать отдельную стадию настройки сущности внутрь теста её создания, если это самостоятельный контракт
- не делать тест с именем одного шага, если внутри фактически проверяются два или три шага
