# Сообщение в каждом `expect`

Каждый `expect` в тесте должен принимать вторым аргументом короткое описание того, что именно проверяется.

## Правило

- писать `expect(actual, "что проверяется")`
- сообщение должно описывать смысл проверки, а не повторять matcher
- сообщение должно быть коротким и однозначным
- это правило относится к каждому assert-level `expect` в тесте

## Пример

```ts
expect(ast, "loadMeta должен вернуть ref").toEqual(ref)
expect(generator, "generator должен быть создан").toBeDefined()
expect(firstLevel.done, "первый слой не должен завершать generator").toBe(false)
```

## Зачем это нужно

- по падению сразу видно, какой именно контракт сломался
- длинные сценарные тесты читаются как список явных проверок
- смысл assert не теряется среди однотипных `toEqual` и `toBe`

## Что не делать

- не оставлять `expect(actual)` без пояснения
- не писать слишком общее сообщение вроде `должно работать`
- не дублировать matcher буквально, если из текста неясно, что именно проверяется
