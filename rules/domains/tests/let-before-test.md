# `let` перед тестами

Если одно и то же значение нужно нескольким тестам внутри одного `describe`, его надо объявлять как `let` в ближайшей общей области перед тестом, где оно впервые присваивается.

## Правило

- `let` не надо поднимать в начало всего `describe`, если он нужен только с середины сценария
- `let` объявляется прямо перед первым тестом, где значение впервые присваивается
- если значение не используется между тестами, его надо держать внутри конкретного теста как локальный `const`
- общий `let` нужен только для данных, которые реально переиспользуются дальше по цепочке тестов

## Зачем это нужно

- тесты читаются как последовательность шагов
- не приходится пересобирать один и тот же объект в каждом тесте
- промежуточный результат живёт ровно там, где он нужен, и не расползается на лишнюю область видимости

## Пример

```ts
describe("init", () => {
  let ast: MetaAST

  test("load", async () => {
    ast = (await loadMetaAST("zavx0z/git" as SRC)) as MetaAST
  })

  let wimp: Wimp

  test("create wimp", () => {
    wimp = new Wimp(src)
  })

  let generator: ReturnType<typeof particleGenerator>

  test("create ast generator first level", () => {
    generator = particleGenerator(wimp, ast.matter, ast.fields)
  })

  test("create ast generator second level", () => {
    const secondLevel = generator.next()
    expect(secondLevel.done).toBe(false)
  })
})
```

## Что не делать

- не выносить все `let` в начало `describe` по инерции
- не хранить в общем `let` значения, которые нужны только одному тесту
- не объявлять `let` ниже теста, где оно впервые присваивается
