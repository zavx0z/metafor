# trigger - Триггер для управления переходами

## Введение

Триггеры — это ключевой механизм в MetaFor, который определяет, при каких условиях происходит переход между состояниями. Они обеспечивают декларативное описание логики, гарантируя предсказуемость и простоту управления состояниями.

---

## Основные принципы работы триггеров

1. **Декларативность**  
   Триггеры описываются в виде условий, связанных с параметрами контекста. Это делает логику понятной и легко поддерживаемой.

2. **Единичность срабатывания**  
   В каждый момент времени система гарантирует, что может сработать только один триггер, исключая конфликты и неопределённость.

3. **Приоритет проверки**

   - Условие `isNull` проверяется в первую очередь.
   - Если `isNull: true`, остальные условия игнорируются.
   - Все условия триггера должны выполняться одновременно, чтобы произошёл переход.

4. **Валидация на этапе разработки**
   - Все триггеры проверяются на пересечения, чтобы исключить конфликты.
   - Обнаруженные ошибки устраняются до запуска системы, что упрощает отладку и гарантирует надёжность.

---

## Валидация триггеров

### Зачем это нужно?

- Обеспечить, чтобы триггеры не пересекались и система оставалась детерминированной.
- Исключить ситуации, когда несколько триггеров могут сработать одновременно для одного контекста.

### Принципы валидации

1. **Проверка пересечений**

   - Условия триггеров анализируются на возможность одновременного выполнения.
   - Если два триггера могут быть истинными при одном и том же контексте, они считаются пересекающимися.

2. **Решение конфликтов**

   - Пересекающиеся триггеры не допускаются в системе.
   - Разработчик должен вручную устранить пересечения или задать чёткие правила.

3. **Предотвращение ошибок в продакшне**
   - Ошибки логики триггеров устраняются на этапе создания, исключая проблемы во время выполнения.

---

## Определение триггеров

Триггеры определяются в параметре `trigger` перехода и представляют собой объект, описывающий условия для перехода:

```javascript
MetaFor("todo-list")
  .states("IDLE", "LOADING", "LOADED", "ERROR")
  .context((t) => ({
    items: t.array({ title: "Список элементов", default: [] }),
    isLoading: t.boolean({ title: "Состояние загрузки", default: false }),
    error: t.string({ title: "Сообщение об ошибке", nullable: true, default: null }),
  }))
  .transitions([
    {
      from: "IDLE",
      to: "LOADING",
      trigger: { isLoading: true }, // Триггер: переход произойдет, когда isLoading станет true
    },
    {
      from: "LOADING",
      to: "LOADED",
      trigger: { items: { length: { gt: 0 } } }, // Триггер: переход произойдет, когда длина массива items станет больше 0
    },
    {
      from: "LOADING",
      to: "ERROR",
      trigger: { error: { isNull: false } }, // Триггер: переход произойдет, когда error не будет null
    },
    {
      from: "ERROR",
      to: "IDLE",
      trigger: { error: null }, // Триггер: переход произойдет, когда error станет null
    },
  ])
// ...
```

## Типы Trigger

Для триггеров MetaFor определены декларативные типы, которые описывают возможные условия для каждого типа данных:

### EnumTriggerCondition

Условия триггера для enum:

- `eq`, `notEq`, `oneOf`, `notOneOf`, `isNull`.

```typescript
E[number] | null | {
  isNull?: boolean
  eq?: E[number]
  notEq?: E[number]
  oneOf?: E[number][]
  notOneOf?: E[number][]
}
```

### StringTriggerCondition

Условия триггера для строк:

- Проверка начала и конца строки, наличие подстроки, регулярное выражение, длина строки и др.

```typescript
string | RegExp | null | {
  isNull?: boolean
  startsWith?: string
  endsWith?: string
  include?: string
  pattern?: RegExp
  eq?: string
  notEq?: string
  notInclude?: string
  notStartsWith?: string
  notEndsWith?: string
  length?: number | {min?: number; max?: number}
  between?: [string, string]
}
```

### NumberTriggerCondition

Условия триггера для чисел:

- `gt`, `lt`, `eq`, `between` и др.

```typescript
number | null | {
  isNull?: boolean
  eq?: number
  gt?: number
  gte?: number
  lt?: number
  lte?: number
  notEq?: number
  notGt?: number
  notGte?: number
  notLt?: number
  notLte?: number
  between?: [number, number]
}
```

### BooleanTriggerCondition

Условия триггера для булевых значений:

- Проверка `eq`, `notEq`, `logicalEq`, `isNull`.

```typescript
boolean | null | {
  isNull?: boolean
  eq?: boolean
  notEq?: boolean
  logicalEq?: boolean
  notNull?: boolean
}
```

### Общий TriggerType

Тип для всего контекста:

```typescript
Partial<{
  [K in keyof C]: C[K] extends StringEnumDefinition<infer V>
    ? EnumTriggerCondition<V>
    : C[K] extends NumberEnumDefinition<infer V>
    ? EnumTriggerCondition<V>
    : C[K] extends StringDefinition
    ? StringTriggerCondition
    : C[K] extends NumberDefinition
    ? NumberTriggerCondition
    : C[K] extends BooleanDefinition
    ? BooleanTriggerCondition
    : C[K] extends ArrayDefinition
    ? any[] | { length: NumberTriggerCondition }
    : never
}>
```

## Особенности работы

1. **Единичность выполнения**  
   Только один триггер может сработать для заданного контекста. Это гарантируется валидацией.

2. **Блокировка во время выполнения действия**  
   Пока выполняется действие текущего состояния, триггеры временно блокируются, предотвращая переход в новое состояние.

3. **Публикация изменений**  
   После выполнения триггера изменения контекста и состояния публикуются для подписчиков.

---

## Преимущества подхода

1. **Простота управления**  
   Логика триггеров остаётся декларативной и легко читаемой.

2. **Детерминированность**  
   Гарантия, что система всегда ведёт себя предсказуемо.

3. **Минимизация ошибок**  
   Валидация триггеров на этапе разработки исключает ошибки в продакшне.

4. **Лёгкость отладки**  
   Чёткая структура и автоматическая проверка триггеров делают систему удобной для анализа.

---

## Итог

Триггеры в MetaFor — это мощный инструмент, который позволяет декларативно описывать изменения состояний. Благодаря валидации на этапе разработки и строгим правилам их работы, система остаётся надёжной, предсказуемой и легко масштабируемой. Такой подход обеспечивает высокое качество разработки и исключает большинство проблем, связанных с конфигурацией триггеров.
