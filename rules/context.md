# Контекст в MetaFor

Контекст является центральным элементом управления состояниями и данными в MetaFor. Он служит единым источником истины для частицы и определяет её поведение, а также автоматические переходы между состояниями.

---

## Введение

Контекст в MetaFor — это структура данных, на основе которой вычисляются состояния и выполняются переходы. Вместо того чтобы менять состояния напрямую или обрабатывать события императивно, MetaFor использует контекст как основу для декларативного описания поведения системы.

### Отличие от классического подхода

В классическом подходе:

- Состояние меняется в ответ на события.
- Логика переходов описывается условными операторами.
- Данные разбросаны по разным частям приложения.

В MetaFor:

- Состояние вычисляется напрямую из контекста.
- Логика переходов описывается декларативно с помощью триггеров.
- Контекст является единым источником всех данных, связанных с частицей.

Такой подход делает поведение системы прозрачным и предсказуемым.

---

## Структура контекста

### Определение типов

Контекст задаётся через метод `.context()`, принимающий функцию:

```javascript
Atom("user").context((t) => ({
  name: t.string({ title: "Имя пользователя", nullable: true, default: "Guest" }),
  age: t.number({ title: "Возраст", default: 18 }),
  role: t.enum("guest", "user", "admin")({ title: "Роль пользователя", default: "guest" }),
  tags: t.array({ title: "Теги", default: ["new"] }),
  isActive: t.boolean({ title: "Активен", default: true }),
}))
```

Обязательно указывайте параметр `title` для всех полей контекста — это упрощает генерацию документации и интерфейсов.

---

## Типы данных контекста

Контекст MetaFor определяется с использованием набора утилит типизации. Каждое поле должно иметь явное описание типа, значение по умолчанию и возможность быть `null`.

### Доступные типы

| Тип           | Описание                                               | Пример использования                                           |
| ------------- | ------------------------------------------------------ | -------------------------------------------------------------- |
| `t.string()`  | Строка                                                 | `t.string({ title: "Имя", default: "Гость", nullable: true })` |
| `t.number()`  | Число                                                  | `t.number({ title: "Возраст", default: 18 })`                  |
| `t.boolean()` | Булево значение                                        | `t.boolean({ title: "Активен", default: true })`               |
| `t.array()`   | Массив                                                 | `t.array({ title: "Теги", default: ["новый"] })`               |
| `t.enum()`    | Перечисление (enum), может быть строковым или числовым | `t.enum("user", "admin")({ title: "Роль", default: "user" })`  |

Все типы поддерживают параметры:

- **title** — описание поля (используется для документации и UI, указывать всегда).
- **default** — значение по умолчанию (обязательно для всех не-nullable полей).
- **nullable** — допускает значение `null`, если указано `true`.

### Nullable поля

Если поле описано с `nullable: true`, оно может быть обновлено значением `null`. В противном случае система предотвратит установку null-значения, даже при частичном обновлении:

```javascript
t.string({ title: "Имя", nullable: true, default: null })
```

## Работа с контекстом

### 1. Изменение данных

Контекст обновляется только с помощью метода `update()` внутри действия. Действия не принимают внешних аргументов и могут взаимодействовать только с ядром и контекстом:

```javascript
.actions(({ context, update, core }) => ({
  fetchItems: () => {
    update({ isLoading: true });
    fetch('/api/todos')
      .then(response => response.json())
      .then(data => {
        // Сохраняем в контексте только индексы, сами данные — в ядро
        const itemIds = data.map(item => item.id);
        core.data = data;
        update({
          items: itemIds,
          isLoading: false
        });
      })
      .catch(error => {
        update({
          error: error.message,
          isLoading: false
        });
      });
  },

  incrementCounter: () => {
    update({
      counter: context.counter + 1
    });
  }
}))
```

**Рекомендация:** всегда группируйте связанные изменения в одном вызове `update()` для минимизации количества обновлений.

---

### 2. Получение текущих значений

Доступ к актуальным данным контекста осуществляется напрямую через объект `context`:

```javascript
.actions(({ context, update, core }) => ({
  logItems: () => {
    console.log('Item IDs:', context.items);
    console.log('Items Data:', core.data);
  },

  addItem: () => {
    const newItem = generateNewItem(); // генерируется внутри ядра
    core.data = [...core.data, newItem];
    update({
      items: [...context.items, newItem.id]
    });
  }
}))
```

## Подписка на изменения контекста

Контекст может поддерживать подписку на изменения для внешних наблюдателей или синхронизации (если предусмотрено реализацией системы подписок). Это позволяет реагировать на обновления контекста в реальном времени.

---

## Взаимодействие с триггерами

Контекст является основой для работы триггеров. Триггеры подписываются на изменения полей контекста и автоматически выполняют переходы между состояниями при выполнении заданных условий.

Пример триггера:

```javascript
.triggers({
  onLoaded: ({ context }) => context.isLoading === false && context.items.length > 0
})
```

## Примеры использования контекста

### Пример 1: Список задач

```javascript
MetaFor("todo-list")
  .states("IDLE", "LOADING", "LOADED", "ERROR")
  .context((t) => ({
    items: t.array({ title: "Идентификаторы задач", default: [] }),
    filter: t.enum("all", "active", "completed")({ title: "Фильтр", default: "all" }),
    search: t.string({ title: "Поиск", default: "" }),
    isLoading: t.boolean({ title: "Загрузка", default: false }),
    error: t.string({ title: "Ошибка", nullable: true, default: null }),
  }))
```

**Данные задач по идентификаторам должны храниться в ядре вне контекста.**

---

## Практические рекомендации

1. **Контекст — единый источник истины для состояния.** Данные желательно выносить в ядро.
2. **Обязательно задавайте `title` для всех полей контекста.** Это упрощает документацию и интерфейсы.
3. **Явно задавайте значения по умолчанию.** Это предотвращает ошибки при инициализации.
4. **Используйте nullable для опциональных данных.** Это повышает читаемость и предсказуемость.
5. **Обновляйте контекст только через `update()`.** Это гарантирует корректную работу триггеров.
6. **Действия не принимают аргументов и работают только с ядром и контекстом.**
7. **Храните идентификаторы, а не сами данные.** Полные данные лучше хранить централизованно в ядре.
8. **Минимизируйте количество обновлений.** Группируйте связанные изменения в одном вызове.
9. **Используйте функциональные обновления,** если значение зависит от текущего состояния.

---

## Заключение

Контекст в MetaFor предоставляет надёжный и прозрачный способ управления состояниями и идентификаторами данных приложения. Полные данные рекомендуется выносить в ядро, оставляя в контексте лишь ссылки или индексы, что упрощает сопровождение, ускоряет обработку и делает поведение системы предсказуемым. Для максимальной читаемости и интеграции с UI обязательно указывайте заголовки (`title`) для всех полей контекста.
