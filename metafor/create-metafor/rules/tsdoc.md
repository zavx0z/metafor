# 📘 AI Documentation Standards (Docs-as-Code)

Этот документ описывает строгий стандарт ведения документации для AI-ассистентов.

**Контекст проекта:**

* **Динамичное развитие:** Код быстро эволюционирует.
* **Нет обратной совместимости:** Мы не поддерживаем старые версии.
* **Принцип:** Вся документация живет **внутри кода** в формате TSDoc.

---

## 1. Философия: High Signal-to-Noise Ratio

Документация должна объяснять **"Зачем"** и **"Как это работает внутри"**, а не пересказывать **"Что это"**.

* **⛔ Запрещено:** Переводить названия переменных на русский язык в описании.
* **⛔ Запрещено:** Создавать TSDoc-блоки ради галочки. Лучше отсутствие описания, чем бесполезный шум.
* **✅ Требуется:** Описывать неявные связи, ограничения и алгоритмы.

---

## 2. Структура документации

### 2.1. Точка входа (Module Level)

Главный файл модуля (`src/index.ts`) **обязан** содержать тег `@packageDocumentation`.
Текст должен описывать **текущую архитектуру** (паттерны, ответственность модуля).

### 2.2. Уровень Сущности (Class / Interface / Properties)

**🔴 The Value-Add Test (Тест на ценность):**
Прежде чем создать TSDoc-блок (`/** ... */`) для свойства, задай вопрос: *"Дает ли это описание информацию, которой нет в названии и типе?"*

* Если **НЕТ** → **Не создавай TSDoc-блок вообще.**
* Если **ДА** → Пиши.

**Что считается ценной информацией:**

1. **Связь с железом/системой:** "Данные отправляются в GPU", "Синхронизируется с БД".
2. **Ownership / Lifecycle:** "Нужно вызывать dispose()", "Ссылка (не клон)".
3. **Side Effects:** "Изменение сбрасывает кэш", "Триггерит перерисовку".
4. **Unit of Measure:** "Секунды", "Радианы", "Нормализованный вектор".

**Пример:**

* ❌ `name: string;` (Без TSDoc, так как "Имя" очевидно)
* ✅ `/** Уникальный идентификатор (UUID v4). */ uuid: string;`
* ✅ `/** Если true, пересчитывает матрицу каждый кадр. */ matrixAutoUpdate: boolean;`

### 2.3. Уровень Метода (Public)

**⛔ Правило "Нет Дублирования Типов":** Запрещено указывать типы в тегах (`@param {number}`).
**⛔ Правило "Smart Default":** Запрещен тег `@default`, если значение видно в сигнатуре.

**Обязательные теги (если есть что сказать):**

* **@param:**
  * **Никаких переводов!** (❌ `color - Цвет`).
  * Для **generic-названий** (`name`, `id`, `data`, `config`) **ОБЯЗАТЕЛЬНО** описывать ожидаемую структуру, формат или допустимый словарь.
  * Для **чисел**: Обязательно указывать допустимый диапазон (`[0..1]`) и поведение при выходе за него.
* **@returns:** Описывай **результат**, а не тип. Если возвращает `this` (chaining) — укажи это.
* **@throws:** Обязательно, если метод валидирует входные данные.

### 2.4. Уровень Метода (Private / Protected)

Добавлять TSDoc **ТОЛЬКО** если метод содержит сложный математический алгоритм или нетривиальную бизнес-логику. Хелперы оставлять без документации.

---

## 3. Правила форматирования

1. **Таблицы:** Для матриц состояний.
2. **Ссылки:** `{@link ClassName}`.
3. **Примеры (`@example`):** Обязательны для конструкторов и методов с неочевидными аргументами.

---

## 4. Процесс изменения кода (Workflow)

Соблюдайте правило **Атомарности** и **Чистоты Контекста**.

> **"Изменение кода, обновление локальной документации и обновление глобального контекста должно происходить в одной итерации."**

1. **Локально:** Изменил логику → Переписал TSDoc. Удалил старое.
2. **Глобально:** Архитектура сменилась → Переписал `@packageDocumentation`.

---

     * 
     * @example
     * ```ts
     * const isDead = unit.takeDamage(50, 'pure');
     * ```
     */
    public takeDamage(amount: number, type: 'physical' | 'pure' = 'physical'): boolean {
        // ... implementation
    }
}
```
