# Правило: Структура файлов модуля

| Файл | Обязательность | Назначение |
| --- | --- | --- |
| `{name}.ts` | **Обязательно** | Основная логика и публичный API модуля. |
| `{name}.spec.ts` | Опционально | Unit-тесты, покрывающие основные сценарии. |
| `{name}.t.ts` | Опционально | TypeScript типы, интерфейсы и перечисления (enum). |

---

## Правила именования типов

1. **Типы принадлежат модулю, который их используют.**
   - `load.ts` → типы в `load.t.ts`
   - `execute.ts` → типы в `execute.t.ts`

2. **Кросс-модульные зависимости типов.**
   - Если типы одного модуля зависят от типов другого — импортируй через `.t.ts` файл.
   - Пример: `execute.t.ts` импортирует `ActionFn` из `load.t.ts`.

3. **Чистые функции.**
   - Модули с чистой логикой (`execute.ts`) не должны импортировать типы из модулей с сайд-эффектами (`load.ts`).
   - Импортируй только из `.t.ts` файлов.

4. **Разделение ответственности.**
   - `.ts` — только функции и логика.
   - `.t.ts` — только типы (никаких импортов функций, только другие типы).
   - `.spec.ts` — только тесты.
